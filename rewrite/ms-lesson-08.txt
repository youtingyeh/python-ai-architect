@section 開場：搜尋「退費」，為什麼找不到「款項返還」？
你在學校的課程平台搜尋「怎麼申請退費」，結果顯示「找不到相關結果」。但其實學校規章裡明明有一份文件，標題叫做「課程取消與款項返還辦法」。

問題出在哪？傳統的搜尋是「**比對字面**」：它找的是**包含「退費」這兩個字**的文件。「款項返還」意思一樣，但字不一樣，所以找不到。這個問題叫做「**詞彙不匹配**」（Vocabulary Mismatch）：同一個意思，人們會用很多不同的詞來表達。

人類一看就知道「退費」和「款項返還」是同一件事。能不能讓電腦也**用意思來搜尋**，而不是用字面？

這就是這一課的主角：**嵌入向量**（Embedding）和**向量搜尋**（Vector Search）。它們是現代 AI 搜尋、推薦系統、以及下一課 RAG（讓 AI 查資料再回答）的核心技術。

這一課對應 Microsoft《Generative AI for Beginners》第 08 課「建立搜尋應用」，我們會學到：
1. 怎麼把一段文字變成一串數字，而且意思相近的文字，數字也相近；
2. 怎麼計算兩段文字「有多像」（餘弦相似度）；
3. 向量搜尋有哪些盲點；
4. 怎麼把向量搜尋和傳統搜尋結合起來（混合搜尋）；
5. 為什麼「很相似」不代表「正確」；
6. 一條很容易被忽略的鐵律：換模型就要全部重建。

@section 把文字變成地圖上的座標
**嵌入**（Embedding）的核心想法是：**把一段文字，變成高維空間中的一個點（一串數字）。**而且，**意思相近的文字，會被放在相近的位置。**

**先用一張二維地圖來想像。**
假設我們有一張地圖，橫軸代表「跟金錢有多相關」，縱軸代表「跟課程有多相關」：
- 「退費申請」→ 座標大約 (0.9, 0.8)：很金錢、也很課程
- 「款項返還辦法」→ (0.85, 0.75)：意思接近，位置也接近
- 「課程時間表」→ (0.1, 0.9)：很課程，但不太金錢
- 「Python 迴圈教學」→ (0.0, 0.2)：兩者都不太相關

在這張地圖上，「退費申請」和「款項返還辦法」**挨得很近**，雖然它們沒有一個字相同。

**真實的嵌入，維度多得多。**實際的嵌入模型會把一段文字變成幾百到幾千個數字，例如 768 維或 1,536 維。每一維代表什麼？**沒有人知道**，也沒有人規定。是嵌入模型在訓練過程中，從大量文字中**自己學出來**的。我們只知道，訓練完成後，意思相近的文字會落在相近的地方。

**嵌入模型怎麼學會的？**
回想第 12 課的 One-Hot 編碼和嵌入表：每個 Token 對應一個向量。嵌入模型把這個概念延伸到整段文字。訓練時，它會看大量「意思相近的配對」（例如問題和它的答案、同一件事的不同說法），學著把配對的向量拉近；同時把不相關的文字推遠。

一個有名的早期發現：在詞向量空間中，**「國王」的向量 −「男人」+「女人」≈「皇后」的向量**。這說明向量空間的「方向」，真的捕捉到了某種語意關係（例如「性別」這個方向）。

**重要的提醒，先記在心裡：**
> 向量相近，代表「**話題相近**」，不代表「**內容正確**」或「**立場一致**」。

這一點後面會用數字證明。

@section 怎麼算兩段文字有多像？餘弦相似度
有了向量，怎麼計算兩個向量「有多接近」？最常用的方法是「**餘弦相似度**」（Cosine Similarity）。

**直覺：看兩個箭頭的夾角。**
把每個向量想像成從原點出發的一支箭頭。
- 兩支箭頭指向**同一個方向**（夾角 0 度）→ 非常相似，餘弦值 = **1**
- 兩支箭頭**互相垂直**（夾角 90 度）→ 毫無關係，餘弦值 = **0**
- 兩支箭頭指向**相反方向**（夾角 180 度）→ 完全相反，餘弦值 = **−1**

我們只在乎**方向**，不在乎箭頭的**長度**。

**公式：**
$$\cos\theta = \frac{q \cdot x}{\|q\| \times \|x\|}$$

- 分子 $q \cdot x$ 是**內積**（第 14 課學過）：對應位置相乘再加總。
- 分母是兩個向量的**長度**相乘。長度的算法是每個數字平方、加總、再開根號：$\|q\| = \sqrt{q_1^2 + q_2^2 + \cdots}$。

**一個省事的事實：**大多數嵌入 API 輸出的向量，長度都已經被調整成 1（叫做**正規化**，Normalization）。長度都是 1 的話，分母就是 1，**餘弦相似度就等於內積**，計算非常快。

**實際算一次（簡化成 3 維）。**

查詢「如何申請退費」：$q = [0.80, 0.60, 0.00]$
（驗證長度：$\sqrt{0.64 + 0.36 + 0} = \sqrt{1} = 1$ ✓）

**文件 A**「退款與返還辦法」：$x_A = [0.60, 0.80, 0.00]$
$$q \cdot x_A = 0.80 \times 0.60 + 0.60 \times 0.80 + 0 = 0.48 + 0.48 = 0.96$$
非常相似！

**文件 B**「Python 迴圈語法教學」：$x_B = [0.00, 0.00, 1.00]$
$$q \cdot x_B = 0 + 0 + 0 = 0$$
毫無關係。

**文件 C**「**嚴禁**退費之特價專案」：$x_C = [0.78, 0.62, 0.05]$
$$q \cdot x_C = 0.80 \times 0.78 + 0.60 \times 0.62 + 0 \approx 0.624 + 0.372 = 0.996$$

**相似度 0.996，甚至比文件 A 還高！**

但文件 C 說的是「**不能**退費」，跟使用者想知道的「怎麼退費」立場完全相反。為什麼它的分數這麼高？因為它**也在談退費這個話題**，用的詞彙和語境非常相近。嵌入向量擅長捕捉「在談什麼」，卻不擅長分辨「肯定還是否定」。

**這就是開頭提醒的重點：高相似度只代表「主題相關」，不代表「答案正確」。**

@section 向量資料庫：在百萬個點中快速找鄰居
實際應用中，你可能有幾萬、幾百萬段文件。每次搜尋時，要拿查詢向量和**每一個**文件向量都算一次相似度，再排序取前幾名，太慢了。

**向量資料庫**（Vector Database）專門解決這個問題。它用特殊的索引結構，讓你能在極短的時間內找到「最接近的幾個點」。這叫做「**近似最近鄰搜尋**」（Approximate Nearest Neighbor，ANN）。

「近似」的意思是：它不保證找到**絕對**最近的那幾個，但幾乎總是能找到非常接近的，而且速度快上千倍。這是一種用一點點準確度換取大量速度的取捨。

常見的工具包括：
- 專門的向量資料庫：Pinecone、Weaviate、Qdrant、Milvus、Chroma
- 傳統資料庫加上向量功能：PostgreSQL 的 pgvector 擴充、Elasticsearch
- 雲端搜尋服務：Azure AI Search（Microsoft 課程使用的）

**完整的流程分兩個階段：**

**建立索引（事先做一次）：**
1. 把所有文件切成適當大小的段落（叫做「**切塊**」，Chunking，下一課會詳細說明）；
2. 每一段送進嵌入模型，得到向量；
3. 把向量和原文、相關資訊一起存進向量資料庫。

**查詢（每次搜尋時）：**
1. 把使用者的問題送進**同一個**嵌入模型，得到查詢向量；
2. 在向量資料庫中找出最相似的前 K 段（例如 K = 5）；
3. 回傳這些段落的原文。

@section 向量搜尋的三個盲點
很多團隊導入向量搜尋後，乾脆把原本的關鍵字搜尋全部拆掉。結果搜尋品質反而**變差**了。因為純向量搜尋有三個明顯的盲點：

**盲點一：精確的編號、代碼、型號。**
工程師搜尋錯誤代碼 `ERR_SSL_VERSION_MISMATCH`、零件料號 `SKU-8849-B`、法條「第 24 條第 2 項」。

嵌入向量會把整段文字壓縮成一個「平滑」的語意表示。`SKU-8849-B` 和 `SKU-8849-C` 在語意上幾乎一樣（都是某個產品型號），向量的相似度可能高達 0.99。結果搜尋 B 型號，卻把 C 型號的說明書排在第一名。對需要精確匹配的情況，這是致命的。

**盲點二：否定詞。**
前面算過了：「可以退費的條件」和「不可退費的例外」，向量幾乎重疊。

**盲點三：新詞、內部術語。**
公司剛取的專案代號（例如「鳳凰計畫」）、新產品名稱、內部縮寫。通用的嵌入模型在訓練時沒見過這些詞，無法給它們準確的語意位置。

**結論：向量搜尋不是萬能的。**它擅長「找意思相近的」，但不擅長「找一模一樣的」。

@section 混合搜尋：兩種方法各取所長
既然向量搜尋擅長語意、關鍵字搜尋擅長精確比對，最好的做法就是**兩個一起用**。這叫做「**混合搜尋**」（Hybrid Search）。

**關鍵字搜尋的代表：BM25。**
BM25 是一種經典的關鍵字搜尋演算法，搜尋引擎用了幾十年。它的基本想法是：
- 文件中包含越多查詢的關鍵字，分數越高；
- 但**罕見**的詞比常見的詞更重要（「SKU-8849-B」比「的」重要得多）；
- 文件很長的話，要適度扣分（不然長文件靠著字多就佔便宜）。

**怎麼合併兩邊的結果？**
問題是：BM25 的分數範圍可能是 0 到 25，餘弦相似度是 −1 到 1，**單位完全不同，不能直接相加**。就像不能把身高（公分）和體重（公斤）直接相加來評比一個人。

**解法：不看分數，只看名次。**這個方法叫做「**倒數排名融合**」（Reciprocal Rank Fusion，RRF）。

$$\text{RRF分數}(d) = \frac{1}{k + \text{向量排名}} + \frac{1}{k + \text{BM25排名}}$$

k 是一個平滑用的常數，通常取 60。如果某份文件在某一邊沒有上榜，那一項就是 0。

**算一次。**

**文件 X**：向量搜尋第 2 名、BM25 第 1 名
$$\frac{1}{60+2} + \frac{1}{60+1} = \frac{1}{62} + \frac{1}{61} \approx 0.0161 + 0.0164 = 0.0325$$

**文件 Y**：向量搜尋第 1 名，但**不含**查詢的產品型號，BM25 沒上榜
$$\frac{1}{60+1} + 0 \approx 0.0164$$

文件 X 的總分約是 Y 的兩倍，排到第一名。**兩邊都說好的文件，會自動被推到最前面。**

為什麼用倒數？因為排名越前面，倒數越大；排名往後，分數下降得越來越平緩。k = 60 的作用是讓第 1 名和第 2 名的差距不會太懸殊，避免單一來源的第一名獨佔優勢。

**更進一步：重新排序**（Reranking）。
混合搜尋找出前 50 個候選後，可以再用一個更精細（但較慢）的「**重排模型**」（Reranker），把問題和每個候選段落**放在一起**仔細比對，重新排出最終的前 5 名。重排模型能同時看到問題和段落的每個字，比單純比較兩個向量準確得多，也比較能分辨否定詞。

@section 中繼資料過濾：相似不代表「現在有效」
**情境：**使用者問「今年的學費退費比例是多少？」

向量搜尋找到一段相似度 0.97 的文件：「開課後退還 70%」。AI 照著回答。結果引發客訴，因為這份文件是 **2021 年已經廢止的舊辦法**，2026 年的新辦法規定退還 50%。

**向量相似度只看「文字長得像不像」，它完全不知道：**
- 這份文件是不是**過期**了；
- 它屬於**哪個部門**；
- 現在查詢的人**有沒有權限**看它。

**解法：中繼資料過濾**（Metadata Filtering）。

**中繼資料**（Metadata）是「關於資料的資料」，例如一本書的作者、出版年、分類號。在建立索引時，為每一段文字加上結構化的標籤：
```
{
  "text": "開課後退還 70%……",
  "status": "archived",           # 已封存（過期）
  "effective_year": 2021,
  "department": "教務處",
  "allowed_roles": ["student", "staff"]
}
```

**查詢時，先過濾再比較相似度：**
> 只在 status = 有效、且目前使用者的角色在 allowed_roles 裡的段落中，找最相似的。

**絕對不能**先從全公司的所有文件中撈出前 5 名，然後指望 AI 自己忽略過期的或沒權限的。因為：
- 前 5 名可能全是過期文件，有效的反而沒被撈到；
- 如果撈到總經理專屬的薪資機密，一旦交給 AI，就可能被說出來。

**權限控制**（ACL，Access Control List，存取控制清單）必須在**搜尋的階段**就執行，不能事後補救。這和第 23 課「多使用者隔離」是同樣的道理。

@section 鐵律：索引和查詢必須用同一個嵌入模型
這是一條很容易被忽略、但違反時後果很慘的規則：

> **建立索引時用哪個嵌入模型，查詢時就必須用同一個模型、同一個版本。**

**為什麼？**每個嵌入模型都是獨立訓練出來的。訓練時，模型從隨機的起點開始，最後自己發展出一套座標系統。模型 A 的「第 1 維」可能代表某種語意特徵，模型 B 的「第 1 維」代表完全不同的東西。

**一個比喻：**模型 A 的座標是（經度、緯度），模型 B 的座標是（溫度、海拔）。兩邊都是兩個數字，但把「台北的經緯度」拿去和「某座山的溫度海拔」比較距離，算出來的數字毫無意義。

**更可怕的是：程式不會報錯。**如果兩個模型剛好都輸出 768 維，維度一樣，計算可以照常進行，只是結果完全是隨機的雜訊。系統會**靜默地**回傳一堆答非所問的搜尋結果，你可能要很久之後才發現。

這和第 13 課「分詞器和模型是連體嬰」是完全一樣的道理。

**實務做法：**
1. 在索引的資訊中，明確記錄 `embedding_model_id`（用了哪個模型、哪個版本）和維度。
2. 查詢時，程式先檢查查詢用的模型是否和索引記錄的一致，不一致就報錯。
3. 要換嵌入模型時：
   - 用新模型把**所有**文件重新產生向量，建立一份**全新的索引**；
   - 舊索引繼續提供服務；
   - 新索引建好、測試通過後，**一次切換**過去。
   這種「新舊兩套並存、驗證後切換」的做法叫做「**藍綠部署**」（Blue-Green Deployment）：藍色是舊的、綠色是新的，隨時可以切回去。

@section 動動腦：判斷看看
**情境一**：搜尋「如何申請退費」，系統回傳一段相似度 0.96 的段落。可以直接把它當成正確答案嗎？
→ 不行。0.96 只代表主題相近。這段可能是「不可退費」的例外條款、可能是過期的舊辦法、也可能是其他課程的規定。要搭配中繼資料過濾（有效狀態、日期、適用範圍），最好再用重排模型，並讓 AI 根據原文回答時引用出處。

**情境二**：純向量搜尋找同義詞很厲害，但搜尋料號 `SKU-9910-B` 時，常把 `SKU-9910-A` 排第一。怎麼改？
→ 改用混合搜尋：向量搜尋負責語意、BM25 負責精確比對料號，用 RRF 合併。

**情境三**：團隊把嵌入模型從舊版升級到新版，只更新了查詢的程式，沒有重建索引。搜尋結果變得亂七八糟，但沒有任何錯誤訊息。原因？
→ 索引用舊模型、查詢用新模型，兩邊的座標系統不同，相似度變成隨機雜訊。必須用新模型重建全部索引。

@section 本課重點整理
- **詞彙不匹配**：傳統搜尋比對字面，找不到同義不同字的內容。
- **嵌入**：把文字變成高維向量，意思相近的文字位置相近。每一維的意義是模型自己學出來的。
- **餘弦相似度**：看兩個向量的夾角。正規化後等於內積。1 是非常相似、0 是無關。
- **高相似度 ≠ 正確**：「可以退費」和「嚴禁退費」的相似度可能很高。向量捕捉話題，不分辨立場。
- **向量資料庫**：用近似最近鄰搜尋，在大量向量中快速找出最相似的幾個。
- **三個盲點**：精確編號、否定詞、新詞。
- **混合搜尋**：向量搜尋加上 BM25 關鍵字搜尋，用 RRF 依名次合併。可再用重排模型提升準確度。
- **中繼資料過濾**：依狀態、日期、部門、權限先過濾，再比較相似度。權限必須在搜尋階段執行。
- **同一個模型**：索引和查詢必須用同一個嵌入模型和版本。換模型就要重建全部索引，用藍綠部署切換。

@term 嵌入
把文字（或圖片等）轉換成一串數字向量，讓意思相近的內容位置相近（Embedding）。
@term 向量搜尋
用向量之間的相似度來找出意思相近內容的搜尋方式（Vector Search）。
@term 詞彙不匹配
相同意思用不同詞彙表達，導致字面比對找不到的問題（Vocabulary Mismatch）。
@term 餘弦相似度
用兩個向量夾角的餘弦值衡量相似程度（Cosine Similarity），範圍 −1 到 1。
@term 正規化
把向量長度調整為 1，只保留方向資訊（Normalization）。
@term 向量資料庫
專門儲存向量並能快速找出最相似向量的資料庫（Vector Database）。
@term 近似最近鄰
犧牲極少準確度、大幅加快速度地找出最接近向量的方法（ANN）。
@term BM25
經典的關鍵字搜尋演算法，依關鍵字出現次數、罕見程度和文件長度計分。
@term 混合搜尋
同時使用向量搜尋和關鍵字搜尋，再合併結果（Hybrid Search）。
@term RRF
倒數排名融合：依各來源的名次（而非分數）合併多個搜尋結果。
@term 重排模型
把問題和候選段落放在一起精細比對、重新排序的模型（Reranker）。
@term 中繼資料
描述資料本身屬性的資料（Metadata），例如日期、作者、狀態、權限。
@term ACL
存取控制清單（Access Control List）：記錄誰有權限存取哪些資料。
@term 藍綠部署
新舊兩套系統並存，新的驗證通過後再一次切換流量的部署方式（Blue-Green Deployment）。
@term 切塊
把長文件切成適當大小的段落，以便建立索引和搜尋（Chunking）。
