@section 開場：讀到「它」的時候，你會回頭看
讀這句話：「小明把蛋糕放進冰箱，因為**它**快融化了。」

你立刻知道「它」是蛋糕，不是冰箱，也不是小明。你是怎麼做到的？你的大腦在讀到「它」時，**回頭掃了一下前文**，在「小明」、「蛋糕」、「冰箱」之中，找出最可能會「融化」的那個，然後把注意力集中在它身上。

再換一句：「小明把蛋糕放進冰箱，因為**它**已經清空了。」這次「它」變成了冰箱。同一個字，指的東西不同，因為**你注意的地方不同**。

這就是 2017 年一篇論文《Attention Is All You Need》（注意力就是你所需要的一切）的核心想法。這篇 Google 團隊的論文提出了 **Transformer** 架構，而 ChatGPT 名字裡的 **T**，指的正是 Transformer。它的心臟，就是這一課的主角：**注意力機制**（Attention）。

前兩課的 Bigram 模型有嚴重的失憶症，只看得到前一個字。這一課要解決的問題就是：**怎麼讓模型在預測下一個字時，聰明地回頭看前面所有的字，並且自己決定要多注意哪些？**

我們會結合 Karpathy 的 GPT 課程，以及李沐《動手學深度學習》的注意力章節，一步一步拆解：
1. 從「平均」到「有選擇地注意」；
2. Query、Key、Value 三個角色；
3. 注意力公式，以及為什麼要除以一個根號；
4. 為什麼模型不能偷看未來；
5. 多頭注意力：同時用好幾種角度看；
6. 位置編碼：讓模型知道字的順序。

@section 第一步：最笨的方法——全部平均
要讓模型利用前面所有的字，最簡單的方法是：**把前面所有字的資訊平均起來。**

回憶上一課：每個 Token 會先變成一組數字向量（嵌入）。假設我們現在在第 t 個位置，想要總結第 1 到第 t 個字的資訊，最直接的方式是取平均：

$$\bar{x}_t = \frac{1}{t} \sum_{s=1}^{t} x_s$$

這樣每個位置都得到了一個「前文摘要」。

**但問題很明顯。**平均代表**每個字都一樣重要**。回到開頭的句子，模型讀到「它」時，「蛋糕」、「把」、「放進」、「，」這些字的份量一模一樣。這就像把一整頁書的字全部混成一團墨水，重要的資訊被稀釋得無影無蹤。

**我們真正需要的是：加權平均，而且權重要由內容決定。**讀到「它」時，給「蛋糕」很高的權重、給「把」很低的權重；而且這個權重要**隨句子內容動態改變**：換成「它已經清空了」，權重就應該轉到「冰箱」身上。

Karpathy 在課程中展示了一個漂亮的數學技巧：「前面所有位置的平均」可以用**一個矩陣乘法**一次算完所有位置。做法是準備一個下三角形的權重矩陣，每一列代表「第 t 個位置要給前面每個位置多少權重」。全部平均時，第 t 列就是 t 個 1/t。

而注意力機制要做的，就是**讓這個權重矩陣不再是固定的 1/t，而是由資料自己算出來。**

@section Query、Key、Value：一場配對遊戲
注意力怎麼決定「誰重要」？它設計了三個角色。最好的比喻是**圖書館找書**，或是**交友軟體配對**。

每個位置的字，都會用三組不同的權重矩陣，各自轉換出三個向量：

**① Query（查詢，q）：「我在找什麼？」**
這是提問者。例如讀到「它」時，它的 Query 可能在問：「前面有沒有一個可以融化的東西？」

**② Key（鍵，k）：「我身上有什麼標籤？」**
這是每個字貼在身上、供人比對的標籤。「蛋糕」的 Key 可能代表「我是一個食物、可以融化的名詞」；「冰箱」的 Key 代表「我是一個電器、容器」。

**③ Value（值，v）：「如果你選中我，我給你什麼內容？」**
這是真正要傳遞的資訊。一旦配對成功，「蛋糕」會把它的 Value（關於蛋糕的語意內容）傳給「它」。

**為什麼要把 Key 和 Value 分開？**因為「用來被找到的特徵」和「被找到後要提供的內容」不一定一樣。就像圖書館：書的**索引卡**（書名、分類號）是 Key，你用來找書；而**書的內容**是 Value，是你真正要讀的。

**配對怎麼算？**用 Query 和每個 Key 做**內積**（Dot Product）：兩個向量對應位置相乘再加總。

內積有一個直覺意義：**兩個向量方向越接近，內積越大**。所以「它」的 Query 跟「蛋糕」的 Key 方向很接近，內積就很大，代表很相關；跟「把」的 Key 方向差很多，內積就小。

**完整流程：**
1. 「它」的 Query 跟前面每個字的 Key 做內積，得到一排相關分數。
2. 用 Softmax 把分數變成加起來等於 1 的權重（第 7 課學過）。
3. 用這組權重，把每個字的 Value 加權平均起來。
4. 結果就是「它」從前文收集到的資訊，現在「它」的表示裡含有「蛋糕」的意思了。

**重要的是：W_Q、W_K、W_V 這三組權重是學出來的。**模型在訓練過程中，自己學會「什麼樣的字應該去找什麼樣的字」。沒有人教它「代名詞要找名詞」，它從大量文字中自己摸索出來。

這個機制叫做「**自注意力**」（Self-Attention），「自」是因為 Query、Key、Value 全都來自**同一段文字自己**，是句子裡的字互相注意。

@section 注意力公式，以及那個神秘的根號
把一整句話所有位置的 Query、Key、Value 排成矩陣 Q、K、V，注意力可以寫成一行公式（李沐的 D2L 和原始論文都用這個寫法）：

$$\text{Attention}(Q, K, V) = \text{softmax}\left(\frac{QK^\top}{\sqrt{d_k}}\right) V$$

一塊一塊拆開看：
- $QK^\top$：所有 Query 和所有 Key 兩兩做內積，得到一張 T×T 的**分數表**（T 是句子長度）。第 t 列第 s 欄，代表「第 t 個字對第 s 個字有多感興趣」。（$K^\top$ 讀作「K 轉置」，就是把矩陣的列和欄對調。）
- $\div \sqrt{d_k}$：除以一個數字，等一下解釋。
- softmax：每一列變成加總為 1 的權重。
- $\times V$：用權重把 Value 加權平均。

這叫做「**縮放點積注意力**」（Scaled Dot-Product Attention）。「點積」就是內積，「縮放」就是除以那個根號。

**為什麼要除以 $\sqrt{d_k}$？**

$d_k$ 是 Key 向量的長度（維度），例如 64。這個除法看起來像裝飾，其實是**防止訓練卡死**的關鍵。

假設 Query 和 Key 的每個數字都是隨機的，平均 0、變異數 1（變異數是衡量「數字分散程度」的指標）。內積是 $d_k$ 個乘積加起來。統計學告訴我們：**$d_k$ 個獨立隨機數加起來，變異數也會變成 $d_k$ 倍**。

所以當 $d_k = 64$ 時，內積的變異數是 64，標準差是 $\sqrt{64} = 8$。分數很容易出現 +20、−20 這種極端值。

**極端值丟進 Softmax 會怎樣？**Softmax 會被最大的那個值完全霸佔。例如分數是 [20, 2, 1]，Softmax 後幾乎是 [1.0, 0.0, 0.0]。注意力變成「只看一個字、完全忽略其他字」。

這比過度專注更糟的是：**梯度會消失**。第 11 課學過，tanh 在飽和區梯度幾乎是 0；Softmax 也一樣，當輸出接近 0 或 1 時，它對輸入的導數接近 0，梯度傳不回去，模型學不動。

**除以 $\sqrt{d_k}$**，剛好把變異數從 $d_k$ 壓回 1，分數回到溫和的範圍，Softmax 的輸出比較柔和，梯度才能順利流動。

一個簡單的數字感覺：分數 [8, 0, 0] 做 Softmax 約是 [0.999, 0.0003, 0.0003]；除以 8 變成 [1, 0, 0]，Softmax 約是 [0.58, 0.21, 0.21]，平緩許多。

@section 不准偷看未來：因果遮罩
GPT 的訓練目標是：在第 t 個位置，**根據第 1 到 t 個字，預測第 t+1 個字**。

訓練時，我們會一次把整句話丟進去，讓所有位置同時預測（這樣才有效率，可以平行計算）。但這產生了一個漏洞：如果第 t 個位置的 Query 可以去看第 t+1 個位置的 Key 和 Value，那它就**直接看到答案了**！

模型會學到一個偷懶的策略：「把下一個位置的內容抄過來就好。」訓練損失降到幾乎 0，看起來超厲害。但到了真正使用時，未來的字還沒寫出來，沒得抄，模型瞬間崩潰。這是第 6 課「資料洩漏」的一種形式。

**解法：遮住右上角。**

那張 T×T 的分數表，第 t 列第 s 欄代表「第 t 個字看第 s 個字」。合法的是 $s \le t$（看自己和過去），違規的是 $s > t$（看未來）。違規的部分剛好是表格的**右上半部**。

做法：
1. 準備一個下三角矩陣（左下和對角線是 1，右上是 0），用 `torch.tril` 建立（tril 是 triangle lower，下三角）。
2. 把分數表中右上角的位置，全部改成**負無限大** $-\infty$。
3. 再做 Softmax。因為 $e^{-\infty} = 0$，未來位置的權重自動變成 0，而其他位置的權重會自動重新分配，加起來仍然是 1。

這叫做「**因果遮罩**」（Causal Mask）。「因果」是指：結果只能由過去造成，不能由未來造成。

**這和 BERT 不同。**另一類模型，例如 Google 的 BERT，是用來「理解」文字而不是「生成」文字，它允許每個字同時看左邊和右邊（雙向注意力），因為它不需要預測下一個字。GPT 這類生成模型則一定要遮住未來。

@section 一個細節陷阱：為什麼一定要在 Softmax「之前」遮？
很多人第一次寫時會想：「反正目的是讓未來的權重變 0，那我先做 Softmax，再把右上角乘以 0 不就好了？」

**絕對不行。**用一個數字例子說明。

第 1 個位置只能看自己，但它對三個位置算出的原始分數是 [2, 4, 10]（後兩個是未來）。

**正確做法（Softmax 前遮）**：先遮成 [2, −∞, −∞]，Softmax 得到 [1.0, 0, 0]。不管未來的分數是 10 還是 1，結果永遠是 [1.0, 0, 0]，完全不受未來影響。

**錯誤做法（Softmax 後遮）**：先對 [2, 4, 10] 做 Softmax。分母是 $e^2 + e^4 + e^{10} \approx 22{,}089$，第一個位置的權重是 $e^2 / 22{,}089 \approx 0.00033$。之後把後兩個乘以 0，得到 [0.00033, 0, 0]。

問題有兩個：
1. 權重加起來不是 1，數學上就錯了。
2. **更糟的是**：0.00033 這個數字的大小，取決於未來那個分數是 10 還是 1。如果未來分數是 1，這個值會完全不同。換句話說，**未來的資訊透過「分母」偷偷滲透進來了**。模型只要觀察自己的權重被縮放了多少，就能反推出未來大概是什麼字。

這叫做「**分母資訊洩漏**」。所以遮罩一定要在 Softmax 之前，用 $-\infty$ 填入。

@section 多頭注意力：同時用好幾種眼光看
一組 Query、Key、Value，經過 Softmax 只會產生**一組權重**，也就是一種「注意的方式」。但語言很複雜，一個字常常同時需要關注好幾種關係。

例如句子：「那隻因為跑太快而跌倒的小狗，最後還是**站**了起來。」讀到「站」時，模型同時需要：
- 找**主詞**：誰站？→ 小狗
- 找**時態**：什麼時候？→ 了
- 找**對比的動作**：前面發生什麼？→ 跌倒

一組注意力很難同時兼顧這三件事。

**解法：開好幾組，各看各的。**這叫做「**多頭注意力**」（Multi-Head Attention）。

就像一個評審團：一位評審專看文法、一位專看指代關係、一位專看語氣。每位評審（頭）有自己的一組 W_Q、W_K、W_V，獨立計算注意力，最後把所有評審的意見**串接**起來，再用一個輸出矩陣 W_O 融合成最終結論。

**實際的切法：**假設每個字的向量長度是 C = 512，用 h = 8 個頭。每個頭不是拿完整的 512 維，而是分到 512 / 8 = **64 維**的子空間。所以 8 個頭的總計算量，和一個 512 維的大頭差不多，但能捕捉 8 種不同的關係。

研究人員實際去觀察訓練好的模型，確實發現不同的頭學到了不同的工作：有的專門看前一個字、有的專門找主詞動詞配對、有的專門處理標點和句子邊界。沒有人指定它們分工，是訓練過程中自然形成的。

**工程上的小技巧**：程式裡不需要真的用迴圈跑 8 次。只要用一個大的線性層一次算出全部的 Q、K、V，再用 `.view()` 和 `.transpose()` 把張量重新排列成（批次, 頭數, 長度, 每頭維度）的形狀，8 個頭就能**平行**一次算完。第 3 課學的張量形狀操作，在這裡發揮了關鍵作用。

@section 位置編碼：讓模型知道誰先誰後
注意力機制有一個令人驚訝的特性：**它天生不知道字的順序。**

仔細看公式：每個字的 Query、Key、Value 只取決於字本身。如果把「狗咬人」改成「人咬狗」，每個字算出的 Q、K、V 完全一樣，只是排列順序換了而已。注意力的內積和加權平均，根本不在乎誰排第一、誰排第三。

數學上這叫做「**排列等變**」（Permutation-Equivariant）：輸入順序怎麼換，輸出就跟著怎麼換，但每個字的結果不變。對注意力來說，一句話就像一袋彈珠，沒有前後。

但對語言來說，順序就是意思。「狗咬人」不是新聞，「人咬狗」才是新聞。

**解法：在輸入時就把「位置」資訊加進去。**這叫做「**位置編碼**」（Positional Encoding）。有幾種做法：

**① 正弦位置編碼（原始 Transformer 論文、D2L 教材）。**
用不同頻率的正弦和餘弦波，為每個位置產生一組獨特的數字。像是用好幾根轉速不同的時鐘指針，組合起來就能唯一標記每個時刻。好處是不需要學習，而且理論上能處理任意長度。

**② 可學習的位置嵌入（GPT-2、Karpathy 的 nanoGPT）。**
更直接：準備一張表，第 0 個位置一組向量、第 1 個位置一組向量……讓模型自己學。使用時把「字的嵌入」和「位置的嵌入」**直接相加**：`x = tok_emb + pos_emb`。缺點是只能處理訓練時看過的最大長度。

**③ 旋轉位置編碼 RoPE（Llama、Qwen 等現代模型）。**
在 Query 和 Key 做內積之前，依照位置把它們「旋轉」一個角度。巧妙之處在於：兩個向量各自旋轉後再做內積，結果只取決於它們的**相對距離**（差幾個位置），而不是絕對位置。這讓模型更容易處理比訓練時更長的文本，是目前的主流做法。

@section 動動腦：手算一次小小的注意力
**設定**：一句話只有 3 個字，我們看第 3 個字的注意力（它可以看第 1、2、3 個字）。為了簡單，假設 $d_k = 4$，所以要除以 $\sqrt{4} = 2$。

第 3 個字的 Query 和三個 Key 的內積是：[2, 6, 4]。

**步驟一：縮放。**除以 2，得到 [1, 3, 2]。

**步驟二：Softmax。**
- $e^1 \approx 2.72$、$e^3 \approx 20.09$、$e^2 \approx 7.39$
- 總和 ≈ 30.20
- 權重 ≈ [0.09, 0.67, 0.24]

第 3 個字最注意第 2 個字（67%），其次是自己（24%），幾乎不理第 1 個字（9%）。

**步驟三：加權 Value。**假設三個字的 Value 是（簡化成單一數字）[10, 20, 30]：
$0.09 \times 10 + 0.67 \times 20 + 0.24 \times 30 = 0.9 + 13.4 + 7.2 = 21.5$

第 3 個字收集到的資訊是 21.5，主要來自第 2 個字。

**對照：如果是第 1 個字呢？**因果遮罩讓它只能看自己，所以權重是 [1, 0, 0]，輸出就是自己的 Value 10。

**對照：如果忘了除以 2？**分數 [2, 6, 4] 直接做 Softmax，權重約是 [0.02, 0.87, 0.12]，更集中在第 2 個字。$d_k$ 越大，這種「過度集中」越嚴重，這就是要縮放的原因。

@section 本課重點整理
- **注意力**讓模型在處理每個字時，有選擇地回頭看前文，自己決定要多注意哪些字。它是 Transformer 和 GPT 的核心。
- **從平均到加權**：簡單平均讓所有字一樣重要；注意力讓權重由內容動態決定。
- **Q、K、V**：Query 是「我在找什麼」、Key 是「我有什麼標籤」、Value 是「我提供什麼內容」。Q 和 K 的內積決定權重，用權重把 V 加權平均。三組轉換矩陣都是學出來的。
- **公式**：$\text{softmax}(QK^\top / \sqrt{d_k}) V$。除以 $\sqrt{d_k}$ 是為了讓分數保持溫和，避免 Softmax 飽和、梯度消失。
- **因果遮罩**：生成模型不能偷看未來，把分數表右上角設為 $-\infty$ 再做 Softmax。一定要在 Softmax **之前**遮，否則未來資訊會透過分母洩漏。
- **多頭注意力**：多組 Q、K、V 平行計算，各自捕捉不同的關係，最後串接融合。
- **位置編碼**：注意力本身不知道順序，必須另外加入位置資訊。方法有正弦編碼、可學習位置嵌入、旋轉位置編碼（RoPE）。

下一課，我們把注意力和其他零件組裝起來，從頭打造一個迷你 GPT。

@term Transformer
2017 年提出的神經網路架構，以注意力機制為核心，是 GPT、Claude 等現代語言模型的基礎。
@term 注意力機制
讓模型處理每個位置時，依內容動態決定要多注意其他哪些位置的機制（Attention）。
@term 自注意力
Query、Key、Value 都來自同一段文字，讓句子中的字互相注意（Self-Attention）。
@term Query
查詢向量：代表「我在找什麼樣的資訊」，用來和其他位置的 Key 比對。
@term Key
鍵向量：代表「我有什麼特徵可被比對」，像圖書館的索引卡。
@term Value
值向量：代表「被選中後要提供的內容」，依注意力權重加權平均。
@term 內積
兩個向量對應位置相乘再加總（Dot Product）。方向越接近，內積越大。
@term 縮放點積注意力
softmax(QKᵀ/√dₖ)V，Transformer 使用的注意力計算方式。
@term 變異數
衡量一組數字分散程度的指標，數字越分散變異數越大。
@term 因果遮罩
把注意力分數表中「未來位置」設為負無限大，防止生成模型偷看答案（Causal Mask）。
@term BERT
Google 提出的雙向 Transformer 模型，每個字可同時看左右兩邊，擅長理解而非生成。
@term 多頭注意力
同時用多組 Q、K、V 平行計算注意力，各自捕捉不同關係後再融合（Multi-Head Attention）。
@term 位置編碼
在輸入中加入每個字的位置資訊，讓本身不知道順序的注意力機制能分辨先後（Positional Encoding）。
@term RoPE
旋轉位置編碼：依位置旋轉 Query 和 Key，讓內積只依賴相對距離。Llama 等現代模型採用。
@term 排列等變
輸入順序調換時，輸出只跟著調換、數值不變的性質，代表運算本身不知道順序。
