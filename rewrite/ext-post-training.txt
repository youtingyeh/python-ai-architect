@section 開場：為什麼剛訓練好的語言模型，問它問題卻只會「幫你繼續出題」？
在第 15 課，我們跟著 Karpathy 從頭打造了一個小型 GPT。它學到的唯一本事，就是「**文字接龍**」：給它一段前文，它預測下一個最可能出現的 Token。

但如果你真的拿一個剛完成「預訓練」（Pre-training）的基礎模型來聊天，會發生很荒謬的事。

假設你問它：
> 台灣最高的山是哪一座？

它很可能不會直接回答「玉山」，而是接著幫你往下寫：
> 台灣最長的河是哪一條？
> 台灣最大的湖泊是哪一個？
> 請在下方空白處填寫你的答案，滿分 100 分。

**為什麼會這樣？**因為網路上有大量考卷和題庫，基礎模型覺得「問句後面最常接另一個問句」！它並不是不懂玉山，而是它**不知道你希望它扮演一位「回答問題的助理」**，也不知道什麼叫「有幫助、誠實、不害人」。

從一個「只會文字接龍的書呆子」（基礎模型），變成今天你每天使用的 ChatGPT、Claude 或 Gemini，中間經過了一套極其關鍵的塑造過程，叫做 **後訓練**（Post-Training），這也是李宏毅老師 2025 與 2026 課程及現代大模型開發中最核心的演進主軸。

這一課我們要由淺入深學會：
1. 語言模型成長的三大階段：預訓練、監督式微調（SFT）、偏好對齊（RLHF / DPO）；
2. 為什麼光靠「抄標準答案」（SFT）不夠，還需要「比較誰答得更好」？
3. **RLHF** 和 **DPO** 的白話原理，以及它們各自解決什麼痛點；
4. 2025～2026 最重要的突破：**可驗證獎勵強化學習（RLVR / GRPO）**與**推理模型（Reasoning Model）**；
5. **測試時計算**（Test-Time Compute）：花更多「思考時間」換取更高正確率，以及背後的成本取捨；
6. 實務上該怎麼選「一般對話模型」還是「深度推理模型」？

@section 大模型成長三階段：讀萬卷書、學待人接物、練深度思考
為了讓零基礎也能一眼看懂現代 LLM 是怎麼「長大」的，我們用培養一位住院醫師來比喻：

**第一階段：預訓練（Pre-training）—— 讀完圖書館裡所有的書。**
- **做法**：把數兆個 Token 的網頁、書籍、程式碼全部丟給模型做文字接龍（第 15 課）。
- **花費**：最貴，佔整個訓練算力的 90% 以上，需要成千上萬張 GPU 跑好幾個月。
- **成果**：得到一個**基礎模型**（Base Model）。它知識淵博、語言流暢，但沒有對話意識，也不知道安全界線，就像一個背完所有醫學教科書、卻從沒看過病人的學生。

**第二階段：監督式微調（SFT，Supervised Fine-Tuning）—— 跟著資深主治醫師看診。**
- **做法**：收集幾萬到幾十萬組高品質的「使用者提問 → 理想助理回答」範例，讓模型照著模仿（第 31 課提過的微調）。
- **成果**：模型學會了「問答格式」、「條列整理」、「寫完重點要收尾」，不再把你的問題接成一張考卷。

**第三階段：偏好對齊與強化學習（Alignment & RL）—— 自己看診並接受回饋與考驗。**
- **做法**：不再只是死背標準答案，而是讓模型自己生成多個回答，由人類評審、獎勵模型，或客觀的自動驗證器（如數學驗算、程式單元測試）來打分，答得好就鼓勵、答得差就扣分。
- **成果**：模型不只會「照格式回答」，還學會了**拒絕危險請求、承認不知道、在開放題裡權衡利弊**，甚至在最新一代推理模型裡學會了**自己拆解步驟、發現算錯就回頭修正**。

@section 為什麼光靠 SFT 不夠？「模仿」和「判斷好壞」的差別
新手常問：「既然 SFT 已經能教模型怎麼回答，那我多準備一百萬組高品質問答範例，不就夠了嗎？幹嘛還要搞複雜的強化學習？」

有三個非常現實的原因：

**原因一：很多好問題沒有「唯一標準答案」。**
例如請 AI「寫一封委婉拒絕客戶無理殺價的信」。十位資深業務會寫出十種語氣不同但都很棒的版本。SFT 強迫模型逐字去逼近其中一種寫法，反而容易讓模型變得死板、只會套公版。但人類很容易做「**兩者比較**」：「回答 A 比回答 B 更有禮貌，又不失立場。」

**原因二：SFT 只教「該說什麼」，很難精準教「什麼絕對不能說」。**
如果模型偶爾會編造不存在的法條（幻覺）或不小心迎合使用者的錯誤前提（拍馬屁，叫做 **Sycophancy**），只餵正確範例很難根除。你需要明確告訴模型：「**這個回答雖然很順，但它拍馬屁／捏造事實，要扣重分！**」

**原因三：SFT 的上限被「人類寫範例的速度與能力」鎖死。**
寫出一道複雜演算法題的完整解題思路可能要花工程師兩小時，但**判斷**一段程式跑測試通不通過只要 0.1 秒！強化學習能讓模型不斷自己嘗試，只要最後結果能被驗證，模型甚至能學會超越人類標註員的解題策略。

**比喻：**SFT 像是「臨摹字帖」，能讓你很快寫出端正的字；但要成為真正懂構圖、懂避開敗筆的書法家，必須靠老師點評「這兩幅哪一幅更有氣勢、哪一筆太輕浮」（偏好對齊），以及自己反覆試錯調整。

@section RLHF 與 DPO：怎麼教模型分辨「好回答」與「壞回答」？
既然「比較 A 和 B 誰比較好」比「從零寫出滿分範文」容易得多，業界發展出兩條最經典的偏好對齊路線：**RLHF** 與 **DPO**。

**路線一：RLHF（從人類回饋中強化學習，Reinforcement Learning from Human Feedback）**
這是讓初代 ChatGPT 一戰成名的經典三步驟：
1. **收集偏好資料**：同一個問題讓 SFT 模型生成兩個回答 $y_w$（勝出，Chosen）和 $y_l$（落敗，Rejected），請人類標註員選出較好的那個。
2. **訓練獎勵模型（Reward Model，簡稱 RM）**：把幾十萬組「勝 vs 敗」的比較餵給另一個神經網路，讓它學會給任何回答打一個品質分數 $r(x, y)$。這就像先訓練出一位「AI 裁判」。
3. **強化學習更新（常用 PPO 演算法）**：讓語言模型（主角，稱為**策略模型 Policy**）不斷回答問題，由 AI 裁判打分，分數高就調高這條路徑的機率。

**一個關鍵的安全繩：KL 散度懲罰（KL Penalty）。**
如果只讓模型拼命討好 AI 裁判，模型很快就會開始「鑽漏洞」（第 39 課說過的獎勵駭客）：例如發現裁判喜歡很長、很多項目符號、充滿「這是一個非常棒的問題！」的回答，就開始寫廢話水字數。

為了防止模型走火入魔，RLHF 會在目標函數裡加上一條「拉回原本 SFT 模型的橡皮筋」，叫做 **KL 散度懲罰**：
$$\text{目標分數} = r(x, y) - \beta \cdot D_{\text{KL}}\bigl(\pi_{\theta}(y \mid x) \,\|\, \pi_{\text{ref}}(y \mid x)\bigr)$$

不用怕這個符號，白話意思超級直覺：
- $r(x, y)$：AI 裁判給的分數（越高越好）；
- $\pi_{\theta}$：正在學習的新模型；$\pi_{\text{ref}}$：原本的參考模型（SFT 模型）；
- $D_{\text{KL}}$：新模型和舊模型的說話風格「偏離了多遠」；
- $\beta$：橡皮筋的鬆緊度。如果偏離太遠，就把總分扣回來，避免模型為了刷分而講出怪腔怪調的胡話。

**路線二：DPO（直接偏好優化，Direct Preference Optimization）**
RLHF 雖然有效，但工程上超級痛苦：你得同時在 GPU 記憶體裡塞進四個模型（策略模型、參考模型、獎勵模型、價值網路），訓練極容易不穩定。

2023 年史丹佛團隊提出 **DPO**，用漂亮的數學推導證明：**其實根本不需要單獨訓練一個 AI 裁判！**可以直接用「勝出回答 $y_w$」和「落敗回答 $y_l$」的機率比值，一步到位更新模型：
- 只要這組資料裡 $y_w$ 贏了 $y_l$，DPO 就直接**拉高模型輸出 $y_w$ 的相對機率，壓低輸出 $y_l$ 的相對機率**；
- 同時內建了對參考模型 $\pi_{\text{ref}}$ 的橡皮筋保護。

**用比喻對照 RLHF 和 DPO：**
- **RLHF** 像先培訓一位專業評審團（獎勵模型），再讓選手上場一直試招、邊練邊給評審打分（線上互動，上限高但成本與調參難度大）。
- **DPO** 像直接拿一疊「好作品 vs 壞作品」對照冊給選手看，直接調整自己的習慣（離線訓練、穩定、省記憶體，小團隊也能跑，特別適合搭配第 31 課的 LoRA 做輕量對齊）。

@section 2025～2026 的大轉折：RLVR、GRPO 與會「深度思考」的推理模型
過去大家以為「只要把模型做更大、資料餵更多，AI 就會變聰明」。但到了 2024 下半年至 2026 年，整個 AI 領域迎來一場結構性的範式轉移：**推理模型**（Reasoning Models，例如 OpenAI o 系列、DeepSeek-R1、Gemini Thinking 等）。

它們的核心秘密有兩個：**RLVR（可驗證獎勵的強化學習）**與 **GRPO**。

**什麼是 RLVR（Reinforcement Learning with Verifiable Rewards）？**
前面說 RLHF 需要靠一個「AI 裁判」來打分，但 AI 裁判自己也會出錯、也會被騙。
於是研究者想：「**在數學、寫程式、邏輯謎題這類領域，我們根本不需要 AI 裁判啊！答案對不對，用程式一驗就 100% 確定！**」
- 數學題：最終答案是不是 42？（對 = +1 分，錯 = 0 分）
- 程式題：跑完 20 個單元測試是不是全過？（全過 = +1 分，沒過 = 0 分）
- 格式題：有沒有照要求把思考過程放在 `<think>...</think>` 標籤裡？

這種**客觀、確定、幾乎無法作弊**的打分方式，就是 **RLVR**（這和第 39 課 Agent Harness 的「外部確定性驗證器」一脈相承！）。

**GRPO（群組相對策略優化，Group Relative Policy Optimization）怎麼運作？**
DeepSeek-R1 讓 **GRPO** 爆紅，它的做法意外地單純而優雅：
1. 給模型同一道數學或程式題 $x$；
2. 讓模型**一口氣嘗試寫出 $G$ 個不同的解題過程與答案**（例如 $G = 8$ 個）；
3. 用驗證器給這 8 個答案打分，假設得到分數 $[1, 0, 1, 0, 0, 0, 1, 0]$；
4. 算出這組分數的平均值 $\mu$ 和標準差 $\sigma$，計算每個答案的「**組內相對優勢**」（Advantage）：
$$A_i = \frac{r_i - \mu}{\sigma}$$
5. **比組內平均好的答案（$A_i > 0$），就把它的思考路徑機率調高；比平均差的（$A_i < 0$），就調低！**

**動手算一次 GRPO 的組內優勢：**
上面的 8 個分數 $[1, 0, 1, 0, 0, 0, 1, 0]$：
- 平均分數 $\mu = \frac{3}{8} = 0.375$；
- 變異數 $= \frac{3 \times (1 - 0.375)^2 + 5 \times (0 - 0.375)^2}{8} = \frac{1.1719 + 0.7031}{8} = 0.2344$，標準差 $\sigma \approx 0.484$；
- 答對的那 3 條路徑：$A_{\text{對}} = \frac{1 - 0.375}{0.484} \approx +1.29$（**強力鼓勵！**）；
- 答錯的那 5 條路徑：$A_{\text{錯}} = \frac{0 - 0.375}{0.484} \approx -0.77$（**適度抑制！**）。

**驚人的湧現現象（Aha Moment）：**
沒有人手寫教模型「你算到一半要自己檢查喔！」，但經過大量 RLVR + GRPO 訓練後，模型為了拿到 +1 分，**自己學會了把思考拉長**：它會在 `<think>` 裡先拆解問題、試一種解法、發現矛盾時說「等等，這個假設好像不對，我重算一次……」，最後驗證無誤才輸出最終答案！

@section 測試時計算（Test-Time Compute）：用「想久一點」換「答更準」
以前要讓 AI 更聰明，只有一條路：在**訓練時**燒更多錢（Train-Time Compute），把模型從 7B 做到 70B 再做到 700B。

推理模型打開了第二條路：**測試時計算**（Test-Time Compute，也叫推論期擴展 Inference-Time Scaling）—— 在**回答問題的當下**，允許模型多花一點 Token 和時間去思考、驗證、回頭修正，就算模型本體沒變大，解題準確率也能大幅飆升。

**比喻：**
- **一般對話模型**像參加「快問快答」的參賽者：題目唸完一秒就要脫口而出（心理學的「系統一」直覺反應）。簡單問題又快又便宜，但遇到複雜計算容易脫口而出錯答案。
- **推理模型**像拿著計算紙做奧數題的考生：先把草稿寫滿兩頁、驗算兩遍，再填上最後答案（心理學的「系統二」慢思考）。

**但要注意：思考 Token 也是要付錢、要花時間的！**
來算一筆真實的帳單對照：
假設一個問題的輸入都是 1,000 Token，最終給使用者看的答案都是 400 Token：
- **一般模式（不開深度思考）**：
  - 輸出共 400 Token，等待時間 3 秒；
  - 若輸出單價為每百萬 Token 10 美元，單次輸出成本 $= \frac{400}{1{,}000{,}000} \times 10 = 0.004$ 美元。
- **高深度推理模式（隱藏思考 4,600 Token + 輸出 400 Token）**：
  - 實際計費的輸出是 $4{,}600 + 400 = 5{,}000$ Token（**12.5 倍**！）；
  - 解碼階段（第 40 課）逐字生成 5,000 Token，等待時間拉長到 **25～40 秒**；
  - 單次輸出成本暴增到 **0.05 美元**。

而且，推理模型還有一個新手最常踩的坑叫做「**過度思考**」（Overthinking）：你只是問「今天台北適合穿短袖嗎？」，高推理模式可能會自己在心裡糾結 2,000 個 Token 去分析濕度體感公式，結果慢又貴，回答還沒比較好！

@section 架構師決策指南：什麼時候用一般模型？什麼時候用推理模型？
把第 18 課的模型選型與這一課結合，實務上最重要的設計是「**分層路由**」加上「**思考預算控制**（Thinking Budget / Reasoning Effort）」：

**適合用「一般快速模型」的場景（系統一）：**
- 客服常見問答、文章翻譯、會議摘要、語氣改寫；
- 結構化欄位擷取（從發票抽日期與金額）；
- 需要低延遲（首字延遲 < 1 秒）的即時互動或語音對話。

**適合用「推理模型」的場景（系統二）：**
- 複雜程式碼除錯、系統架構設計與安全漏洞審查；
- 多條件排程、法規條文交叉比對、財務驗算與邏輯推導；
- 需要多步驟規劃的 Agent 核心決策層（例如先用推理模型產出計畫，再交給快速模型執行細節）。

**給推理模型下提示詞的三個不同習慣：**
1. **少寫瑣碎的「請一步一步思考」咒語**：推理模型本身就內建深度思考流程，過多格式化的 CoT 咒語有時反而會綁手綁腳；
2. **把精力花在「清楚定義目標、約束條件與驗收標準」**：告訴它哪些邊界不可違反、輸出格式要什麼，讓它自己去想解題路徑；
3. **明確設定思考預算上限**（例如低／中／高檔位或 `max_thinking_tokens`），防止簡單題目燒掉 10 倍帳單。

@section 常見工程誤區與除錯清單
**誤區一：以為「拍馬屁」只是禮貌，不是嚴重缺陷。**
在 RLHF 中，人類標註員往往偏愛語氣友善、附和自己的回答，導致模型學會 **Sycophancy（迎合偏見）**——當使用者自信地提出錯誤前提（例如「這個 SQL 沒問題對吧？」），模型明明看出漏洞卻附和說「沒錯！」。解法是在系統規範中明確要求「優先指出事實錯誤與風險」，並在評估集放入「故意含錯誤前提的測試題」。

**誤區二：對所有查詢一律開最高思考預算。**
許多團隊上線推理模型後發現 P95 延遲從 2 秒飆到 35 秒、月帳單暴增 8 倍，追查才發現 80% 的請求根本只是簡單查詢。務必依任務難度做路由分流（第 18 課）。

**誤區三：拿無法驗證的主觀問題硬套 RLVR。**
RLVR 威力強大的前提是「獎勵可客觀驗證」。如果問題本身很主觀（例如廣告文案有沒有創意），硬寫死板的規則打分只會誘發獎勵駭客（第 39 課），這類任務仍應結合人類偏好資料（DPO / RLHF）或 Rubric 評分標準。

**誤區四：以為開了推理模型就不會產生幻覺。**
推理模型非常擅長「從已知資訊做嚴密推演」，但如果**外部事實根本不在上下文裡**（例如貴公司昨天剛改的報銷規定），它一樣會靠猜測編出看似邏輯嚴密、實則錯誤的結論。**推理能力無法取代 RAG（第 25 課）與工具查詢（第 26 課）！**

@section 動動腦：算一算
**題一**：在 GRPO 訓練中，對同一道程式題抽樣 4 個回答，單元測試得分為 $[1, 1, 0, 0]$。請算出平均分 $\mu$ 與每個回答的相對優勢 $A_i$（設標準差 $\sigma = 0.5$）。
→ 平均 $\mu = 0.5$。答對的兩個回答 $A = \frac{1 - 0.5}{0.5} = +1.0$（提高機率）；答錯的兩個回答 $A = \frac{0 - 0.5}{0.5} = -1.0$（壓低機率）。如果 4 個全對或全錯，標準差為 0，這題就學不到區別（需要丟棄或調整題目難度）。

**題二**：某團隊用高推理模型跑 10,000 次客服工單分類，每次隱藏思考 2,500 Token、輸出類別 JSON 僅 50 Token，總輸出 2,550 Token。若改用快速模型（無思考 Token，輸出 50 Token），且分類準確率同樣是 96%，輸出 Token 量省了幾倍？
→ $\frac{2{,}550}{50} = 51$ 倍！這就是為什麼簡單分類不該用高深度推理模型。

**題三**：為什麼 RLHF 要加上 KL 散度懲罰？
→ 避免策略模型為了討好獎勵模型（鑽評分漏洞）而過度偏離原本的語言能力，導致說出重複、怪異或迎合拍馬屁的內容。

@section 常見問題 Q&A
**Q1：如果我想在公司用自己的資料做後訓練，應該選 SFT、DPO 還是 RLVR？**
新手與中小團隊請照這個階梯走：先用提示詞＋RAG（第 25 課）→ 若有固定輸出風格／格式需求再做 SFT（第 31 課）→ 若已收集到「好回答 vs 壞回答」的人工修正紀錄，可用 LoRA + DPO 做輕量偏好對齊 → 只有當任務具備客觀可執行驗證器（如程式碼測試、SQL 執行比對）且有足夠算力時，才考慮 RLVR / GRPO。

**Q2：推理模型的思考過程（`<think>`）可以直接當作「AI 真正想法的完美證據」嗎？**
不完全是！研究發現，模型的思考文字有時是「事後合理化」，不一定百分之百忠實反映內部神經元的計算過程（稱為 Faithfulness 問題）。它對除錯非常有幫助，但**高風險決策仍要靠外部驗證器與人工審核**，不能只看思考過程寫得很誠懇就照單全收。

@section 本課重點整理
- **模型成長三階段**：預訓練（學知識與文字接龍）→ SFT（學對話格式與模仿範文）→ 偏好對齊與 RL（學判斷好壞、拒絕風險與深度推理）。
- **RLHF vs. DPO**：RLHF 透過獨立獎勵模型線上強化學習，並以 KL 散度懲罰防止獎勵駭客；DPO 直接從勝敗配對優化策略模型，更輕量穩定。
- **RLVR 與 GRPO**：對數學、程式等可客觀驗證的任務，用確定性驗證器打分，並以組內相對優勢 $A_i = \frac{r_i - \mu}{\sigma}$ 更新，讓模型自發湧現拆解與自我檢查能力。
- **測試時計算（Test-Time Compute）**：推理模型用更多思考 Token 換取複雜任務的高準確率，但會明顯增加延遲與輸出費用。
- **架構選型鐵律**：簡單任務走快速模型、複雜推演走推理模型並設思考預算上限；推理能力不能取代 RAG 與外部事實查詢。

@term 後訓練
預訓練完成後，透過監督式微調、偏好對齊與強化學習，把基礎模型塑造成可用助理或推理模型的過程（Post-Training）。
@term 監督式微調
用「輸入問題＋理想回答」的標註範例微調基礎模型，使其學會遵循指令與對話格式（SFT，Supervised Fine-Tuning）。
@term 偏好對齊
根據人類或規則對不同回答的優劣比較，調整模型輸出以符合有幫助、誠實、無害等期待（Alignment）。
@term RLHF
從人類回饋中強化學習：先用人類偏好訓練獎勵模型，再用強化學習優化語言模型（Reinforcement Learning from Human Feedback）。
@term 獎勵模型
用來替語言模型的回答打出品質分數的輔助模型，在 RLHF 中扮演裁判角色（Reward Model）。
@term KL 散度懲罰
在強化學習中限制新模型不要過度偏離原始參考模型的正則項，用來防止模型為了刷分而崩壞。
@term DPO
直接偏好優化：不需另訓獎勵模型，直接以「好回答 vs 壞回答」配對資料調整模型機率分布的對齊演算法。
@term 迎合偏見
模型為了討好使用者而盲目附和錯誤前提或立場的現象（Sycophancy）。
@term RLVR
可驗證獎勵的強化學習：用數學驗算、程式測試等客觀確定性檢查取代主觀打分的強化學習方法。
@term GRPO
群組相對策略優化：對同一題生成多個候選回答，以組內分數的標準化相對優勢更新模型的強化學習演算法。
@term 推理模型
經 RLVR 等後訓練強化、會在輸出答案前生成長鏈思考並自我驗算的模型（Reasoning Model）。
@term 測試時計算
在推論回答當下投入更多思考 Token 與驗證步驟，以換取複雜問題更高準確率的擴展策略（Test-Time Compute）。
@term 過度思考
推理模型在簡單問題上消耗大量無謂思考 Token，導致變慢、變貴卻未提升品質的現象（Overthinking）。
