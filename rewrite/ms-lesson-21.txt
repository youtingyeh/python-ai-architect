@section 開場：同一個模型，為什麼換家廠商就變笨了？
一個真實常見的故事：

某團隊在雲端廠商 A 使用 `Llama-3.3-70B-Instruct` 模型，系統穩定運作了好幾個月。後來工程師發現廠商 B 也提供**同名的模型**，價格便宜 40%。他心想：「同一個開源模型，品質一定一樣。」於是只改了一行網址，把流量切過去，也沒有重新測試。

結果切換當天，繁體中文錯字變多，工具呼叫的 JSON 格式錯誤率**暴增三倍**。

同一個模型，為什麼換個地方跑，表現就差這麼多？

這一課以 Meta 的 **Llama** 模型家族為例，對應 Microsoft《Generative AI for Beginners》第 21 課「使用 Meta 模型建構應用」。Llama 是最有影響力的「**開放權重**」模型之一：Meta 公開了模型的參數，任何人都可以下載、部署、微調（在授權條款範圍內）。我們要學：
1. 使用開放權重模型時的**三層責任**；
2. Llama 家族的不同尺寸，各適合什麼用途；
3. 為什麼同名模型在不同廠商會表現不同；
4. **對話模板**：一個很不起眼卻會讓模型能力大跌的細節；
5. 自己架設還是用雲端服務？
6. 正式上線的治理重點。

（註：本課提到的具體版本和條款以撰寫時的資料為例，實際使用前請查看最新的官方說明。）

@section 三層責任：權重、執行環境、應用
使用閉源的商業模型時（例如透過 OpenAI 的 API 使用 GPT 系列），「模型」和「運行模型的伺服器」是同一家公司一起提供的，你只要呼叫 API 就好。

但使用 Llama 這種開放權重模型時，事情被拆成了**三層**，每一層由不同的人負責：

**第一層：模型權重和授權（由 Meta 提供）。**
包含：
- 神經網路的結構和訓練好的參數；
- 知識截止日期（第 2 課）；
- Tokenizer 和約 12.8 萬個 Token 的詞表；
- 官方的**對話模板**（後面會詳細說明）；
- **授權條款**：Llama 使用 Meta 自己的社群授權，不是 Apache-2.0。例如規定月活躍使用者超過 7 億的公司需要另外申請授權、產品命名的規範，以及一份「可接受使用政策」，列出禁止的用途。

**第二層：執行環境和託管（你選擇的）。**
模型參數只是一個檔案，需要有軟體和硬體把它「跑起來」。你可以：
- **自己架設**：在自己的顯示卡上，用開源的推論引擎（例如 vLLM、SGLang、TGI，第 40 課會介紹）運行；
- **向雲端廠商購買**：AWS、Google Cloud、Azure，以及許多專門的 AI 託管公司，都提供 Llama 的 API。

**關鍵：**不同廠商的量化精度、處理方式、速度限制、資料保存政策，可能**完全不同**。

**第三層：應用和安全治理（你的團隊全權負責）。**
模型的原始參數**不包含**：
- 使用者身分驗證；
- RAG 的權限隔離（第 25 課）；
- 輸入和輸出的內容安全檢查（第 28、29 課）；
- 稽核紀錄。

這些都必須由你自己在應用層建立。

**比喻：**開放權重模型像一份公開的食譜（第一層）。不同的餐廳（第二層）可以照著做，但有的用頂級食材、有的偷偷換成便宜的；有的火候精準、有的隨便。而這道菜端上桌時的衛生、過敏標示、服務品質（第三層），則是你這家店自己的責任。

@section Llama 家族：從手機到資料中心
現代的 Llama 家族涵蓋了各種尺寸，而且共用同一套 Tokenizer 和工具呼叫格式，方便在不同任務間搭配使用（以 Llama 3.x 世代為例）：

**超輕量：1B 和 3B。**
- 從大模型經過「**修剪**」（Pruning，去掉不太重要的參數）和**蒸餾**（第 32 課）而來；
- 量化後只需 1 到 2.5 GB 記憶體；
- 適合：手機、筆電、需要極低延遲的初步分類或「路由」（判斷要把問題交給哪個系統處理）。

**主力小模型：8B。**
- 一張 16 到 24 GB 的顯示卡就能順暢運行；
- 適合：大量的搜尋摘要、資料擷取、特定領域的 LoRA 微調（第 31 課）。

**企業主力：70B。**
- 在多步驟推理、中文理解、工具呼叫的穩定度上大幅提升；
- Llama 3.3 70B 在許多測試上接近更早期 405B 模型的表現；
- 是很多企業正式環境的**甜蜜點**：能力夠強，部署成本還可以接受。

**旗艦：405B。**
- 部署成本很高，比較適合**離線**工作：
  - 產生高品質的合成資料，用來微調小模型；
  - 當「**AI 評審**」（第 21 課），幫忙評分其他模型的輸出；
  - 當蒸餾的「教師模型」，把能力傳給 8B 小模型。

**看圖模型：11B 和 90B Vision。**
- 可以同時理解圖片和文字，例如讀圖表、表單、截圖。

@section 同名模型，不同表現：四個隱藏差異
回到開場的故事。為什麼「同一個模型名稱」，在不同廠商（甚至同一個推論引擎的不同設定）下表現天差地遠？原因在第二層，有四個常見的隱藏差異：

**差異一：偷偷量化。**
有些主打超低價或超高速的廠商，在後台把原本 16 位元的模型參數，甚至 KV 快取，**降級**成 8 位元或 4 位元（第 32 課的量化），卻沒有在模型名稱上清楚標示。

一般聊天時看不太出差別，但遇到繁體中文專有名詞、複雜的 JSON 格式時，準確度就會明顯下降。還記得第 32 課說的嗎？**量化最傷的，正是中文罕見字和複雜格式。**

**差異二：結構化輸出的實作。**
要求模型輸出符合特定格式的 JSON 時（第 34 課），很多廠商會用一種叫「**約束解碼**」（Constrained Decoding）的技術：在生成每個 Token 時，直接排除不符合格式的選項。但不同廠商用的工具不同，對複雜格式的支援程度也不一樣。

**差異三：上下文長度被截短。**
模型本身支援 128K Token，但某些廠商的 API 可能只開放 8K 或 32K。超過的部分可能被直接截掉，而你不一定會收到錯誤訊息。

**差異四：偷偷加了提示詞。**
有些廠商會在你的提示詞前面，自動插入他們自己的系統提示詞（例如安全規範），影響模型的行為。

**教訓：**模型名稱只是第一層的身分證，第二層的實作才決定你實際拿到的品質。**換廠商，就等於換模型，一定要重新測試。**

@section 對話模板：一個小細節，能力掉四成
自己架設開源模型時，最常見的人為錯誤是**對話模板**（Chat Template）用錯。

**什麼是對話模板？**
回想第 15 課：模型經過「指令微調」才學會對話。微調時，每一段對話都用一套**特殊的控制符號**包起來，讓模型知道「這是系統指令」「這是使用者說的」「這是我該回答的」「這一輪結束了」。

以 Llama 3 為例，一段對話會被轉成這樣的格式：
```
<|begin_of_text|><|start_header_id|>system<|end_header_id|>

你是一位客服助理。<|eot_id|><|start_header_id|>user<|end_header_id|>

訂單什麼時候到？<|eot_id|><|start_header_id|>assistant<|end_header_id|>

```
- `<|start_header_id|>` 和 `<|end_header_id|>`：包住說話者的身分；
- `<|eot_id|>`：代表「這一輪說完了」（End of Turn）。模型回答完時，也會輸出這個符號，代表「我講完了」。

**這些符號是模型在訓練時看了幾百萬次的格式。**格式一錯，就像對一個習慣讀橫式文件的人，突然給他一份直式、標點全亂的文件。

**常見錯誤一：用錯模板或自己拼字串。**
- 沿用舊版 Llama 2 的格式 `[INST] ... [/INST]`；
- 或圖方便自己寫：`"User: 訂單什麼時候到？\nAssistant: "`。

模型**不會報錯**，還是會回答，但因為輸入格式和訓練時不同，它的指令遵循和推理能力可能**下降 20% 到 40%**。最可怕的是，這種退化不會有任何錯誤訊息提醒你。

**常見錯誤二：沒設定停止符號。**
忘了告訴推論引擎「看到 `<|eot_id|>` 就停止」。結果模型回答完問題後**停不下來**，開始自己扮演使用者，自問自答下一輪對話，一直生成到字數上限才被截斷。浪費費用，還會把奇怪的內容顯示給使用者。

**正確做法：永遠用官方工具自動產生格式。**
大部分工具都提供現成的函式，例如：
```
tokenizer.apply_chat_template(messages)
```
它會根據模型自帶的模板，自動把對話轉成正確的格式。**絕對不要自己手寫字串拼接。**

@section 自己架設還是用雲端服務？
決定第二層要自己架還是向廠商買時，有兩個主要的考量。

**考量一：使用量和成本的交叉點。**
- **自己架設**：顯示卡是**按時間**付費的。不管有沒有人在用，機器開著就在花錢。
- **雲端 API**：**按用量**付費，用多少付多少。

**比喻：**自己買車 vs. 搭計程車。每天通勤長距離，買車划算；一個月只出門幾次，搭計程車便宜得多。

具體來說：
- 如果系統只有上班時間偶爾有人用，顯示卡平均使用率**低於 20%**，用雲端 API 通常比長期租兩張高階顯示卡便宜 **60% 以上**；
- 如果是全天候、大量、穩定的使用（使用率長期**超過 55%**），自己架設並搭配第 40 課會介紹的批次處理技術，每個 Token 的平均成本可以壓得很低。

**考量二：資料隱私。**
金融、醫療、政府單位要特別確認：
- **零資料保存**（Zero Data Retention，ZDR）：廠商是否承諾不記錄你的提示詞和輸出、絕不拿你的資料訓練模型？
- **資料存放地點**：資料在哪個國家的機房處理？受哪國法律管轄？

如果法規要求資料**完全不能離開**公司內部網路（甚至完全不連外網），那自己架設開放權重模型就是**唯一**的選擇。這也正是開放權重模型最大的優勢之一。

@section 上線治理：記錄完整「指紋」，加上安全防護
把 Llama 或任何開放權重模型推上正式環境時，有兩件事必須做到。

**一、記錄「模型 + 執行環境」的完整指紋。**
在上線紀錄中，只寫 `"model": "llama-3.3-70b-instruct"` 是**完全不夠**的。必須完整記錄：
- **權重版本**：參數檔案的唯一識別碼；
- **執行環境**：哪家廠商，或自建時用哪個推論引擎、哪個版本；
- **量化精度**：16 位元、8 位元還是 4 位元；
- **對話模板**的版本；
- **停止符號**的設定。

**原則：**任何一項改變（換廠商、升級推論引擎、調整量化），都要**視同換了一個新模型**，重新跑完整的黃金測試集，確認表現一致後才能上線。這叫做「**廠商一致性驗證**」。

**二、在應用層加上獨立的安全防護。**
開放權重模型讓開發者完全掌控系統提示詞和微調，這也代表**沒有人幫你把關**。企業必須在第三層自己建立防護：
- **輸入端**：在請求送進主模型**之前**，用一個輕量的安全分類模型（例如 Meta 提供的 **Llama Guard** 或 Prompt Guard）和規則過濾，攔截越獄和提示詞注入（第 29 課）；
- **輸出端**：在回答送回使用者**之前**，再檢查一次，攔截不當內容和個資外洩。

這就是第 29 課的「**縱深防禦**」：不依賴單一防線，層層把關。

@section 動動腦：抓出問題
**情境一**：開場的故事，團隊只改了網址就把流量切到便宜的廠商 B，結果中文錯字和 JSON 錯誤暴增。最可能的原因是什麼？
→ 第二層的差異：廠商 B 可能偷偷量化、用不同的對話模板或約束解碼工具。換廠商就等於換模型，必須重新測試。

**情境二**：工程師自己架設 Llama 8B，用 `f"System: {sys}\nUser: {q}\nAssistant:"` 拼接提示詞，結果模型回答完後停不下來，繼續自問自答。為什麼？
→ 手寫的格式破壞了官方的特殊控制符號，而且沒有設定 `<|eot_id|>` 為停止符號，模型無法辨認「這一輪結束了」。應改用 `apply_chat_template()`。

**情境三**：一個內部系統每天只有上午會被使用約 200 次，該自己買顯示卡架設，還是用雲端 API？
→ 使用率很低，雲端 API 通常便宜得多。除非資料有不能離開內網的法規要求。

**情境四**：三層責任中，哪一層要負責「確認員工只能查到自己有權限的文件」？
→ 第三層（應用和治理層），由你的團隊負責。模型權重和託管廠商都不會幫你做。

@section 常見問題 Q&A
**Q1：「開放權重」和「開源」一樣嗎？**
不完全一樣。嚴格意義的「開源」通常要求公開訓練程式碼、訓練資料，並使用允許自由使用的授權。很多模型（包括 Llama）只公開了訓練好的參數，訓練資料沒有完整公開，授權也有一些限制，所以比較精確的說法是「**開放權重**」（Open Weights）。

**Q2：自己架設模型需要多少技術能力？**
用 Ollama 或 LM Studio 這類工具，在自己的電腦上跑一個小模型，幾乎不需要技術背景，下載後點幾下就能用。但要架設一個能同時服務幾百位使用者、穩定可靠、有監控的正式系統，就需要專業的工程能力（工程篇的系統架構課程會談到）。

**Q3：Llama Guard 是什麼？**
它本身也是一個語言模型，但經過特別訓練，專門判斷一段文字是否屬於某些危險類別（例如暴力、犯罪、自我傷害等）。它很小、很快，適合放在主模型前後當「安檢門」。

@section 本課重點整理
- **三層責任**：模型權重與授權（Meta）、執行環境與託管（你選的廠商或自建）、應用與安全治理（你的團隊）。
- **Llama 家族**：1B/3B 適合邊緣裝置；8B 單卡主力；70B 企業甜蜜點；405B 適合合成資料和當教師；Vision 版本能看圖。
- **同名不同表現**：偷偷量化、約束解碼工具不同、上下文被截短、偷加提示詞。換廠商就等於換模型。
- **對話模板**：格式錯誤能力可能下降 20% 到 40%，且不會報錯；忘了停止符號會自問自答。永遠用 `apply_chat_template()`。
- **自建 vs. 雲端**：使用率低用雲端 API，使用率高且穩定可考慮自建；資料不能離開內網時只能自建。
- **上線治理**：記錄權重、廠商或引擎、量化、模板、停止符號的完整指紋；任一改變都要重新測試。應用層加上 Llama Guard 等縱深防禦。

@term 開放權重
公開訓練好的模型參數供人下載使用，但不一定公開訓練資料或完全無限制（Open Weights）。
@term 推論引擎
把模型參數載入顯示卡並處理請求、生成文字的軟體，例如 vLLM。
@term 託管廠商
提供模型 API 服務、替你運行模型的雲端公司（Hosting Provider）。
@term 修剪
移除模型中較不重要的參數，讓模型變小的技術（Pruning）。
@term 約束解碼
生成每個 Token 時排除不符合指定格式的選項，確保輸出格式正確。
@term 對話模板
指令微調時用來標示系統、使用者、助理各段落的固定格式（Chat Template）。
@term 特殊控制符號
對話模板中標示段落開始、結束等用途的特殊 Token，例如 eot_id。
@term 停止符號
告訴推論引擎看到就停止生成的 Token（Stop Token）。
@term 零資料保存
廠商承諾不記錄、不保存、不拿使用者資料訓練的政策（Zero Data Retention）。
@term 資料存放地點
資料實際被處理和儲存的國家或機房，影響適用的法律（Data Residency）。
@term 廠商一致性驗證
更換廠商或執行環境後，重新測試確認模型表現一致的程序。
@term Llama Guard
Meta 提供的安全分類模型，用來檢查輸入與輸出是否含有危險內容。
@term 縱深防禦
設置多層獨立防護，不依賴單一防線的安全設計原則。
