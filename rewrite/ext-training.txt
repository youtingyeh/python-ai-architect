@section 開場：把零件組裝成一台會學習的機器
到目前為止，我們已經收集了一整箱零件：
- **張量**（第 3 課）：裝資料的容器；
- **梯度與自動微分**（第 4 課）：告訴每個旋鈕往哪轉；
- **損失函數與梯度下降**（第 5 課）：衡量錯多少、一步步修正；
- **資料切分**（第 6 課）：公平地考試；
- **Softmax 與交叉熵**（第 7 課）：分類時怎麼輸出機率、怎麼計分。

這一課要把它們組裝起來，變成一台真正的「**神經網路**」，並搞清楚電腦每一次學習時，**到底依序做了哪些事**。

為什麼「順序」值得花一整課？因為神經網路的訓練程式有一個很討厭的特性：**順序寫錯了，程式通常不會報錯**。它會照樣跑，損失值也照樣印出來，只是模型什麼都沒學到，或學得很慢、很怪。很多新手會花好幾天懷疑模型架構、懷疑資料，最後才發現只是兩行程式碼的順序顛倒了。

我們會依序學：
1. 為什麼神經網路一定要有「非線性」這個關鍵零件；
2. 為什麼資料要一小批一小批地餵；
3. 每一次學習的「黃金五步驟」；
4. 訓練模式和考試模式的切換；
5. 幾種常見的「調整方法」（優化器）；
6. 損失卡住不動時，該從哪裡開始查。

@section 疊再多層直線，還是一條直線：為什麼需要「非線性」
第 5 課的線性回歸只是一條直線（或多個輸入時的一個平面）。它很好懂，但能力有限：很多真實世界的關係是彎的、是有轉折的。例如房價和坪數，小坪數時每坪很貴，大到一定程度後每坪價格反而下降。

最直覺的升級方法：**把好幾層線性計算串在一起**。第一層算出一組中間結果，餵給第二層，再餵給第三層……這種一層接一層、每層都和上一層全部連接的結構，叫做**多層感知機**（MLP，Multilayer Perceptron）。中間那些不是輸入也不是輸出的層，叫做**隱藏層**（Hidden Layer），因為我們不會直接看到它們的內容。

但這裡有個陷阱。假設第一層是 $\mathbf{h} = \mathbf{x} W_1 + \mathbf{b}_1$，第二層是 $\hat{\mathbf{y}} = \mathbf{h} W_2 + \mathbf{b}_2$，中間什麼都不加。（粗體的 $\mathbf{x}$、$\mathbf{h}$ 代表一整排數字，$W$ 是權重表格。）把第一層代進第二層展開：

$$\hat{\mathbf{y}} = (\mathbf{x} W_1 + \mathbf{b}_1) W_2 + \mathbf{b}_2 = \mathbf{x} (W_1 W_2) + (\mathbf{b}_1 W_2 + \mathbf{b}_2)$$

兩個權重表格相乘 $W_1 W_2$，結果還是一個權重表格；後面那串也只是一組常數。所以整個式子等於：

$$\hat{\mathbf{y}} = \mathbf{x}\, W_{\text{eff}} + \mathbf{b}_{\text{eff}}$$

（eff 是 effective，「實際上等效的」。）**兩層直線疊起來，還是一層直線。**不管你疊 2 層還是 1,000 層，只要中間全是線性計算，整個網路在數學上都會「塌縮」成一層。就像把好幾片平面鏡疊在一起，照出來的永遠是平的，不會變成哈哈鏡。

這種網路連一個很經典的簡單問題都解不了：**XOR**（互斥或）。規則是「兩個輸入恰好一個為真時輸出真」。如果把四種情況畫在紙上，你會發現沒辦法用一條直線把「真」和「假」分開。

**解法：在每一層之後加上一個「彎曲」的動作。**

這個動作叫做**激活函式**（Activation Function），寫成 $\sigma(\cdot)$。隱藏層變成：

$$\mathbf{h} = \sigma(\mathbf{x} W_1 + \mathbf{b}_1)$$

現代最常用的激活函式是 **ReLU**，規則簡單到不可思議：

$$\text{ReLU}(z) = \max(0, z)$$

**負數變成 0，正數維持不變。**就像一個單向閥門：水往一邊流可以通過，往另一邊流就被擋住。

就這麼簡單的一個轉折，讓神經網路能拼出任意複雜的形狀。想像用很多根「折了一次的吸管」拼圖案：每根吸管只折一次，但幾百根拼起來，可以近似出任何曲線。數學家證明了，只要神經元夠多，加了非線性的網路理論上可以逼近任何連續的函數，這叫做「**通用近似定理**」（Universal Approximation Theorem）。

ReLU 還有兩個實務上的優點：計算極快（只是比大小）；正數那一側的導數永遠是 1，梯度可以順暢地往回傳，比較不會發生第 7 課提到的「梯度消失」。ChatGPT 這類 Transformer 模型則常用 ReLU 的平滑版本 **GELU**，原理類似，只是轉折處比較圓滑。

@section 一口一口吃：小批次梯度下降
有了網路架構，接下來要餵資料。假設訓練集有 100 萬筆資料，有三種餵法：

**餵法一：一口吞下全部（全批次梯度下降，Full-Batch GD）。**把 100 萬筆一次全部算完，求出平均損失和梯度，才更新一次參數。問題是：顯示卡（GPU）的記憶體根本塞不下，程式會直接因為記憶體不足而當掉（錯誤訊息常寫 **OOM**，Out of Memory）；而且辛辛苦苦算了 100 萬筆，才跨出一小步，太慢了。

**餵法二：一次一粒（隨機梯度下降，SGD，Batch Size = 1）。**每看一筆資料就更新一次。更新很頻繁，但單筆資料的梯度「雜訊」很大——就像只問一個路人就決定方向，可能被帶歪。而且顯示卡擅長同時算很多東西，一次只算一筆，等於讓一百個人的工廠只派一個人上工。

**餵法三：一小口一小口（小批次隨機梯度下降，Mini-batch SGD）。**這是現代深度學習的標準做法。每次拿一小批，例如 32、64 或 256 筆，算出這批的平均梯度，更新一次參數。

在 PyTorch 裡，負責「切小批、端上桌」的工具叫做 `DataLoader`。通常這樣設定：

```
DataLoader(dataset, batch_size=64, shuffle=True)
```

- `batch_size=64`：每批 64 筆。
- `shuffle=True`：每一輪開始前，先把訓練資料**洗牌打亂**。

把全部訓練資料完整看過一遍，叫做一個 **Epoch**（訓練輪次，念作「艾波克」）。每處理一個小批次、更新一次參數，叫做一個 **Step** 或 **Iteration**（一步）。例如 100 萬筆資料、每批 64 筆，一個 Epoch 大約是 15,625 步。

小批次同時有三個好處：
1. **記憶體用量固定可控**，不會爆掉。
2. **剛好能塞滿顯示卡的平行算力**，效率高。
3. **適度的雜訊反而有好處**：每批抽到的資料不同，梯度會帶點隨機晃動，這讓模型比較容易跳出「又尖又窄的小坑」，落到「寬而平的谷底」。寬平的谷底通常代表模型學到的規律比較穩健，遇到新資料時表現較好。

（第 6 課說時間序列不能隨機打亂來**切分**資料集；這裡的 shuffle 是在**訓練集內部**打亂餵的順序，兩件事不衝突。）

@section 每一次學習的黃金五步驟
這是本課最重要的一節。每從 `DataLoader` 拿到一批資料 `(x, y)`（x 是輸入、y 是正確答案），PyTorch 的訓練程式**必須依照這個順序**做五件事：

**第 1 步：清除舊的梯度——`optimizer.zero_grad()`**
把所有參數的梯度存錢筒倒空。第 4 課說過，PyTorch 的梯度是「累加」的，不清空的話，上一批的梯度會混進來。

**第 2 步：前向傳播——`y_hat = model(x)`**
把這批輸入送進神經網路，一層一層算到底，得到預測 `y_hat`。同時，自動微分在背後畫好計算圖、暫存中間結果。

**第 3 步：計算損失——`loss = criterion(y_hat, y)`**
比較預測和正確答案，算出這一批的平均損失，得到**一個數字**。（`criterion` 是「評判標準」，也就是你選的損失函數，例如 MSE 或交叉熵。）

**第 4 步：反向傳播——`loss.backward()`**
從損失出發，沿著計算圖往回走，用鏈式法則算出損失對**每一個參數**的梯度，存進各參數的 `.grad`。

**第 5 步：更新參數——`optimizer.step()`**
「**優化器**」（Optimizer）讀取每個參數的梯度，依照它的更新規則（最簡單的就是 $\theta \leftarrow \theta - \eta \cdot \text{grad}$，$\theta$ 念作 theta，代表任一個參數）**實際修改**模型的權重。

用學生寫考卷來比喻：
1. 擦掉上次的批改痕跡；
2. 寫這次的考卷；
3. 對答案、算分數；
4. 逐題找出錯在哪、該怎麼改；
5. 真正動手把筆記改正。

**特別注意：真正改變模型的，只有第 5 步。**前四步都只是在「計算」，第 5 步才「動手」。所以如果你漏寫了 `optimizer.step()`，模型永遠不會變。

**最常見的順序錯誤：**把 `zero_grad()` 寫在 `backward()` 和 `step()` 之間：

```
loss.backward()          # 算好梯度
optimizer.zero_grad()    # 糟糕，剛算好的梯度被清成 0
optimizer.step()         # 用全是 0 的梯度更新 → 原地踏步
```

程式完全不會報錯，損失每一輪都印得出來，只是永遠不會下降。這就是開場說的「順序錯了，模型什麼都沒學到」。

**把五步驟放進完整流程：**

```
for epoch in range(訓練輪數):
    model.train()                       # 切到訓練模式（下一節解釋）
    for x, y in train_loader:           # 一批一批拿資料
        optimizer.zero_grad()           # 1 清梯度
        y_hat = model(x)                # 2 前向
        loss = criterion(y_hat, y)      # 3 算損失
        loss.backward()                 # 4 反向
        optimizer.step()                # 5 更新
    # 每輪結束後，用驗證集考一次（下一節）
```

@section 上課模式與考試模式：model.eval() 和 no_grad() 都要寫
每個 Epoch 訓練完，通常會用驗證集（第 6 課的模擬考）考一次，看模型進步了沒。這時候標準寫法一定會同時出現兩行：

```
model.eval()
with torch.no_grad():
    ...用驗證集計算分數...
```

很多工程師以為這兩行是重複的，只寫了其中一行。**這是很危險的誤解，因為它們控制的是兩套完全不同的東西。**

**`model.train()` / `model.eval()`：切換某些「零件」的行為。**

有兩種常見的網路零件，在「上課（訓練）」和「考試（評估）」時的做法不一樣：

- **Dropout 層**：訓練時，它會**隨機**把一部分神經元暫時關掉（例如每次隨機關掉 20%），並把剩下的輸出放大一點來補償。目的是逼網路不要過度依賴少數幾個神經元，有點像球隊練習時隨機讓幾個主力坐板凳，逼其他人也練起來。（第 9 課會詳細講。）但**考試時必須全員上場**，關閉隨機丟棄，讓結果穩定、每次都一樣。
- **BatchNorm（批次正規化）層**：它會把每一層的數值調整到穩定的範圍，讓訓練更順。訓練時，它用「**這一小批**」資料的平均和標準差來調整，同時偷偷記錄一個長期平均；**考試時**，則改用訓練期間累積下來的「**長期平均**」。因為考試時可能一次只考一題，一題的「平均」沒有意義。

`model.eval()` 就是把這些零件切換成考試模式；`model.train()` 切回上課模式。

**`with torch.no_grad():`：關掉自動微分的「記錄」。**

第 4 課學過，前向傳播時 PyTorch 會畫計算圖、暫存中間結果，準備給反向傳播用。考試時根本不需要反向傳播，這些記錄全是浪費。`no_grad()` 就是告訴 PyTorch：這一區別畫圖、別暫存。可以省下大約一半的記憶體，而且算得更快。

**只寫一個會怎樣？**
- **只寫 `model.eval()`**：Dropout 和 BatchNorm 正確切換了，但 PyTorch 還是在畫計算圖、暫存一大堆東西。驗證資料一多，顯示卡記憶體就可能爆掉。**`eval()` 完全不會關閉梯度追蹤。**
- **只寫 `no_grad()`**：記憶體省下來了，但 Dropout 還在考試時隨機關掉神經元，同一份考卷每次考的分數都不一樣，而且偏低。

所以**驗證和推論時兩行都要寫**。還有一個常被遺忘的收尾：驗證結束後，要記得呼叫 `model.train()` 切回訓練模式，否則下一輪訓練會在考試模式下進行。

@section 優化器：從「直直走」到「有慣性的球」再到「每人一雙鞋」
第 5 步 `optimizer.step()` 裡，優化器到底怎麼利用梯度？不同的優化器有不同的「走路方式」。

**① 標準 SGD：照梯度直直走。**

規則就是 $\theta_{t+1} = \theta_t - \eta\, g_t$（$g_t$ 是第 t 步的梯度）。在漂亮的碗形地形上很好用，但真實的損失地形常常像一條「**兩側山壁很陡、谷底很平緩的狹長峽谷**」。

這時 SGD 會出現一個尷尬的行為：它幾乎只感受到兩側陡峭山壁的坡度，於是在峽谷兩側來回反彈，像乒乓球一樣；而真正通往終點、沿著谷底的那個平緩方向，前進得非常慢。

**② 動量（Momentum）：像一顆有慣性的鐵球。**

想像不是一個人在走，而是一顆重鐵球滾下山。它不只看「現在的坡度」，還帶著「之前累積的速度」：

$$v_t = \beta\, v_{t-1} + g_t$$

$v_t$ 是目前的速度，$\beta$（念作 beta，通常設 0.9）代表「保留多少之前的速度」。

效果很神奇：在峽谷兩側來回的那個方向，這一步往左、下一步往右，正負互相**抵銷**，震盪變小了；而沿著谷底的那個方向，每一步都朝同一邊，速度**不斷累積加快**。鐵球自然就沿著谷底滾下去了。

**③ Adam / AdamW：每個參數有自己的步伐。**

現代深度學習最常用的是 **Adam**，以及它的改良版 **AdamW**（W 代表把一種叫「權重衰減」的正則化做了更正確的處理，第 9 課會講）。

Adam 除了有動量（記錄梯度的平均方向，寫作 $m_t$），還額外記錄**每個參數各自的梯度有多大、多不穩定**（梯度平方的平均，寫作 $v_t$），然後把步伐除以 $\sqrt{v_t}$：

- 梯度一直很大、很劇烈震盪的參數 → 除以一個大數字 → **自動縮小步伐**，避免暴衝。
- 梯度一直很小、很少被更新的參數 → 除以一個小數字 → **自動放大步伐**，讓它也學得到。

就像一支登山隊，不是所有人都用同一個步伐，而是每個人依照自己腳下的地形自動調整：陡峭處小步走、平坦處大步走。這讓深層網路和 Transformer 的訓練快很多、也穩定很多。

實務上，如果你不知道該用哪個，**AdamW 配上學習率 0.001（寫作 `1e-3`）左右**，是一個很常見的起點。

@section 損失卡住不動？六點除錯清單
寫完訓練程式按下執行，卻發現每一輪印出的損失像一灘死水，完全不降（或在原地小幅跳動），請依序檢查以下六點：

**1. 五步驟的順序和完整性。**`zero_grad()` 是不是寫到 `backward()` 後面去了？是不是只寫了 `backward()`，忘了寫真正更新權重的 `step()`？

**2. 優化器手上拿的是不是「現在這個」模型。**建立優化器時會把模型的參數交給它：`torch.optim.AdamW(model.parameters(), lr=1e-3)`。如果之後你又重新建立了模型（`model = MyModel()`），優化器手上握著的還是**舊模型**的參數。它很認真地更新舊模型，而你拿來預測的新模型從沒被動過。就像你很認真地在幫上一台車加油。

**3. 是不是忘記切回訓練模式。**上一輪驗證結束後，有沒有呼叫 `model.train()`？如果沒有，後面的訓練都在考試模式下進行，Dropout 和 BatchNorm 行為都不對。

**4. 計算圖是不是被不小心剪斷了。**在計算損失的過程中，有沒有用到 `.detach()`、`.item()`（把張量變成一個普通 Python 數字），或轉成 NumPy 陣列再轉回來？這些動作都會切斷梯度的回傳路線，讓梯度變成 0。

**5. 預測和答案的形狀、格式對不對。**回歸任務有沒有發生第 3 課的 `(B, 1)` 減 `(B,)` 靜默廣播？分類任務是不是把已經做過 Softmax 的機率，又餵給了 `nn.CrossEntropyLoss()`（第 7 課提醒過它要直接吃 Logits）？

**6. 最強的一招：用一小批資料「硬背」測試。**在跑全部資料之前，只拿 **1 個小批次**（例如 8 筆）反覆訓練 200 步。一個健康的模型和程式，**一定能**把這 8 筆背得滾瓜爛熟，損失降到接近 0。如果連 8 筆都背不起來，那問題 100% 在程式邏輯，而不是資料太難或模型太小。這招叫做「**單批次過擬合測試**」（Single-Batch Overfit Sanity Check），是有經驗的工程師開始新專案時一定會做的第一步。

@section 跟著練一次：這段程式哪裡錯了？
看看下面這段訓練程式，找出所有問題。先自己找，再看說明。

```
model = MyModel()
optimizer = torch.optim.AdamW(model.parameters(), lr=1e-3)
model = MyModel().to("cuda")         # A

for epoch in range(10):
    for x, y in train_loader:
        y_hat = model(x)
        loss = criterion(torch.softmax(y_hat, dim=1), y)   # B
        loss.backward()
        optimizer.zero_grad()          # C
        optimizer.step()
    model.eval()
    val_loss = evaluate(model, val_loader)                 # D
```

**問題 A**：優化器建立之後，又重新建了一個模型並搬到顯示卡上（`cuda` 是 NVIDIA 顯示卡的運算平台）。優化器手上的是舊模型的參數，新模型永遠不會被更新。→ 應該先建好模型、搬到顯示卡，**再**建立優化器。

**問題 B**：如果 `criterion` 是 `nn.CrossEntropyLoss()`，它內部已經包含 Softmax，這裡又自己做了一次，等於做兩次。→ 直接傳 `y_hat`（Logits）。

**問題 C**：`zero_grad()` 放在 `backward()` 之後，把剛算好的梯度清掉了，`step()` 原地踏步。→ 應該移到迴圈最前面。

**問題 D（兩個）**：驗證前切成了 `eval()`，但下一輪訓練開始時沒有切回 `model.train()`；另外，如果 `evaluate` 裡面沒有寫 `with torch.no_grad():`，驗證時仍會浪費大量記憶體。

這段只有十幾行的程式，藏了五個錯誤，而且**沒有任何一個會讓程式報錯**。這就是為什麼本課要花這麼多篇幅講「順序」和「模式」。

@section 本課重點整理
- **疊多層一定要加非線性**：沒有激活函式，1,000 層線性層也只等於 1 層。ReLU（負數變 0、正數不變）是最常用的選擇，GELU 是它的平滑版。
- **小批次梯度下降**：一次餵一小批（例如 64 筆），兼顧記憶體、速度與泛化。看完全部資料一遍叫一個 Epoch，每批更新一次叫一步。
- **黃金五步驟**：`zero_grad()` → 前向 → 算損失 → `backward()` → `step()`。真正改變模型的只有 `step()`；順序錯了不會報錯，只會學不到東西。
- **驗證時兩行都要寫**：`model.eval()` 切換 Dropout／BatchNorm 的行為；`torch.no_grad()` 關閉梯度追蹤、省記憶體。驗證完記得切回 `model.train()`。
- **優化器**：SGD 直直走、Momentum 像有慣性的鐵球、AdamW 讓每個參數有自己的步伐。不知道選什麼，先用 AdamW、學習率 1e-3。
- **損失卡住**：照六點清單查，最有效的是「用 8 筆資料硬背 200 步」，背不起來就是程式有 bug。

下一課，我們要處理另一個常見的困擾：模型練習題考滿分、新題目卻考很差——也就是「過擬合」，以及對付它的各種方法。

@term 神經網路
由很多層「加權總分＋非線性轉折」組成的模型（Neural Network），層數多的叫深度學習。
@term 多層感知機
最基本的神經網路結構（MLP）：好幾層全連接的線性層，中間夾著激活函式。
@term 隱藏層
神經網路中介於輸入和輸出之間的層（Hidden Layer），我們不會直接看到它的內容。
@term 激活函式
加在每層之後、讓網路能學出彎曲關係的非線性函式（Activation Function），例如 ReLU。
@term ReLU
最常用的激活函式：負數變 0、正數不變。像一個單向閥門，計算快又不容易梯度消失。
@term Epoch
把全部訓練資料完整看過一遍，叫做一個 Epoch（訓練輪次）。
@term 小批次
每次拿來計算梯度、更新一次參數的一小批資料（Mini-batch），常見大小是 32、64、256。
@term 優化器
讀取梯度、實際更新模型參數的工具（Optimizer），例如 SGD、Adam、AdamW。
@term 動量
讓參數更新帶有「慣性」的技巧（Momentum），能抵銷來回震盪、在一致方向上加速。
@term AdamW
目前最常用的優化器之一，結合動量與「每個參數自動調整步伐」，並正確處理權重衰減。
@term Dropout
訓練時隨機暫時關掉一部分神經元的技巧，防止網路過度依賴少數神經元；評估時要關閉。
@term BatchNorm
批次正規化層，把每層的數值調整到穩定範圍。訓練時用當批統計、評估時用長期平均。
@term OOM
Out of Memory，記憶體不足，常見於批次太大或忘記關閉梯度追蹤時。
@term 單批次過擬合測試
只用一小批資料反覆訓練，確認模型能把它背起來的除錯方法。背不起來代表程式有 bug。
