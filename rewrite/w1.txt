前 43 課，我們學的是 AI 本身：它怎麼學習、怎麼生成文字、怎麼安全地用在真實系統裡。在很多課裡，你會看到「交給確定性的程式處理」「工程篇會學到」這類句子。

從這一課開始，我們就來學那些「程式」到底怎麼寫、怎麼組織、怎麼變成一個能上線的系統。工程篇共 33 課，大致分成三段：

這些課假設你**看過一點點 Python**（知道什麼是變數、`if`、`for` 迴圈）。如果完全沒碰過，建議先花一兩個小時看任何一份 Python 入門教學，再回來讀。

這一課的主題是**函式**：程式的最小積木。我們要學：

2. 什麼是「**純函式**」？什麼是「**副作用**」？

4. 「沒有資料」和「數值是 0」為什麼不一樣？
5. 驗證資料時的兩個陷阱：**布林值**和 **NaN**；
6. 怎麼把「新增、查詢、修改、刪除」拆成乾淨的小函式。

@section 為什麼不要寫成一大坨？
很多初學者寫的第一個程式長這樣：從頭到尾一個大迴圈，裡面有讀取鍵盤輸入（`input()`）、檢查格式、計算、印出結果（`print()`），全部混在一起，兩百行。

練習時能跑就好。但一旦要放進真實的系統（例如第 47 課的 AI 助教平台），就會立刻遇到三個問題：

**問題一：沒辦法自動測試。**
第 39、42 課反覆強調：可靠的系統要靠**自動化測試**。但如果你的計算邏輯和 `input()` 綁在一起，測試程式一呼叫它，就會**卡住等人用鍵盤輸入**。如果它把結果用 `print()` 印出來，測試只能去比對螢幕上的文字，非常脆弱。

**問題二：出錯時找不到原因。**
平均分數算錯了。是輸入讀錯了？特殊情況沒處理？還是公式寫錯了？全部混在一起，只能從頭一行一行看。

**問題三：沒辦法重複使用。**
同一套「計算成績」的邏輯，命令列工具要用、網站後端要用、每晚的報表程式也要用。如果它被焊死在一個腳本裡，就只能複製貼上三份。之後改一個規則，要改三個地方，很容易漏改。

**比喻：**一間餐廳，如果主廚同時負責接電話點餐、切菜、炒菜、收銀、洗碗，任何一環出問題，整間店都停擺，也找不出是哪裡慢。把工作拆開，每個人只做一件事，才能各自改進、各自檢查。

@section 純函式：只看輸入，只給輸出
**函式**（Function）就是一段有名字、可以重複呼叫的程式。你給它一些**輸入**（叫做**參數**），它做完事情，**回傳**一個結果。

```
def add(a, b):
    return a + b
```

工程上，我們特別喜歡一種函式，叫做「**純函式**」（Pure Function）。它有兩個特徵：
1. **結果只取決於輸入**：同樣的輸入，永遠得到同樣的輸出。不偷看外面的東西（例如目前時間、某個全域變數、檔案內容）；
2. **沒有副作用**：除了回傳結果，不做任何其他事。不印東西、不寫檔案、不修改傳進來的資料。

**「副作用」**（Side Effect）就是函式在回傳結果之外，對外面世界造成的改變。例如：印到螢幕、寫進資料庫、寄信、修改了別人的資料。

**比喻：**純函式像一台計算機：按 3 + 5，永遠是 8，而且按完不會順便幫你打電話給別人。

副作用本身不是壞事：程式最終一定要存檔、要顯示結果，否則沒有用。重點是**把它們隔開**：
- **核心邏輯**寫成純函式（好測試、好重用）；
- **輸入輸出**（讀鍵盤、印螢幕、讀寫檔案、網路）放在外圍一層薄薄的程式裡。

這種「核心乾淨、外圍處理雜事」的結構，在之後的網站開發中會一再出現。

**輸入輸出契約**（Input/Output Contract）：每個函式都應該說清楚三件事：
- 接受什麼樣的輸入？（例如「一個數字清單，每個數字在 0 到 100 之間」）
- 回傳什麼？（例如「一個字典，包含筆數、平均、最小、最大」）
- 遇到不合法的輸入會怎樣？（例如「拋出 ValueError」）

這就像第 45 課的「規格書」，只是縮小到一個函式的大小。

@section 小心：你的清單被偷偷改掉了
這是 Python 初學者最容易踩、也最難發現的坑之一。

**Python 的變數不是「盒子」，而是「標籤」。**
很多人以為 `a = [1, 2, 3]` 是把清單裝進一個叫 `a` 的盒子裡。實際上，Python 是在記憶體中建立一個清單，再把 `a` 這張**標籤貼在它上面**。這種關係叫做「**參照**」（Reference）。

```
a = [3, 1, 2]
b = a        # b 和 a 貼在「同一個」清單上
b.append(9)
print(a)     # [3, 1, 2, 9]  ← a 也變了！
```

把清單傳進函式時也一樣：函式裡拿到的，是**同一個清單**，不是一份複本。

**危險的寫法：**
```
def top_score(scores):
    scores.sort()        # 直接把原本的清單排序了
    return scores[-1]
```
呼叫完 `top_score(my_scores)` 之後，你會發現 `my_scores` 的順序被改了。如果其他地方還依賴原本的順序（例如第一筆是第一次考試的成績），就出錯了，而且很難追查。

這種直接修改原本資料的行為，叫做「**就地修改**」（In-place Mutation）。像清單（list）、字典（dict）這種可以被修改的資料，叫做「**可變物件**」（Mutable Object）。

**安全的寫法：產生新的，不改舊的。**
```
def top_score(scores):
    return sorted(scores)[-1]   # sorted() 會回傳一份新的排好的清單
```
或者更直接：`max(scores)`。

**原則：除非函式的目的就是修改資料，否則不要改動傳進來的清單和字典。**

@section 「沒有資料」不等於「0 分」
假設要寫一個計算平均分數的函式。如果傳進來的是**空清單** `[]`（例如剛註冊、還沒考過試的新生），應該回傳什麼？

**選項一：回傳 0。**
看起來很合理，但有個嚴重問題：**0 分是一個真實存在的成績**。一個學生考了零分，平均就是 0。如果「沒考試」也回傳 0，下游的報表或 AI 分析，就會把「**還沒有資料**」誤判成「**表現極差**」，可能錯誤地把新生標記為需要輔導。

**選項二：印出「錯誤：沒有成績」。**
違反了純函式原則。而且呼叫的程式拿不到任何可以判斷的值。

**選項三：回傳 `None`。**
`None` 是 Python 中專門表示「**沒有值**」的特殊值。它清楚地告訴呼叫的人：「這裡無法算出結果」，而且不會和任何真實的分數混淆。

**用 `None` 表示「無資料」，用例外表示「資料有錯」**：這種區分，讓每個回傳值都**只有一種意思**，沒有歧義。

**比喻：**體溫計顯示「0 度」和顯示「—（未測量）」是完全不同的意思。前者代表病人出了大事，後者只是還沒量。

順帶一提：如果直接用 `sum(scores) / len(scores)` 計算空清單，會因為「除以 0」而讓程式當掉（`ZeroDivisionError`）。所以**先檢查空清單**，是必要的第一步。

@section 驗證資料的兩個陷阱：布林值和 NaN
資料常常從外部來（使用者輸入、CSV 檔案、其他系統），不一定乾淨。所以函式要**驗證**輸入。這裡有兩個 Python 特有的陷阱。

**陷阱一：`True` 會被當成數字 1。**
在 Python 中，布林值（`True`/`False`）其實是整數的一種「子類別」：
```
isinstance(True, int)   # True
True == 1               # True
True + True             # 2
```
所以，如果你只寫 `isinstance(x, (int, float))` 來檢查「是不是數字」，`True` 會**通過檢查**，被當成 1 分算進平均裡！

外部資料中混入 `True` 並不罕見（例如試算表的勾選欄位）。**正確做法：先排除布林值。**
```
if isinstance(x, bool) or not isinstance(x, (int, float)):
    raise ValueError("分數必須是數字")
```

**陷阱二：NaN 會溜過範圍檢查。**
NaN（Not a Number，「不是數字」）是浮點數中一個特殊的值，常在資料缺漏或計算錯誤時出現（例如 0 除以 0 的浮點結果）。它有一個奇怪的特性：**和任何數字比較，結果都是 False**，連和自己比也是。
```
nan = float('nan')
nan < 0      # False
nan > 100    # False
nan == nan   # False
```

所以如果你這樣檢查範圍：
```
if score < 0 or score > 100:
    raise ValueError(...)
```
NaN 會讓兩個條件都是 False，**直接通過**！接著被算進平均，整個平均都會變成 NaN。

**正確做法：改成「必須在範圍內」的寫法。**
```
if not (0 <= score <= 100):
    raise ValueError("分數必須在 0 到 100 之間")
```
NaN 不滿足 `0 <= score <= 100`（結果是 False），加上 `not` 就變成 True，被攔下來了。

**原則：寫檢查條件時，用「確認它是好的」，而不是「確認它不是壞的」。**壞的情況你可能想不完，好的情況比較好定義。

@section 走一遍：成績統計函式
把上面的觀念組合起來，看一個完整的推演。有四位學生的成績：
- Alice：`[80, 95, 100]`
- Bob：`[]`（新生，還沒考試）
- Charlie：`[0, 60]`
- David：`[85, True, '90', float('nan')]`（從外部檔案匯入的髒資料）

呼叫 `calculate_stats(scores)` 時：

**Bob 的 `[]`：**第一步檢查發現是空清單，立刻回傳 `None`，不做除法，避免程式當掉。

**Alice 的 `[80, 95, 100]`：**逐一檢查每個值：不是布林值、是數字、在 0 到 100 之間，全部通過。計算總和 275，除以 3，回傳一個**新的字典**：
```
{"count": 3, "mean": 91.67, "min": 80, "max": 100}
```

**Charlie 的 `[0, 60]`：**正常算出平均 30.0。注意：Charlie 有考零分，結果是有意義的數字；Bob 沒考試，結果是 `None`。兩者被清楚區分了。

**David：**檢查到第二個值 `True` 時，被布林值檢查攔下，拋出 `ValueError`。外層負責批次匯入的程式**捕捉**這個錯誤，把 David 的資料放到一個「**待處理錯誤區**」，等人工檢查，而**不會**讓錯誤的數值混進全班的平均裡。

這個「錯誤資料另外放、不影響正常資料」的做法，在系統架構中叫做「**死信佇列**」（Dead-Letter Queue），第 76 課會再提到。

@section CRUD：資料操作的四個基本動作
幾乎所有管理資料的系統，都離不開四個基本動作，合稱 **CRUD**：
- **C**reate（新增）：新增一位學生；
- **R**ead（讀取）：查詢某位學生的資料；
- **U**pdate（更新）：修改學生的成績；
- **D**elete（刪除）：刪除一位學生。

**原則：每個動作寫成一個獨立的函式，而且不夾帶 `print()` 或 `input()`。**
```
def create_student(roster, student_id, name): ...
def get_student(roster, student_id): ...
def update_score(roster, student_id, score): ...
def delete_student(roster, student_id): ...
```
這樣，現在的命令列介面可以呼叫它們，之後第 54 課的網站 API 也可以呼叫**同一套**函式。

**清單還是字典？**
選擇用什麼**資料結構**來存資料，會影響效率：
- **清單**（list）：有順序，適合「全部走過一遍」或「排序」。但要找某位學生，最壞的情況要從頭找到尾。資料有 n 筆，就要找 n 次，記作 $O(n)$；
- **字典**（dict）：用唯一的編號（例如學號）當「鑰匙」（key），**不管有多少筆，查詢、修改、刪除平均都只要一步**，記作 $O(1)$。

**比喻：**清單像一疊沒有索引的考卷，要找某人的，只能一張一張翻；字典像按學號排好的檔案櫃，直接拉開對應的抽屜。

這個 $O(\cdot)$ 的寫法叫做「**時間複雜度**」，用來描述資料量變大時，執行時間怎麼增長。第 58 課的資料庫索引會再遇到它。

@section 程式碼審查中最常見的四個錯誤
**錯誤一：用回傳錯誤文字代替拋出例外。**
```
return "錯誤：分數不合法"
```
呼叫的人每次都要檢查「回傳的是文字還是數字？」，一旦忘記，就會拿文字去做數學運算而當掉。正確做法是 `raise ValueError(...)`，下一課會詳細介紹例外。

**錯誤二：計算函式裡順便 `print()`。**
測試難寫，而且在網站伺服器裡，大量印出的文字沒人看，還拖慢速度。

**錯誤三：可變的預設參數。**
```
def add_student(student, roster=[]):
    roster.append(student)
    return roster
```
這是 Python 最著名的陷阱之一。預設值 `[]` **只在函式定義時建立一次**，之後所有沒傳 `roster` 的呼叫，都**共用同一個清單**！第一次呼叫加了 Alice，第二次呼叫（以為是新的空清單）加了 Bob，結果回傳 `[Alice, Bob]`。

在網站服務中，這可能造成**甲使用者看到乙使用者的資料**，是嚴重的資安事故。正確做法：
```
def add_student(student, roster=None):
    if roster is None:
        roster = []
    ...
```

**錯誤四：一邊走訪清單，一邊刪除元素。**
```
for x in items:
    if x < 0:
        items.remove(x)
```
刪掉一個元素後，後面的元素位置往前移，迴圈會**跳過**下一個元素。正確做法是產生新清單：
```
items = [x for x in items if x >= 0]
```
這種 `[... for ... if ...]` 的寫法叫做「**串列推導式**」（List Comprehension），是 Python 很常用的語法。

@section 動動腦：找出問題
**題一**：為什麼空清單的平均應該回傳 `None`，而不是 0？
→ 0 是有效的真實分數，回傳 `None` 才能區分「沒有資料」和「平均為零」。

**題二**：為什麼檢查分數時要先寫 `isinstance(score, bool)`？
→ 因為在 Python 中 `True` 是整數的一種，等於 1，會被誤當成合法分數。

**題三**：`if score < 0 or score > 100: raise ...` 有什麼漏洞？
→ NaN 和任何數字比較都是 False，會直接通過檢查。應改成 `if not (0 <= score <= 100)`。

**題四**：`def f(items=[])` 有什麼危險？
→ 預設清單只建立一次，所有呼叫共用，可能造成不同使用者的資料互相混入。應改用 `None` 當預設值。

@section 本課重點整理
- **拆開大腳本**：核心邏輯和輸入輸出分開，才能測試、除錯、重用。
- **純函式**：結果只取決於輸入、沒有副作用。核心邏輯寫成純函式，副作用放在外圍。
- **參照**：Python 的變數是標籤，清單和字典傳進函式後是同一份。不要就地修改，用 `sorted()` 或推導式產生新的。
- **`None` vs. 0**：「沒有資料」用 `None`，「資料有錯」拋出例外，讓每個回傳值只有一種意思。
- **驗證陷阱**：先排除布林值；用 `not (low <= x <= high)` 同時擋住越界和 NaN。
- **CRUD 分離**：新增、讀取、更新、刪除各自獨立，不夾帶輸入輸出。用學號查詢時字典比清單快得多。
- **四個常見錯誤**：回傳錯誤文字、計算函式裡 print、可變預設參數、邊走訪邊刪除。

@term 函式
有名字、可重複呼叫的一段程式，接收參數並回傳結果（Function）。
@term 參數
呼叫函式時傳進去的輸入值（Parameter / Argument）。
@term 純函式
結果只取決於輸入、而且沒有任何副作用的函式（Pure Function）。
@term 副作用
函式除了回傳結果之外，對外部造成的改變，例如印出、寫檔、修改資料。
@term 輸入輸出契約
說明函式接受什麼輸入、回傳什麼、遇到錯誤怎麼處理的約定。
@term 參照
變數指向記憶體中某個物件的關係；多個變數可指向同一個物件（Reference）。
@term 可變物件
建立後內容還能被修改的資料，例如 list、dict（Mutable Object）。
@term 就地修改
直接改動原本的資料，而不是產生新的一份（In-place Mutation）。
@term None
Python 中表示「沒有值」的特殊值。
@term NaN
Not a Number，浮點數中表示「不是有效數字」的特殊值，和任何值比較都是 False。
@term ValueError
Python 內建的例外類型，表示傳入的值不合法。
@term CRUD
新增、讀取、更新、刪除四種基本資料操作的合稱。
@term 時間複雜度
描述資料量增加時執行時間如何增長的方式，例如 O(n)、O(1)。
@term 串列推導式
用 [x for x in items if 條件] 產生新清單的 Python 語法（List Comprehension）。
@term 死信佇列
存放無法正常處理的資料或訊息、等待人工檢查的地方（Dead-Letter Queue）。
