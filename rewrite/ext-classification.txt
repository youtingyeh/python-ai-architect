@section 開場：準確率 95% 的模型，可能一個都抓不到
工廠請你做一個 AI，從晶圓照片中找出有瑕疵的晶片。一個月後，你驕傲地報告：「模型準確率 95%！」

主管問了一句：「那它抓到幾個瑕疵品？」

你一查，答案是：**零個**。

怎麼可能？因為 100 片晶圓裡，本來就只有 5 片有瑕疵。你的模型學到了一個偷懶的策略：**不管看到什麼，一律說「正常」**。這樣 95 片正常的全部猜對，5 片瑕疵的全部猜錯，準確率剛好 95%。在簡報上很好看，在產線上毫無用處。

這一課要學的，就是分類模型（第 1 課說的「貼標籤」）該怎麼正確地**輸出答案**、怎麼**計算錯誤**，以及最重要的：**怎麼評估它到底好不好**。我們會依序認識：

- 模型怎麼說出「這張圖 80% 是刮痕」？（Softmax）
- 分類問題的損失要怎麼算？（交叉熵）
- 為什麼準確率會騙人？（正確率悖論）
- 該看哪些指標才不會被騙？（混淆矩陣、精確率、召回率、F1）
- 怎麼依照錯誤的代價調整模型的「警戒程度」？（決策門檻）

這一課的內容，從醫療篩檢、詐騙偵測到垃圾信過濾都用得到，就算你永遠不寫程式，學會這套看指標的方法，也能幫你看穿很多 AI 產品的誇大宣傳。

@section 從「分數」到「機率」：Softmax 怎麼運作
在回歸任務（猜數字）裡，模型直接輸出一個數字就好，例如房價 1,280 萬。但在分類任務裡，我們希望模型說的是：「這張照片是**正常**的機率 10%、是**刮痕**的機率 70%、是**裂紋**的機率 20%。」

一組合格的機率要滿足兩個條件：
1. 每個機率都不能是負的（$\hat{p}_k \ge 0$）；
2. 所有類別的機率加起來剛好是 1（$\sum_{k=1}^K \hat{p}_k = 1$），也就是 100%。

（這裡 $K$ 是類別數，例子中 $K = 3$；$\hat{p}_k$ 是模型猜「第 k 類」的機率。）

問題是，神經網路最後一層算出來的東西，只是一組沒有規則的「原始分數」，可正可負、可大可小，例如 `[1.0, 3.0, 2.0]`，或 `[-5, 0.2, 7]`。這組原始分數有個專門名稱叫做 **Logits**（念作「羅吉茨」）。我們需要一個方法，把任意的分數轉換成合格的機率。

這個方法就是 **Softmax 函式**：

$$\hat{p}_i = \frac{\exp(z_i)}{\sum_{j=1}^K \exp(z_j)}$$

看起來複雜，其實只有兩個動作：
1. **每個分數都取「指數」**：$\exp(z)$ 就是 $e^z$（$e$ 是一個約等於 2.718 的數學常數）。指數的特性是**結果永遠是正數**，而且分數越高、結果放大得越厲害。
2. **除以全部的總和**：讓所有結果加起來等於 1。

**實際算一次。**原始分數 $z = [1.0, 3.0, 2.0]$（正常、刮痕、裂紋）：
- $e^{1} \approx 2.72$，$e^{3} \approx 20.09$，$e^{2} \approx 7.39$
- 總和 $\approx 30.20$
- 機率：正常 $2.72 / 30.20 \approx 9\%$、刮痕 $20.09 / 30.20 \approx 67\%$、裂紋 $7.39 / 30.20 \approx 24\%$

模型的結論：這張最可能是刮痕（67%）。

為什麼要先取指數，而不是直接把分數除以總和？第一，分數可能是負的，直接除會出現負機率；指數保證全部變正。第二，指數會**拉開差距**：原始分數 3 只比 2 多 1，但機率 67% 比 24% 多了將近三倍。這讓模型「傾向」最高分的那個類別，但又不像「最高分拿 100%、其他全 0」那麼絕對——所以叫 **Soft**max（溫和版的取最大值）。而且它處處平滑，方便第 4 課的梯度計算。

**一個工程小技巧：先減最大值。**如果某個分數是 100，$e^{100}$ 是一個 44 位數的天文數字，超過電腦常用的單精度浮點數（FP32）能表示的上限（大約 $e^{88.7}$），會直接變成 `inf`（無限大），接著算出一堆錯誤。這叫做**數值溢位**（Overflow）。

解法很巧妙：計算前，先把每個分數都減掉其中的最大值 $M$：

$$\hat{p}_i = \frac{\exp(z_i - M)}{\sum_{j=1}^K \exp(z_j - M)}$$

數學上，這等於分子分母同時乘上 $e^{-M}$，結果完全不變；但減完之後最大的分數變成 0，$e^0 = 1$，再也不會溢位。所有正式的深度學習工具都內建了這個技巧。

@section 分類的損失：交叉熵——「你對正確答案有多沒信心」
有了機率，下一步是設計損失函數：模型猜得多爛？

我們關心的其實只有一件事：**模型給「正確答案」的機率有多高**。如果這張照片真的是刮痕，我們希望模型給刮痕的機率越接近 1 越好。

分類任務的標準損失叫做**交叉熵**（Cross-Entropy Loss），公式是：

$$L_{\text{CE}} = -\log(\hat{p}_y)$$

$\hat{p}_y$ 是模型給「正確類別 y」的機率，$\log$ 是對數（自然對數）。前面加個負號，是因為機率小於 1 時對數是負的，加負號讓損失變成正數。（完整公式寫成 $-\sum_{k=1}^K y_k \log(\hat{p}_k)$，其中正確答案用「只有正確那一格是 1、其他都是 0」的向量表示，叫做 **One-Hot** 編碼。因為只有正確那格是 1，加總後就只剩 $-\log(\hat{p}_y)$ 這一項。）這個損失也叫做「**負對數概似**」（Negative Log-Likelihood）。

**用數字感受它的脾氣：**

- 模型對正確答案給 100% 信心：$-\log(1) = 0$。完美，零損失。
- 給 50%：$-\log(0.5) \approx 0.69$。
- 給 10%：$-\log(0.1) \approx 2.30$。
- 給 0.1%（幾乎篤定猜錯）：$-\log(0.001) \approx 6.91$。
- 機率越接近 0，損失越趨近無限大。

所以交叉熵的性格是：**稍微沒把握，罰一點；信心滿滿地答錯，重罰。**這很像一位嚴格但公平的老師：猜錯可以原諒，但「篤定地說錯」要付出很大代價。這會逼模型對自己的判斷保持誠實。

**為什麼分類不用第 5 課的均方誤差（MSE）？**

因為交叉熵和 Softmax 搭配時，梯度會變得非常漂亮。損失對每個原始分數 $z_i$ 的梯度剛好是：

$$\frac{\partial L_{\text{CE}}}{\partial z_i} = \hat{p}_i - y_i$$

也就是「**模型給的機率減掉正確答案**」。錯多少，梯度就多大，簡單直接。

如果改用 MSE，在模型「錯得很離譜」的時候，梯度反而會變得非常小——就像一個錯得最嚴重的學生，老師給的訂正提示卻最模糊。結果模型卡住學不動。這個現象叫做「**梯度消失**」（Gradient Vanishing），之後的課會常常遇到。交叉熵避開了這個問題。

**PyTorch 實務提醒**：`nn.CrossEntropyLoss()` 內部已經自動包含了 Softmax（而且是數值穩定的版本）。所以要直接把原始分數 Logits 丟給它，**千萬不要自己先做一次 Softmax**，否則等於做了兩次，結果會錯。這是初學者非常常犯的錯誤。

@section 正確率悖論：95% 的零分模型
訓練完成後，最直覺的評估方式是**準確率**（Accuracy，也常譯作正確率）：

$$\text{Accuracy} = \frac{\text{猜對的數量}}{\text{總數量}}$$

但在真實世界，很多最有價值的 AI 任務都有一個共同特徵：**我們要找的東西非常稀少**。信用卡盜刷可能千分之一、罕見癌症可能萬分之一、機台異常、資安入侵也都很少見。這種「一個類別多、另一個類別少」的情況，叫做**類別不平衡**（Class Imbalance）。

回到開場的例子：100 片晶圓，95 片正常、5 片瑕疵。我寫一行完全不需要 AI 的程式：

```
def predict(x): return 0   # 0 代表正常
```

不管輸入什麼，一律回答「正常」。準確率是多少？95 片正常全部猜對，5 片瑕疵全部猜錯：$\frac{95}{100} = 95\%$。

**95% 的準確率，抓到 0 個瑕疵品。**這種「準確率很高，卻完全沒用」的現象，叫做**正確率悖論**（Accuracy Paradox）。「悖論」是指看似合理、卻導出矛盾結論的情況。

如果是盜刷比例千分之一的資料，「一律說正常」的準確率高達 99.9%。所以下次有人宣傳「我們的 AI 偵測準確率 99.9%」，你應該立刻追問：「那本來的異常比例是多少？你抓到了幾成？」

這就是為什麼我們需要更細的指標。

@section 混淆矩陣：把對錯拆成四格
要看穿正確率悖論，第一步是把模型所有的判斷結果，依照「**真實情況**」和「**模型判斷**」拆成四格，這張表叫做**混淆矩陣**（Confusion Matrix）——意思是「看模型在哪裡搞混了」。

在異常偵測裡，我們把「要找的東西」（瑕疵、盜刷、患病）叫做「**正例**」（Positive），其他叫做「**負例**」（Negative）。注意：這裡的「正」不代表好事，只代表「我們要抓的那一類」。

四格分別是：

1. **真正例 TP（True Positive）**：真的是瑕疵，模型也說是瑕疵。→ **抓對了**。
2. **假正例 FP（False Positive）**：其實是正常，模型卻說是瑕疵。→ **誤報**，狼來了。（統計學又叫「第一型錯誤」。）
3. **假負例 FN（False Negative）**：真的是瑕疵，模型卻說正常。→ **漏報**，放虎歸山。（統計學又叫「第二型錯誤」。）
4. **真負例 TN（True Negative）**：正常的，模型也說正常。→ **放行正確**。

命名的記法：後面的 Positive / Negative 是「**模型說了什麼**」，前面的 True / False 是「**模型說得對不對**」。所以 False Positive 就是「模型說是正例（Positive），但說錯了（False）」。

**套用到例子。**我們訓練了一個真正有用的模型，結果是：
- 5 片真正瑕疵中，抓到 4 片（TP = 4），漏掉 1 片（FN = 1）。
- 95 片正常品中，93 片正確放行（TN = 93），2 片被誤報成瑕疵（FP = 2）。

這個模型的準確率是 $\frac{4 + 93}{100} = 97\%$，只比偷懶模型的 95% 高一點點。但從混淆矩陣看，兩者天差地遠：一個抓到 4 個瑕疵，一個抓到 0 個。有了這四個數字，我們才能從兩個完全不同的角度來評價模型。

@section 精確率與召回率：「喊得準不準」與「抓得全不全」
根據混淆矩陣，分類評估最重要的兩個指標是：

**① 精確率（Precision，也叫查準率）：模型喊「有問題！」的時候，有幾成是真的？**

$$\text{Precision} = \frac{\text{TP}}{\text{TP} + \text{FP}}$$

分母 $\text{TP} + \text{FP}$ 是「模型總共喊了幾次警報」。代入例子：模型喊了 $4 + 2 = 6$ 次，其中 4 次是真的：

$$\text{Precision} = \frac{4}{6} \approx 66.7\%$$

精確率低，代表假警報很多。如果每次警報都要派工程師去檢查，假警報太多，大家就會開始不相信警報——這叫做「**警報疲勞**」，就像放羊的孩子喊太多次狼來了，最後真的狼來了也沒人理。

**② 召回率（Recall，也叫查全率、敏感度）：所有真正有問題的，模型抓出了幾成？**

$$\text{Recall} = \frac{\text{TP}}{\text{TP} + \text{FN}}$$

分母 $\text{TP} + \text{FN}$ 是「真正有問題的總數」。代入例子：真正瑕疵有 $4 + 1 = 5$ 片，抓到 4 片：

$$\text{Recall} = \frac{4}{5} = 80\%$$

而那個「一律說正常」的偷懶模型，召回率是 $\frac{0}{5} = 0\%$。準確率只差 2%，召回率卻是 80% 對 0%，高下立判。

**用捕魚來比喻：**你在湖裡撒網想抓鯉魚。
- **精確率**：網子拉上來的魚裡，有多少是鯉魚（而不是雜魚）。
- **召回率**：湖裡所有的鯉魚，有多少被你抓上來了。
網子撒得越大，召回率越高，但會撈到更多雜魚，精確率下降；網子撒得越小越精準，精確率高，但會漏掉很多鯉魚。

**③ F1 分數：兩者的綜合成績。**

如果只能看一個數字，常用 F1 分數，它是精確率和召回率的「**調和平均數**」：

$$F_1 = \frac{2 \cdot \text{Precision} \cdot \text{Recall}}{\text{Precision} + \text{Recall}} = \frac{2\,\text{TP}}{2\,\text{TP} + \text{FP} + \text{FN}}$$

代入例子：$\frac{2 \times 4}{2 \times 4 + 2 + 1} = \frac{8}{11} \approx 72.7\%$。

為什麼用調和平均，而不是一般平均？因為調和平均會**被比較低的那個拖下來**。如果精確率 100%、召回率只有 2%，一般平均是 51%，看起來還行；但 F1 只有大約 4%，誠實地反映出「這個模型其實很爛」。它逼你兩個都要顧好。

**寫程式時的小陷阱：除以零。**如果模型非常保守，一個正例都沒預測（TP + FP = 0），精確率的分母就是 0。評估程式要明確處理這種情況（通常約定回傳 0 並發出警告），不然程式會當掉或算出 `NaN`。

@section 調整警戒程度：決策門檻與 Precision-Recall 的翹翹板
這是本課最實用的一節。

分類模型其實**不會**直接說「是」或「不是」。它輸出的是一個 0 到 1 之間的機率，例如「這片晶圓有瑕疵的機率是 0.37」。是我們**另外設定了一條線**，叫做**決策門檻**（Threshold，常用 $\tau$ 表示），機率超過門檻才判定為「有瑕疵」。預設的門檻通常是 0.5。

這代表精確率和召回率是一對**可以用門檻調整的翹翹板**：

**把門檻調低**（例如從 0.5 降到 0.15）＝「寧可錯殺，不可放過」：
- 更多可疑的樣本被判定為有問題
- 漏報（FN）減少 → **召回率上升**
- 但誤報（FP）增加 → **精確率下降**
- 適合：**漏掉代價極高**的場景。癌症初步篩檢、飛安重大瑕疵、核電廠預警。

**把門檻調高**（例如升到 0.9）＝「證據確鑿才出手」：
- 只有非常有把握的才判定為有問題
- 誤報減少 → **精確率上升**
- 但漏報增加 → **召回率下降**
- 適合：**誤報代價極高**的場景。自動刪除垃圾信（把重要信件誤刪很糟）、自動封鎖 VIP 客戶的帳號。

**一個完整的例子：罕見重病篩檢。**漏診一位真正的病人，會延誤黃金治療期，後果極嚴重；把健康的人誤判為疑似陽性，只要再抽一次血就能排除。代價非常不對稱。所以應該把門檻**調低**，例如 0.15，優先把召回率拉高、讓漏診降到最少；多出來的誤報，交給後續的精密檢查去過濾。

這正是第 1 課「錯誤的代價不對稱」的延伸：**門檻不是技術問題，而是商業和倫理問題。**它應該由「錯一次要付出什麼代價」來決定，而不是永遠用預設的 0.5。

**怎麼看整體表現？PR 曲線。**既然每個門檻都會得到一組不同的精確率和召回率，我們可以把所有門檻的結果畫成一條曲線，橫軸是召回率、縱軸是精確率，叫做 **PR 曲線**（Precision-Recall Curve）。曲線下的面積叫 **PR-AUC**，越接近 1 代表模型越好（不管門檻設在哪裡，都能同時保持不錯的精確率和召回率）。

你可能也會聽到另一種常見指標 **ROC-AUC**（上一課提過）。在類別極度不平衡時，ROC-AUC 容易看起來虛高——因為它的計算裡包含了數量龐大的「真負例」（那 95% 的正常品），大量正確放行的正常品會把分數撐得很好看。PR-AUC 則專注在「我們要找的那一小撮」，所以更能反映模型抓稀有事件的真實功力。

@section 跟著算一次：同一個模型，三種門檻
我們用 10 片晶圓，看門檻怎麼改變一切。模型對每片給出的瑕疵機率（由高到低）和真實情況如下：

- 0.95（瑕疵）、0.80（瑕疵）、0.62（正常）、0.55（瑕疵）、0.40（正常）、0.30（瑕疵）、0.20（正常）、0.10（正常）、0.05（正常）、0.02（正常）

真正的瑕疵共 4 片。

**門檻 0.9**（非常保守）：只有 0.95 被判為瑕疵。
- TP = 1，FP = 0，FN = 3
- 精確率 = 1/1 = 100%，召回率 = 1/4 = 25%
- 喊一次中一次，但漏掉四分之三。

**門檻 0.5**（預設）：0.95、0.80、0.62、0.55 被判為瑕疵。
- TP = 3（0.95、0.80、0.55），FP = 1（0.62），FN = 1（0.30）
- 精確率 = 3/4 = 75%，召回率 = 3/4 = 75%

**門檻 0.25**（寧可錯殺）：0.95 到 0.30 共 6 片被判為瑕疵。
- TP = 4，FP = 2（0.62、0.40），FN = 0
- 精確率 = 4/6 ≈ 67%，召回率 = 4/4 = 100%
- 一片都沒漏，代價是多檢查兩片正常品。

同一個模型、同樣的機率，只是換了門檻，結論從「漏掉 75%」變成「一個都沒漏」。所以當有人只告訴你「模型精確率 100%」時，記得問：「召回率呢？門檻設在哪裡？」

@section 本課重點整理
- **Softmax** 把原始分數（Logits）轉成機率：先取指數讓全部變正、再除以總和讓加起來等於 1。實作時先減最大值，避免溢位。
- **交叉熵** $-\log(\hat{p}_y)$：只看模型給正確答案的機率，信心滿滿地答錯會被重罰。搭配 Softmax 時梯度就是「機率減答案」，不會像 MSE 那樣梯度消失。PyTorch 的 `CrossEntropyLoss` 要直接餵 Logits。
- **正確率悖論**：資料不平衡時，「一律猜多數」就能拿到超高準確率，卻一個都抓不到。
- **混淆矩陣四格**：TP（抓對）、FP（誤報）、FN（漏報）、TN（放行正確）。
- **精確率**＝喊警報時有幾成是真的；**召回率**＝真正的問題抓出了幾成；**F1** 是兩者的調和平均，會被低的那個拖下來。
- **門檻是翹翹板**：調低提高召回率（適合漏判代價高）、調高提高精確率（適合誤報代價高）。門檻應由錯誤代價決定，不是永遠 0.5。
- 類別不平衡時，**PR-AUC** 比 ROC-AUC 更誠實。

下一課，我們要把前面學的所有零件組裝起來：張量、梯度、損失函數、Softmax，變成一個真正的神經網路，並且搞清楚每一次訓練更新，電腦到底依序做了哪些事。

@term Softmax
把一組任意分數轉換成「全部為正、加總為 1」的機率的函式。先取指數、再除以總和。
@term Logits
神經網路最後一層輸出、還沒轉成機率的原始分數，可正可負。
@term 交叉熵
分類任務最常用的損失（Cross-Entropy），等於 −log(模型給正確答案的機率)。信心滿滿地答錯會被重罰。
@term One-Hot
只有正確類別那一格是 1、其他都是 0 的表示法。例如三類中的第二類寫成 [0, 1, 0]。
@term 數值溢位
數字大到超過電腦能表示的上限，變成 inf（無限大）的情況（Overflow）。
@term 梯度消失
梯度變得非常小、模型幾乎學不動的現象（Gradient Vanishing），常在錯誤很大時反而發生。
@term 準確率
猜對的數量除以總數量（Accuracy）。資料不平衡時容易誤導。
@term 類別不平衡
某一類資料遠多於另一類的情況（Class Imbalance），例如盜刷只占千分之一。
@term 正確率悖論
資料不平衡時，「一律猜多數類」就能得到很高的準確率，卻完全抓不到少數類的現象。
@term 混淆矩陣
把分類結果依「真實情況 × 模型判斷」拆成 TP、FP、FN、TN 四格的表（Confusion Matrix）。
@term 精確率
模型喊「是」的時候，有幾成真的是（Precision）。低精確率代表假警報多。
@term 召回率
所有真正的「是」之中，模型抓到了幾成（Recall）。低召回率代表漏掉很多。
@term F1 分數
精確率和召回率的調和平均數，會被兩者中較低的那個拖下來，逼模型兩邊都顧好。
@term 決策門檻
機率超過多少才判定為「是」的分界線（Threshold）。調低會抓得更全，調高會喊得更準。
@term PR 曲線
把不同門檻下的精確率和召回率畫成的曲線，曲線下面積（PR-AUC）越接近 1 越好。
@term 正例
分類中「我們要找的那一類」（Positive），例如瑕疵、盜刷、患病，不代表好事。
