@section 開場：兩個熱門話題的交會
AI 和量子計算，是近年最常出現在科技新聞上的兩個詞，所以「量子 AI」聽起來特別厲害。但這個詞其實被用來指好幾件**很不一樣**的事情，有些已經有實際成果，有些還停留在研究階段，有些則只是行銷用語。

這一課要幫你把「量子與 AI」的關係拆成三個方向，分別看清楚每個方向目前真正的進展：

1. **AI 幫助量子計算**：用 AI 修正量子電腦的錯誤、設計量子演算法。這是**目前成果最具體**的方向；
2. **量子計算幫助 AI**：也就是「量子機器學習」，希望用量子電腦讓 AI 更強。這個方向**仍在研究階段**，尚未證明在實際問題上有優勢；
3. **量子與 AI 的混合系統**：把量子電腦、GPU 和 AI 整合在同一個計算環境中，各自處理擅長的部分。

讀完這一課，你應該能分辨一則「量子 AI」新聞說的是哪一個方向，以及它大概發展到哪個階段。最後也會介紹，如果你想親手試試量子機器學習，有哪些免費的學習資源。

@section 方向一：AI 幫量子電腦修正錯誤
第 85 課說過，量子位元非常容易出錯，必須用許多物理量子位元組成一個邏輯量子位元，並且不斷檢查和修正錯誤。這裡有一個關鍵的角色叫做**解碼器**（decoder）。

**解碼器在做什麼？**
量子錯誤更正的過程，大致是這樣：系統會定期對一群量子位元做「一致性檢查」，檢查結果會顯示「這附近好像出了錯」，但**不會直接告訴你是哪個量子位元、出了什麼錯**。解碼器的工作，就是根據這些間接的檢查結果，**推論出實際發生了什麼錯誤**，再決定怎麼修正。

這有點像醫生看檢驗報告：報告上只有各種指數，醫生要根據這些數字推斷病因。而且量子電腦的「病情」變化極快，解碼器必須**非常快**地做出判斷。

**AlphaQubit：用 Transformer 當解碼器**
2024 年 11 月，Google DeepMind 和 Google Quantum AI 在《自然》（Nature）期刊發表了 **AlphaQubit**。它是一個以神經網路為基礎的解碼器，使用的正是第 14、15 課學過的 **Transformer** 架構，也就是許多大型語言模型的基礎。

它的訓練方式也很值得一看，和第 41 課談的「先預訓練，再微調」非常相似：
1. 先用量子模擬器產生**數億筆**模擬的錯誤資料來訓練，讓模型學會一般性的解碼規則；
2. 再用真實量子處理器上收集的**數千筆**實驗資料微調，讓模型適應真實硬體的雜訊特性。

結果顯示，AlphaQubit 在 Google 的 Sycamore 處理器實驗中，比當時的主流解碼方法更準確。

**還沒解決的問題：速度**
不過，第一版的 AlphaQubit 有一個限制：太慢了。超導量子電腦每一輪錯誤檢查大約只有一微秒（百萬分之一秒），解碼器必須在這麼短的時間內完成判斷，否則待處理的資料會越積越多，錯誤更正就無法運作。

2025 年 12 月，同一個團隊在 arXiv 發表了 **AlphaQubit 2** 的論文，目標是同時做到**準確、快速、可擴充**。論文報告它在兩種主要的錯誤更正碼（表面碼與色碼）上，於大規模和真實雜訊條件下都達到接近最佳的錯誤率。這類研究還在快速發展中，但它清楚地顯示：**AI 已經成為打造可靠量子電腦的重要工具之一**。

@section 方向一（續）：AI 幫忙設計量子演算法
量子演算法非常難設計。它違反直覺，而且在目前充滿雜訊的硬體上，電路越長、閘越多，出錯的機會就越高。所以研究者開始嘗試：**讓 AI 來設計，或至少幫忙優化量子電路**。

**AlphaTensor-Quantum：減少昂貴的操作**
2024 年，Google DeepMind 與 Quantinuum 等團隊合作，發表了 **AlphaTensor-Quantum**，專門用來減少量子電路中一種叫做「T 閘」的操作數量。在未來的容錯量子電腦上，T 閘是最昂貴、最耗資源的操作之一，減少它的數量就能大幅降低執行成本。

**用 LLM Agent 演化出新的演算法**
更新的研究，則直接使用大型語言模型。Quantinuum 與新創公司 Hiverge 合作，使用一個叫做 **Hive** 的平台：它是**一群 LLM Agent 共同編輯同一份程式碼**，用類似生物演化的方式，不斷產生、評估、篩選、組合各種演算法的變體。

研究者只提供一個簡單的量子化學演算法草稿和要分析的分子，Hive 就演化出了新的演算法。根據報導，這些演算法在 LiH、H₂O 等分子的基態能量計算上達到了化學精度，而且所需的電路深度和閘數量，比人類設計的方法少了一到兩個數量級。研究團隊也在 Quantinuum 的 H2 量子電腦上實際執行了這些電路。

2026 年 3 月，Quantinuum 宣布與 Hiverge、AWS 和 NVIDIA 進一步合作，把這個方法延伸到組合最佳化問題。

**這和你學過的內容有什麼關係？**
Hive 的運作方式，正是第 33 課的 Agent 行動迴圈、第 39 課的 Agent Harness（外部驗證），再加上第 44 課提到的「自我改進」概念的組合：
- LLM 負責**提出**新的程式碼變體；
- 外部的模擬器和量子電腦負責**客觀地驗證**每個變體的效果；
- 表現好的變體被保留下來，繼續演化。

**AI 提出、外部系統驗證**，這個模式在量子領域特別有效，因為量子演算法的效果可以被精確地計算和衡量。這也呼應了整個課程反覆強調的觀念：AI 的產出需要客觀的驗證機制。

@section 方向二：量子電腦幫助 AI
**量子機器學習是什麼？**
**量子機器學習**（Quantum Machine Learning，QML）的想法是：用量子電路來取代或輔助機器學習模型中的某些部分。最常見的形式是**參數化量子電路**（也叫變分量子電路）：

1. 把資料**編碼**進量子位元的狀態；
2. 讓量子位元經過一連串帶有**可調參數**的量子閘（類似神經網路的權重）；
3. **測量**結果，計算損失；
4. 用一般電腦上的最佳化方法**調整參數**，再重複這個過程。

你會發現，這個流程和第 8 課的 PyTorch 訓練迴圈非常像。差別只在於，模型的「中間層」換成了量子電路。這種「量子電路加上古典最佳化器」的組合，叫做**混合量子—古典模型**。

**目前的現實：還沒有證明的實用優勢**
量子機器學習是一個很活躍的研究領域，但對於**一般的機器學習任務**（影像辨識、文字分類、大型語言模型），目前**還沒有證據顯示量子電腦能帶來實際的優勢**。主要的困難包括：

- **資料載入的瓶頸**：把大量的古典資料編碼進量子狀態，本身就可能很耗時，可能抵消量子計算帶來的加速；
- **貧瘠高原**（barren plateau）：在很多量子電路中，隨著量子位元數增加，梯度會變得幾乎為零，模型很難訓練。這有點像深度神經網路中的梯度消失問題；
- **硬體的雜訊與規模**：目前的量子電腦量子位元數有限、雜訊很大，能執行的電路很小；
- **古典方法也在進步**：很多一開始宣稱有「量子優勢」的方法，後來被發現用設計良好的古典演算法也能達到類似效果。

**比較有希望的方向**
研究者認為，量子機器學習比較可能在**資料本身就是量子性質**的問題上展現優勢，例如分析量子實驗的資料、模擬分子和材料。也就是說，量子電腦最可能的貢獻，是幫助**科學領域的 AI**，而不是讓聊天機器人變得更聰明。

@section 方向三：量子與 AI 的混合計算
第三個方向比較偏向工程和產業：把量子電腦、GPU 叢集和 AI 整合在同一個計算環境中，讓每種計算資源處理自己擅長的部分。

**為什麼要整合？**
目前和可見的未來，量子電腦都需要和一般電腦緊密配合：
- 錯誤更正的解碼器（方向一）需要在一般電腦或 GPU 上即時執行；
- 混合量子—古典模型（方向二）需要一般電腦負責最佳化；
- 大部分的資料前處理、結果分析，仍然在一般電腦上完成。

**產業的動態**
2026 年，陸續有企業宣布這類合作。例如 Oxford Quantum Circuits、摩根大通和 AMD 宣布在倫敦設立一個「量子—AI 資料中心」，把量子處理器和高效能運算硬體整合在一起；Quantinuum、NVIDIA 和輝瑞也宣布驗證了一個結合生成式 AI 與量子計算的藥物研發框架。

**怎麼看待這些新聞？**
這類合作宣布，代表產業正在為量子計算的實用化做準備，但它們多半是**基礎建設與早期探索**，而不是已經產生商業效益的產品。閱讀時可以用第 85 課的方法：問清楚它具體解決了什麼問題、和最好的古典方法相比如何、結果是否經過獨立驗證。

**對軟體工程師的意義**
如果量子計算真的實用化，它很可能會以**雲端服務**的形式出現：你透過 API 把特定的計算任務送到量子處理器上，就像現在呼叫 LLM API 一樣。到那時候，本課程學過的工程能力，例如 API 設計、非同步佇列、逾時與重試、成本控制、結果驗證，全部都會用得上。

@section 實作與學習資源：親手試試量子電路
**免費的工具**
如果你想親手試試，有兩個主流的開源 Python 工具都可以免費使用：
- **Qiskit**：IBM 開發，可以在電腦上模擬量子電路，也可以申請在 IBM 的真實量子電腦上執行；
- **PennyLane**：Xanadu 開發，特別適合量子機器學習。它的設計理念是「**可微分的量子程式設計**」，能和 PyTorch 等深度學習框架整合，計算量子電路的梯度。

**推薦的免費課程**
- **IBM 的「Quantum Machine Learning with Qiskit」**：約 10 小時的中級課程，介紹參數化量子電路、電路的訓練方法，並應用在基本問題上。建議先具備大學程度的線性代數與微積分、Python 基礎，以及量子計算的基本概念；
- **openHPI 的「Quantum Machine Learning (with IBM Quantum)」**：由 IBM 研究人員授課，會同時用古典模型和量子模型解決同樣的問題，也會討論量子機器學習的潛力與瓶頸；
- **PennyLane 官網的示範（Demos）**：有大量附程式碼的教學範例，從基礎到進階都有；
- **GitHub 上的開源教材**：例如「Learn-Quantum-Machine-Learning」，從數學基礎開始，每個主題都有可以在 Colab 上直接執行的筆記本。

**建議的學習順序**
1. 先把線性代數的基礎（向量、矩陣乘法、複數）複習好，這是量子計算的語言；
2. 用本課和第 85 課的 Python 範例，理解量子位元、疊加和干涉；
3. 學習 Qiskit 或 PennyLane 的基本操作，在模擬器上執行簡單的電路；
4. 最後才進入量子機器學習的課程。

**本課範例**
本課的程式範例，用純 Python 模擬一個最簡單的參數化量子電路：一個量子位元經過一個可調整角度的旋轉閘，再測量。透過調整角度，讓測量到 1 的機率接近目標值。這就是量子機器學習「調整參數、讓輸出接近目標」的最小版本。

@section 和 AI 一起做：分辨炒作與真實進展
量子與 AI 都是容易被過度宣傳的領域，兩者結合時更是如此。AI 可以幫你成為一個更清醒的讀者。

**請 AI 幫你分析新聞**
```
以下是一則關於「量子 AI」的新聞。請幫我分析：
1. 這則新聞說的是哪個方向：AI 幫助量子、量子幫助 AI，還是混合計算？
2. 它宣稱的成果是什麼？有沒有和最好的古典方法比較？
3. 使用的是物理量子位元還是邏輯量子位元？有提到錯誤率嗎？
4. 結果是否發表在同行審查的期刊，或只是公司新聞稿？
5. 哪些說法可能誇大了？
如果新聞中沒有足夠的資訊回答某個問題，請直接說「新聞未提供」。
```

最後一句很重要：請 AI **不要替新聞補上它沒說的資訊**。

**請 AI 當你的量子計算家教**
量子計算的數學很抽象，AI 很適合陪你一步一步算：
- 「請一步一步計算，一個從 0 狀態開始的量子位元，經過兩次 Hadamard 閘之後的機率幅。」
- 然後用本課或第 85 課的 Python 範例，**自己執行一次驗證 AI 算得對不對**。

這個「請 AI 解釋，再自己用程式驗證」的習慣，在任何你不熟悉的領域都很有用。

**要特別小心的地方**
量子計算的發展非常快，AI 的訓練資料可能已經過時。具體的數字（量子位元數、錯誤率、公司的里程碑、標準的時程），一定要查證最新的官方來源或論文。

@section 常見疑問
**問：為什麼 AI 幫助量子的方向，會比量子幫助 AI 發展得快？**
答：主要有三個原因。第一，**工具已經成熟**：AI（特別是深度學習和 LLM）已經是成熟、可以大規模使用的技術，而量子電腦還在早期階段，用成熟的工具幫助不成熟的技術，自然比反過來容易。第二，**問題很適合 AI**：量子錯誤的模式複雜、資料可以用模擬器大量產生，這正是神經網路擅長的情境。第三，**效果容易驗證**：一個解碼器準不準、一個電路的閘數多不多，都可以精確計算，讓 AI 的成果能被客觀地衡量。

**問：「量子啟發演算法」又是什麼？**
答：你可能會看到「量子啟發」（quantum-inspired）這個詞。它指的是**借用量子計算的數學想法，但在一般電腦上執行**的演算法。有趣的是，有些研究原本宣稱某個問題需要量子電腦才能加速，後來研究者卻找到了效果類似的量子啟發古典演算法。這也是為什麼評估量子優勢時，一定要問「有沒有和最好的古典方法比較」。另外也要注意，有些產品會用「量子」這個詞做行銷，實際上和量子電腦沒有關係。

**問：如果我想研究量子機器學習，需要很好的物理背景嗎？**
答：不一定需要很深的物理背景，但需要扎實的**線性代數**基礎，而且要熟悉**機器學習**的基本概念（損失函數、梯度、最佳化、過擬合）。前面的課程已經幫你打好了機器學習的部分。PennyLane 等工具的設計，就是讓有機器學習背景的人能用熟悉的方式操作量子電路。建議先跑通幾個官方的示範，再慢慢補充需要的量子力學概念。

**問：AI 會不會讓量子電腦更快成功，因此破解加密的時間提前？**
答：這是一個合理的推論。AI 正在幫助改善錯誤更正、優化電路、設計演算法，這些都可能**加速量子電腦的實用化**，包括能破解加密的量子電腦。這也再次說明了第 85 課的重點：後量子密碼的遷移不應該等到量子電腦真的出現才開始。兩個領域的發展是互相影響的，觀察其中一個時，也要留意另一個。

@section 整理：三個方向的發展狀態對照
用一張清單，把這一課的三個方向整理在一起，方便你以後閱讀新聞時對照：

**AI 幫助量子**
- 代表成果：AlphaQubit 解碼器（2024 年《自然》期刊）、AlphaQubit 2（2025 年論文）、AlphaTensor-Quantum、Quantinuum 與 Hiverge 的 Hive 平台；
- 發展階段：已有經同行審查的研究成果，正在朝即時、大規模的實用化推進；
- 閱讀重點：準確度和速度是否同時達標？是否在真實硬體上驗證過？

**量子幫助 AI**
- 代表方法：參數化量子電路、量子核方法、混合量子—古典模型；
- 發展階段：活躍的研究領域，但對一般 AI 任務**尚未證明實際優勢**；
- 閱讀重點：有沒有和最好的古典方法比較？資料是否本身就具量子性質？規模是否只是很小的展示？

**量子與 AI 混合計算**
- 代表動態：量子—AI 資料中心、量子處理器與 GPU 整合、產業合作宣布；
- 發展階段：基礎建設與早期探索；
- 閱讀重點：具體解決了什麼問題？是合作意向，還是已經產生成果？

這三個方向的進展速度不同，所以看到「量子 AI 突破」的新聞時，先判斷它屬於哪一個方向，就能大致知道該用多大的期待去看待它。

@section 動動腦：判斷看看
**題一**：AlphaQubit 在量子計算中扮演什麼角色？
→ 解碼器：根據錯誤更正的一致性檢查結果，推論實際發生了什麼錯誤；它屬於「AI 幫助量子」的方向。

**題二**：Hive 平台用 LLM Agent 設計量子演算法時，為什麼需要模擬器和量子電腦來驗證？
→ LLM 只負責提出變體，必須由外部系統客觀衡量效果，才能篩選出真正有效的演算法，避免把看似合理但無效的結果留下來。

**題三**：「量子電腦將讓 ChatGPT 這類大型語言模型的訓練快上千倍」，根據目前的研究，這個說法合理嗎？
→ 目前沒有證據支持。量子機器學習對一般機器學習任務尚未證明有實際優勢，還有資料載入瓶頸、貧瘠高原與硬體雜訊等困難。

**題四**：參數化量子電路的訓練流程，和一般神經網路的訓練有什麼相似之處？
→ 都是根據輸出計算損失，再用最佳化方法調整參數、反覆迭代；差別在於模型的一部分換成了帶可調參數的量子電路。

**題五**：量子計算若實用化，最可能以什麼形式被一般軟體工程師使用？
→ 以雲端服務和 API 的形式；API 設計、非同步處理、逾時重試、成本控制與結果驗證等工程能力都會用得上。

@section 本課重點整理
- **「量子 AI」有三個方向**：AI 幫助量子、量子幫助 AI、量子與 AI 混合計算，發展程度差很多。
- **AI 幫助量子（成果最具體）**：AlphaQubit 用 Transformer 解碼量子錯誤，先用模擬資料預訓練、再用真實資料微調；AlphaQubit 2 追求準確且即時；AlphaTensor-Quantum 減少昂貴的 T 閘；Hive 用 LLM Agent 演化出更精簡的量子演算法。
- **AI 提出、外部驗證**：這個模式在量子演算法設計中特別有效。
- **量子幫助 AI（仍在研究）**：參數化量子電路與混合模型；對一般 AI 任務尚未證明實際優勢，面臨資料載入、貧瘠高原、雜訊等挑戰。
- **混合計算**：量子處理器與 GPU、AI 整合，多為基礎建設與早期探索。
- **學習資源**：Qiskit、PennyLane、IBM 與 openHPI 的免費課程；先打好線性代數基礎。
- **分辨炒作**：問清楚方向、比較對象、量子位元類型、是否經過同行審查。

@term 解碼器
在量子錯誤更正中，根據一致性檢查結果推論實際錯誤並決定修正方式的元件（Decoder）。
@term AlphaQubit
Google DeepMind 與 Google Quantum AI 開發、以 Transformer 為基礎的量子錯誤更正解碼器。
@term T 閘
容錯量子計算中最昂貴的量子閘之一，減少其數量能大幅降低執行成本。
@term 量子機器學習
嘗試用量子電路取代或輔助機器學習模型部分元件的研究領域（Quantum Machine Learning，QML）。
@term 參數化量子電路
帶有可調參數的量子電路，可像神經網路一樣透過最佳化方法訓練（Parameterized / Variational Quantum Circuit）。
@term 混合量子—古典模型
由量子電路負責部分計算、一般電腦負責最佳化與其他處理的模型架構。
@term 貧瘠高原
參數化量子電路中梯度隨規模增加而趨近於零、導致難以訓練的現象（Barren Plateau）。
@term Qiskit
IBM 開發的開源量子計算 Python 工具，可模擬電路或在真實量子電腦上執行。
@term PennyLane
Xanadu 開發的開源量子計算工具，支援可微分的量子程式設計，適合量子機器學習。
