@section 開場：免費下載的 AI 模型，真的可以隨便用嗎？
第 18 課提到，除了 OpenAI、Anthropic 這類只能透過 API 使用的模型，還有一大類「**開放權重模型**」：模型檔案可以免費下載，放在自己的電腦或伺服器上執行。例如 Meta 的 Llama、阿里巴巴的 Qwen、Mistral、微軟的 Phi、Google 的 Gemma。

這些模型大多放在一個叫做 **Hugging Face** 的網站上。Hugging Face 可以想成是「**AI 模型界的 GitHub**」：全世界的研究者和公司在上面分享模型、資料集和程式，目前已經有超過一百萬個模型。

看到這麼多免費模型，很容易興奮地挑一個下載量最高的，直接拿來用在公司產品上。但這裡藏著好幾個陷阱：
- **法律陷阱**：「免費下載」不等於「可以免費商用」。有些模型禁止商業使用，有些有特殊條件。
- **版本陷阱**：模型作者隨時可能更新檔案，你的系統行為可能在你不知情的情況下改變。
- **資安陷阱**：某些格式的模型檔案，**載入的瞬間就可能執行惡意程式**，讓整台伺服器被駭。
- **品質陷阱**：排行榜上的高分，不代表它在繁體中文、台灣情境中表現好。

這一課對應 Microsoft《Generative AI for Beginners》第 16 課「開源模型」。我們要學會像審查合約一樣，有系統地評估一個開放權重模型。

@section 先讀說明書：模型卡
每個 Hugging Face 上的模型，都有一份說明文件，叫做「**模型卡**」（Model Card）。它就像藥品的仿單，或家電的使用說明書：告訴你這個東西是什麼、適合做什麼、不適合做什麼、有什麼已知的風險。

專業的工程師挑模型時，**不會只看下載次數或星星數**，而是會仔細讀模型卡。一份好的模型卡會告訴你：

**① 這是什麼類型的模型？**
- **基礎模型**（Base Model）：只做過預訓練，會「文字接龍」但不會當助理（第 15 課）。
- **指令模型**（Instruct / Chat Model）：經過監督微調（SFT），會回答問題、遵守指令。
- **合併模型**（Merge）：有人把好幾個模型的參數混合在一起做出來的，來源比較複雜。

如果你要做聊天應用，卻下載了基礎模型，它可能只會一直接龍，不會回答問題。

**② 用什麼資料訓練的？語言比例如何？**
這一點對繁體中文使用者**特別重要**。很多標榜「多語言」的模型，訓練資料中英文可能佔將近九成，簡體中文佔幾個百分比，而**繁體中文和台灣在地的內容可能不到百分之一**。

如果沒注意這一點，部署後可能出現：
- 繁體簡體混在一起；
- 用中國大陸的用語（「視頻」而非「影片」、「軟件」而非「軟體」、「質量」而非「品質」）；
- 對台灣的法規、制度、地名不熟悉。

**③ 預期用途和禁止用途。**
模型卡會說明這個模型被設計來做什麼，以及**沒有**被驗證過可以做什麼。例如「未經醫療診斷驗證」、「不適合用於法律判決」。也會列出已知的偏見和容易產生幻覺的情況。

**④ 評估結果。**
在哪些測驗上表現如何。（但要小心，後面會說明排行榜的盲點。）

**⑤ 授權條款。**
可以怎麼使用。這是下一段的主題。

@section 「開放權重」不等於「開源」：四種授權等級
這是企業最常踩的法律地雷：**把「可以免費下載」誤以為「可以隨便商用」。**

**先釐清兩個詞：**
- **開源**（Open Source）：在軟體界有嚴格的定義（由開放原始碼促進會 OSI 制定），基本上代表可以自由使用、修改、分享，包括商業用途。
- **開放權重**（Open Weights）：只代表「模型的參數檔案可以下載」。能不能商用、有什麼限制，要看各自的授權條款。

導入任何開放權重模型之前，要把它的授權歸類到以下四個等級：

**第一級：寬鬆的開源授權。**
常見的是 **Apache 2.0** 和 **MIT** 授權。例如 Qwen 的多數版本、部分 Mistral 模型、微軟的 Phi 系列。
- ✓ 可以商用、可以修改、可以微調、可以再分享
- 只需要保留原始的版權聲明
- 這是最安心的等級

**第二級：附帶條件的社群授權。**
例如 Meta 的 **Llama 社群授權**、Google 的 **Gemma 使用條款**。
- ✓ 大部分商業用途都可以
- 但有特殊條件，例如：
  - 產品的月活躍使用者超過某個很大的數字（Llama 的規定是 7 億），要另外向 Meta 申請授權；
  - 衍生模型的名稱必須包含特定字樣；
  - 必須遵守「**可接受使用政策**」，禁止用於某些特定用途。
- 要仔細讀條款，確認你的使用情境沒有違反

**第三級：禁止商用。**
例如 **CC-BY-NC**（NC 是 Non-Commercial，非商業）授權。
- ✗ 只能用於學術研究或個人學習
- 任何直接或間接帶來商業利益的使用（包括公司內部工具）都不行

**第四級：隱藏的上游限制。**
最容易被忽略的陷阱。有些模型本身標示 MIT 授權，看起來很安全。但它的**訓練資料**，可能是用某家商業 AI 服務產生的，而那家服務的條款**禁止用它的輸出來訓練競爭模型**。這種情況下，商用的法律風險仍然很高。

**實務建議：**
- 導入前，讓法務人員看過授權條款；
- 不只看模型本身的授權，也看它的訓練資料來源；
- 把授權資訊記錄在公司的模型清單中。

（本課僅提供一般性的概念說明，具體的授權判斷請諮詢法律專業人士。）

@section 鎖定版本：防止模型在你不知情時改變
在程式中載入 Hugging Face 模型，最常見的寫法是：
```
model = AutoModelForCausalLM.from_pretrained("org/model-name")
```

這行程式預設會下載**最新版本**（主分支 `main` 上的檔案）。問題是：**模型作者隨時可能更新**。可能是：
- 修改了對話格式的範本（Chat Template），讓模型理解對話的方式改變；
- 換了一版權重；
- 改了「結束符號」的設定（第 13 課的特殊 Token），讓模型不知道什麼時候該停。

**實際會發生的問題：**
你的服務在流量大時，會自動增加伺服器（叫做「**自動擴展**」，Auto-scaling）。舊的伺服器用的是上個月下載的版本，新開的伺服器下載了今天的新版本。結果**同一個服務，不同伺服器的行為不一樣**，使用者時好時壞，非常難除錯。

這和第 18、29 課「鎖定模型版本」是同樣的道理。

**解法一：指定確切的版本編號。**
Hugging Face 用 Git 管理檔案，每次更新都有一個 40 個字元的唯一編號（Commit Hash）。載入時明確指定：
```
model = AutoModelForCausalLM.from_pretrained(
    "org/model-name",
    revision="a1b2c3d4e5f6..."    # 完整的 40 字元編號
)
```

**解法二：在公司內部保存一份備份。**
把模型的所有檔案（權重、設定檔、分詞器檔案）下載下來，存在公司內部的儲存空間，並記錄每個檔案的雜湊值（第 29 課），確認檔案沒有被竄改。這樣：
- 不怕外部網路中斷；
- 不怕原作者刪除或修改模型；
- 確保每次部署用的都是完全相同的檔案。

@section 資安警報：載入模型檔案，可能就被駭了
這是很多人不知道、但非常嚴重的安全問題。

**背景：Python 的 pickle 格式。**
早期 PyTorch 儲存模型時，常用 `.bin`、`.pt`、`.pth` 這些檔案格式，它們的底層使用 Python 的 **pickle** 模組。pickle 是一種把 Python 物件「打包」成檔案的方法。

**問題在於：pickle 在「解開」檔案時，可以執行任意程式碼。**這是它的設計特性，不是錯誤。

**攻擊方式：**
攻擊者在 Hugging Face 上傳一個看起來正常的模型，但在 `.bin` 檔案中藏了一行指令，例如「下載並執行某個惡意程式」。當工程師在伺服器上執行 `torch.load()` 載入這個模型的**瞬間**，惡意程式就被執行了。整台伺服器、連同上面的密碼、金鑰、公司內部網路的存取權限，全部淪陷。

而且工程師完全不會察覺，因為模型看起來正常載入了。

資安研究人員確實曾在 Hugging Face 上發現過含有這類惡意程式碼的模型。

**解法：使用 safetensors 格式。**
Hugging Face 推出了一種新的格式叫做 **safetensors**（安全張量）。它的設計非常簡單：
- 檔案開頭是一段純文字的說明（JSON 格式）：有哪些張量、什麼型別、在檔案中的哪個位置；
- 後面就是純粹的數字資料。

**它在設計上就不可能執行任何程式碼**，只能存數字。而且載入速度比 pickle 還快好幾倍（因為可以直接把檔案對應到記憶體，不用複製）。

**實務規則：**
1. **優先選擇有提供 `.safetensors` 檔案的模型**。目前大多數主流模型都有提供。
2. **不要載入來路不明的 `.bin`、`.pt` 檔案**。
3. **注意 `trust_remote_code` 這個參數。**有些新架構的模型，要求設定 `trust_remote_code=True` 才能載入。這代表它會**下載並執行模型作者寫的 Python 程式**。預設應該保持 `False`；如果一定要開啟，必須先由懂程式的人逐行檢查那些程式碼，並鎖定版本編號（避免檢查完之後作者又改了）。

**比喻：**pickle 格式就像一個包裹，打開時裡面可能會跳出東西；safetensors 就像一個透明的資料夾，裡面只有紙張，一目了然。

@section 排行榜的盲點
Hugging Face 有一個知名的「**開放 LLM 排行榜**」（Open LLM Leaderboard），列出各個開放模型在標準測驗上的分數。但第 18 課已經提過，排行榜的高分不等於在你的應用中表現好。對開放模型來說，有三個特別要注意的盲點：

**① 測驗題目污染。**
有些模型（可能是無意的，也可能是刻意的）在訓練時混入了排行榜測驗的題目或改寫版本。分數因此虛高，遇到真正沒見過的問題就打回原形。開放模型的數量非常多，有些人專門為了衝排行榜而微調，這個問題特別嚴重。

**② 語言和文化的落差。**
大部分國際測驗以英文為主。就算有中文測驗，也常以簡體中文和中國大陸的用語為準。

在台灣的應用情境中，很多專有名詞有特定的意思和用法：
- 金融：「背書保證」、「特別股」、「除權息」
- 勞動：「特休折現」、「勞退提繳」
- 醫療：「健保部分負擔」、「轉診」

只在英文或簡體中文上表現好的模型，回答這些問題時可能套用錯誤的法規、用錯詞彙，或出現生硬的翻譯腔。

**③ 測驗形式和真實任務不同。**
排行榜多半是「單一問題、四選一」或「短篇數學題」。但企業應用真正需要的是：
- 長篇文件的 RAG 忠實引用（第 25 課）；
- 多輪工具呼叫的格式穩定度（第 26 課）；
- 遇到不知道的問題能誠實拒答（第 29 課）。
這些能力，排行榜很少測到。

@section 選擇開放模型的四階段流程
綜合以上，一套有系統的開放模型選擇流程：

**階段一：法務和資安初篩。**
- 授權條款是否允許你的商業用途和規模？
- 是否提供 safetensors 格式？
- 是否需要 `trust_remote_code`？如果需要，程式碼是否已經審查過？
- 記錄確切的 40 字元版本編號。

**階段二：硬體試算。**
- 模型有多大？需要多少顯示卡記憶體？
- 第 18 課提過：70 億參數的模型，用 16 位元精度約需 14 GB 記憶體；用 4 位元的**量化**版本（把每個參數用較少的位元儲存，犧牲一點精度換取大幅縮小）約需 4 到 5 GB。
- 在預期的同時使用人數下，首字延遲和生成速度是否夠快？

**階段三：用自己的繁體中文測試集實測。**
用團隊自己建立的 100 到 300 題測試集（第 18、29 課），重點檢查：
- **繁體中文和台灣用語的正確性**：有沒有出現簡體字？有沒有用錯詞？
- **RAG 忠實度和拒答能力**：會不會亂編？資料不足時會不會說不知道？
- **格式穩定度**：JSON 輸出和工具呼叫，一次就成功的比例多高？

**階段四：總成本比較。**
自己架設開放模型，要算：
- 顯示卡的租用或購買費用；
- **閒置時間的成本**：半夜沒人用時，顯示卡還是在花錢；
- 維運人力（更新、監控、處理故障）。

和商用 API（按 Token 計費，不用就不花錢）在**真實流量**下比較。通常流量很大且穩定時，自己架設比較划算；流量小或波動大時，用 API 比較划算。兩者的成本曲線會在某個流量點交叉。

@section 動動腦：審查看看
**情境一**：某新創公司在 Hugging Face 找到一個下載量很高的模型，授權標示為 CC-BY-NC-4.0，打算用在付費的客服產品中。可以嗎？
→ 不行。NC 代表禁止商用。應該換成 Apache 2.0、MIT，或條件符合的社群授權模型。

**情境二**：工程師在程式中寫 `from_pretrained("org/model")`，沒有指定版本。某天新開的伺服器開始出現奇怪的回答，舊伺服器正常。可能原因？
→ 原作者更新了模型，新伺服器下載了新版本。應該指定 40 字元的版本編號，並在內部保存備份。

**情境三**：同事下載了一個只有 `.bin` 檔的模型，打算直接在正式伺服器上用 `torch.load()` 載入測試。有什麼風險？
→ pickle 格式在載入時可以執行任意程式碼，可能被植入惡意程式。應該選擇有 safetensors 格式的模型，或至少在隔離的環境中處理。

**情境四**：某模型在英文排行榜排名很高，部署到台灣的金融客服後，常出現簡體字和大陸用語。問題出在哪裡？
→ 沒有檢查模型卡的語言比例，也沒有用自己的繁體中文測試集實測。排行榜無法反映繁體中文和台灣情境的表現。

@section 本課重點整理
- **Hugging Face** 是 AI 模型界的 GitHub，有上百萬個開放模型。
- **模型卡**是模型的說明書：類型（基礎、指令、合併）、訓練資料與語言比例、用途限制、評估結果、授權。繁體中文的比例特別要注意。
- **開放權重 ≠ 開源**：授權分四級——寬鬆開源（Apache、MIT）、附條件社群授權（Llama、Gemma）、禁止商用（NC）、隱藏的上游資料限制。
- **鎖定版本**：指定 40 字元的版本編號，並在內部保存經過雜湊驗證的備份。
- **資安**：pickle 格式（.bin、.pt）載入時可能執行惡意程式。優先使用 safetensors；`trust_remote_code` 預設關閉，開啟前要審查程式碼。
- **排行榜盲點**：題目污染、偏重英文和簡體中文、測驗形式和真實任務不同。
- **四階段選擇**：法務資安初篩 → 硬體試算 → 用自己的繁中測試集實測 → 總成本比較。

@term Hugging Face
全球最大的 AI 模型、資料集分享平台，可想成 AI 模型界的 GitHub。
@term 模型卡
說明模型類型、訓練資料、用途限制、評估結果和授權的文件（Model Card）。
@term 指令模型
經過監督微調、能遵守指令和回答問題的模型（Instruct Model），相對於只會接龍的基礎模型。
@term 開源
可自由使用、修改、分享（包括商業用途）的授權方式（Open Source），有嚴格的定義。
@term 開放權重
模型參數檔案可以下載，但使用條件依各自授權而定（Open Weights）。
@term Apache 2.0
寬鬆的開源授權，允許商用、修改和再分發，只需保留版權聲明。
@term 可接受使用政策
授權方規定禁止的使用方式清單（Acceptable Use Policy）。
@term Commit Hash
Git 中每次更新的唯一識別編號，可用來精確指定某個版本。
@term 自動擴展
依流量自動增加或減少伺服器數量的機制（Auto-scaling）。
@term pickle
Python 的物件序列化格式，載入時可以執行任意程式碼，有資安風險。
@term safetensors
只儲存張量數字、無法執行程式碼的安全模型檔案格式，載入也更快。
@term trust_remote_code
載入模型時是否允許執行模型倉庫中自訂 Python 程式的設定，預設應關閉。
@term 量化
用較少位元儲存模型參數，以少量精度換取大幅縮小體積和加快速度的技術（Quantization）。
