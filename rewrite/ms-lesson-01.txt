@section 開場：AI 不是在「查答案」，而是在「接話」
很多人第一次用 ChatGPT 時，會以為它像 Google 一樣，有一個巨大的資料庫，問題進來就去裡面「查」答案。

**這是對生成式 AI 最大的誤解。**

前面的 Karpathy 系列告訴我們：語言模型唯一的本事，是**根據前面的文字，算出下一個 Token 的機率**。它沒有一個存著「標準答案」的資料庫。它的所有知識，都被「壓縮」在幾十億、幾千億個參數裡，回答時是一個字一個字**即時生成**出來的。

這個差別非常重要，因為它解釋了生成式 AI 的兩個最大特性：
- **為什麼它很有創意**：同一個問題問兩次，可能得到不同的回答。
- **為什麼它會一本正經地胡說八道**：它可能編出不存在的論文、法條、數據，而且語氣非常自信。

這一課對應 Microsoft《Generative AI for Beginners》的第 01 課，我們要搞懂：
1. 模型怎麼從機率分布中「挑」出下一個字（解碼策略）；
2. 溫度（Temperature）和 Top-p 這兩個旋鈕在做什麼；
3. AI 為什麼會產生「幻覺」；
4. 為什麼把溫度調成 0 也無法消除幻覺；
5. 怎麼真正降低幻覺。

這一課的內容，是你未來使用任何 AI 工具時，判斷「什麼時候可以信它、什麼時候要查證」的基礎。

@section 從提示詞到下一個字：一張機率表
當你輸入「台灣的首都位於」，模型內部發生了什麼？

模型的最後一層會輸出一長串分數，長度等於詞彙表大小（例如 10 萬個 Token），每個 Token 都有一個分數，叫做 **logits**（第 12 課學過）。假設幾個候選的分數是：
- 「台北」：6.0
- 「臺北」：5.0
- 「北部」：2.0
- ……
- 「香蕉」：−8.0

接著用 **Softmax** 把這些分數變成加起來等於 1 的機率。「台北」可能有 70%、「臺北」25%、「北部」1%……「香蕉」幾乎是 0。

然後系統從這張機率表中**挑一個** Token，例如「台北」，把它接到後面，變成「台灣的首都位於台北」，再重新計算下一個字的機率。一路重複，直到產生結束符號或達到長度上限。

**「怎麼從機率表中挑一個」，就叫做「解碼策略」**（Decoding Strategy）。這一步看似簡單，卻大大影響輸出的品質和風格。同一個模型，換一種解碼策略，可能從呆板無聊變成天馬行空。

@section 最簡單的挑法：永遠選第一名
最直覺的做法是：**每一步都選機率最高的那個**。這叫做「**貪婪解碼**」（Greedy Decoding）。「貪婪」的意思是每一步都只顧眼前最好的選擇。

**優點**：
- 結果**固定**：同樣的輸入，永遠得到同樣的輸出。
- 適合有標準答案的任務：分類（這封信是不是垃圾郵件）、資料擷取（從合約中找出日期）、格式轉換（把文字轉成 JSON 格式）。

**缺點一：每一步最好，不代表整體最好。**
就像爬山時每一步都往最陡的方向走，不一定能到達最高峰，可能卡在一個小山頭上。每一步都選最常見、最安全的字，整段話讀起來會非常平淡、制式、沒有個性。

**缺點二：無限重複的陷阱。**
這是貪婪解碼最有名的毛病。一旦模型某一步產生了跟前面相似的句子，下一次遇到同樣的開頭，它又會百分之百選出同樣的下一個字，於是陷入迴圈：

「這件事很重要。這件事很重要。這件事很重要。這件事很重要……」

早期的語言模型經常出現這種現象。

**另一個極端：完全按機率隨機抽。**
如果每一步都完全照機率表抽籤（叫做純隨機抽樣），重複的問題解決了，但又有新問題：詞彙表有 10 萬個 Token，雖然每個冷門 Token 的機率都很小，但**加起來**可能不小。偶爾就會抽到排名第 5 萬名、完全不相干的字，讓整段話突然語無倫次。

所以我們需要一些精細的旋鈕，在「太死板」和「太亂」之間找到平衡。這就是**溫度**和 **Top-p**。

@section 溫度：調整機率表的「尖銳程度」
**溫度**（Temperature，常寫作 T）這個名字來自物理學。在統計物理中，溫度越高，粒子越活潑、越亂跑；溫度越低，粒子越安定、越集中。

**做法**：在把分數送進 Softmax **之前**，先把每個分數除以 T：

$$P_i = \frac{e^{z_i / T}}{\sum_j e^{z_j / T}}$$

（$z_i$ 是第 i 個 Token 的分數。）

**實際算一次。**假設三個候選的分數是 [4, 2, 0]。

**T = 1（標準）**：直接做 Softmax。
- $e^4 \approx 54.6$、$e^2 \approx 7.39$、$e^0 = 1$，總和 63.0
- 機率 ≈ **[86.7%, 11.7%, 1.6%]**

**T = 0.2（低溫）**：分數除以 0.2，等於乘以 5，變成 [20, 10, 0]。
- 差距被放大了 5 倍，指數之後差距更是天文數字。
- 機率 ≈ **[99.995%, 0.005%, 0.000%]**
- 第一名幾乎拿走全部機率。當 T 趨近 0 時，就等於貪婪解碼。

**T = 2（高溫）**：分數除以 2，變成 [2, 1, 0]。
- 差距被縮小。
- 機率 ≈ **[66.5%, 24.5%, 9.0%]**
- 原本只有 1.6% 的第三名，現在有 9% 的機會被選中。

**直覺**：溫度像是一個「冒險程度」的旋鈕。
- **低溫**：保守、穩定、可預測，總是選最有把握的答案。
- **高溫**：大膽、多樣、有創意，願意嘗試不那麼常見的選擇，但也更容易出錯。

**實務建議**：
- 寫程式、擷取資料、回答事實問題：**0 到 0.2**
- 一般客服對話、摘要：**0.3 到 0.7**
- 腦力激盪、寫故事、寫詩：**0.8 到 1.0**
- 超過 1.5 的高溫，輸出通常會變得混亂，很少使用。

@section Top-k 與 Top-p：一刀切掉不合理的選項
溫度有一個副作用：**調高溫度時，它把第二、三名的機率拉高，但同時也把詞彙表尾巴幾萬個完全不相干的字一起拉高了。**這些「長尾雜訊」加起來，被抽中的機會不小。

解法是：**抽籤前，先把明顯不合理的選項淘汰掉。**有兩種做法：

**做法一：Top-k，只留前 k 名。**
每一步只保留機率最高的前 k 個 Token（例如 k = 50），其他全部歸零，再重新分配機率。

問題是：**k 是固定的，但不同情境需要的選項數量差很多。**
- 「太陽從東邊升起，從＿＿落下」：合理的答案只有「西邊」一個。強制保留 50 個，等於把 49 個錯誤選項放進抽籤池。
- 「我最喜歡的食物是＿＿」：合理的答案可能有上百種。只留 50 個又太少了。

**做法二：Top-p（核抽樣，Nucleus Sampling），動態決定留幾個。**
把所有候選按機率從高到低排好，**從第一名開始往下累加，直到累積機率達到 p**（例如 p = 0.9），只保留這些，其他淘汰。

- 模型很有把握時（第一名就有 95%），累加第一名就超過 0.9，抽籤池只剩 **1 個**。
- 模型面對開放問題時（前幾十名機率都差不多），要累加幾十個才到 0.9，抽籤池自動擴大到**幾十個**。

這種「依模型把握程度自動調整」的特性，讓 Top-p 成為目前最常用的方法。這個方法是 2019 年由 Holtzman 等研究者提出的，他們把「累積機率達到 p 的那一小群核心候選」稱為「核」（Nucleus），所以叫核抽樣。

**一個重要的實務建議**：OpenAI 等公司的文件都建議，**溫度和 Top-p 擇一調整就好，不要兩個同時大幅改動**。兩者都在控制隨機程度，同時調會互相干擾，很難預測結果。

@section API 上其他常見的生成參數
呼叫 OpenAI、Azure 或其他 AI 服務的 API 時，除了溫度和 Top-p，你還會看到幾個常見參數。了解它們，才知道每個旋鈕在控制什麼：

**max_tokens（最大輸出長度）。**
限制模型這次最多產生幾個 Token。到達上限時，模型會被**硬生生截斷**，即使話還沒說完。設太小，回答可能斷在半句；設太大，可能浪費錢（輸出 Token 通常比輸入貴好幾倍）。上一課提過，後端應該鎖定這個值，不讓前端自由設定。

**stop（停止詞）。**
指定一個或幾個字串，模型一產生它們就立刻停下。例如做問答時設定 stop 為「問題：」，避免模型答完之後自己又編出下一個問題（回想第 15 課：基礎模型很愛自己接著出題）。

**frequency_penalty（頻率懲罰）與 presence_penalty（出現懲罰）。**
專門對付「重複」問題的參數：
- **頻率懲罰**：一個 Token 已經出現過越多次，下次被選中的分數就扣越多。可以減少同一個詞反覆出現。
- **出現懲罰**：只要一個 Token 出現過（不管幾次），分數就扣一個固定值。鼓勵模型談論新的主題。
通常設在 0 到 1 之間的小數字。設太大會讓模型刻意避開正常該重複的詞（例如主角名字），反而不自然。

**seed（亂數種子）。**
有些 API 允許指定種子，讓同樣的輸入和設定在溫度大於 0 時也盡量產生相同的結果，方便測試和除錯。（第 10 課的可重現實驗，在這裡也適用。）不過供應商通常只保證「盡量」相同，因為伺服器端的硬體和軟體版本也可能影響結果。

**n（產生幾個回答）。**
一次產生好幾個不同的回答，讓程式或使用者挑最好的。費用也會乘上 n 倍。

@section 親手做實驗：感受溫度的差別
如果你有任何一個能調整溫度的 AI 工具（例如 OpenAI Playground、Azure AI Foundry 的遊樂場，或在程式中呼叫 API），很建議做這個小實驗，十分鐘就能對溫度有深刻的體感：

**實驗設計**：用同一個提示詞「用一句話形容秋天」，分別在溫度 0、0.7、1.5 下各產生 5 次。

**你大概會看到：**
- **溫度 0**：5 次的結果幾乎一模一樣，而且很「標準」，像是「秋天是一個涼爽宜人、落葉繽紛的季節」。
- **溫度 0.7**：5 次各有不同，用詞有變化，但都通順合理，像是「秋天是夏天寫給冬天的一封長信」。
- **溫度 1.5**：開始出現奇怪的用詞、跳躍的邏輯，甚至突然換成其他語言或冒出亂碼。

**第二個實驗**：問一個有明確答案的問題，例如「水的化學式是什麼」，同樣用三種溫度各問 5 次。你會發現，在答案很確定的問題上，即使溫度 0.7，答案也幾乎都一樣，因為模型給正確答案的機率本來就接近 100%，溫度調整也拉不太動。這正說明了：**溫度的效果，取決於模型本身有多確定。**

@section 幻覺：AI 為什麼會一本正經地胡說八道？
**幻覺**（Hallucination）指的是：模型用非常自信、流暢、合乎文法的語氣，**編造出不存在的事實**。例如：
- 引用一篇根本不存在的學術論文，連作者、期刊、年份、編號都有；
- 說出一條不存在的法律條文；
- 給出錯誤的歷史日期或統計數字；
- 介紹一個不存在的程式套件或函式。

2023 年美國有律師用 ChatGPT 準備訴狀，結果引用了 6 個完全虛構的判例，被法官發現後受到處分，成為新聞。

**為什麼會這樣？根本原因在訓練目標。**

回想第 12 課：語言模型從第一天開始，就只被訓練一件事——**產生「看起來最像人類文章」的下一個字**。它的損失函數 NLL 只在乎「這段文字自不自然」，**從來不在乎「這段文字是不是真的」**。

**模型的知識是一種「有損壓縮」。**

想像你把一張高畫質照片壓縮成很小的 JPG 檔：整體樣子還在，但細節變模糊了。模型把整個網路的文字壓縮進參數裡，也是一樣：**整體的模式、風格、常識保留得很好，但精確的細節（某篇論文的確切標題、某個數字的確切值）常常變模糊。**

**實際例子：**你要模型「列出三篇關於量子深度學習的 IEEE 期刊論文，附上 DOI 編號」。

模型確實記得很多東西：
- IEEE 論文的標題通常長什麼樣（某某方法於某某問題之應用）；
- 這個領域有哪些知名教授；
- DOI 編號的格式一定是「10.1109/某某.年份.數字」。

於是它按照最高機率，把**真實的知名作者 + 聽起來很專業的詞彙組合 + 格式完全正確的隨機數字**拼在一起。對模型來說，這段文字「看起來」非常合理，機率很高。但在現實世界裡，這篇論文根本不存在。

**重點**：模型**不是故意說謊**，它根本沒有「真」和「假」的概念。它只知道「什麼樣的文字看起來合理」。所以，**不要把語言模型當成權威資料庫**。

**哪些情況特別容易出現幻覺？**
- 冷門、小眾的知識（訓練資料少，記得模糊）；
- 精確的數字、日期、引用、網址；
- 訓練資料截止日期之後發生的事；
- 問題本身有錯誤前提（例如「請解釋愛因斯坦為什麼得到兩次諾貝爾獎」，模型可能順著你編下去）。

@section 為什麼溫度設為 0 也無法消除幻覺？
企業導入 AI 時最常見、也最危險的一個誤解是：「把溫度設成 0，AI 就不會亂講了。」

**溫度 0 只消除了「隨機性」，沒有消除「錯誤」。**

用數字說明。假設你問模型一個冷門法規的細節，模型內部的機率分布是：
- 錯誤答案 A：45%
- 錯誤答案 B：30%
- 正確答案 C：25%

**溫度 1 時**：模型有 25% 的機會答對，75% 答錯。每次問，答案可能不一樣。

**溫度 0 時**：模型**每次都選 A**，也就是說，**100% 穩定地給出同一個錯誤答案**。

這叫做「**確定性幻覺**」（Deterministic Hallucination）。溫度 0 讓錯誤變得**更穩定、更一致**，反而更難被察覺，因為你每次問都得到同樣的答案，會誤以為它很可靠。

**溫度控制的是「怎麼從機率表中挑」，但幻覺的根源是「機率表本身就是錯的」。**要解決幻覺，必須從機率表的來源下手。

（溫度 0 仍然很有用：它讓輸出可重現，方便測試和除錯。只是不要以為它能保證正確。）

@section 怎麼真正降低幻覺？三個方向
既然調參數不夠，就要從系統設計下手。這也是接下來好幾課的主題：

**① 給它資料：檢索增強生成（RAG）。**
不要讓模型「憑記憶」回答，而是先從可靠的資料來源（公司文件、資料庫、網路搜尋）**找出相關資料**，連同問題一起交給模型，請它「**根據這些資料**」回答。

就像考試從閉書考改成開書考：模型不用靠模糊的記憶，而是有參考資料可以對照。這叫做**接地**（Grounding），讓回答「落地」在真實資料上。後面的課程會詳細介紹 RAG（Retrieval-Augmented Generation）。

**② 要它附來源，並且查證。**
在提示詞中要求模型「每個說法都要附上來源段落」，然後由程式或人工檢查這些來源是不是真的存在、內容是不是真的支持這個說法。

**③ 允許它說「不知道」。**
在提示詞中明確寫：「如果提供的資料中找不到答案，請直接說『資料中沒有相關資訊』，不要猜測。」模型被訓練成要有幫助，所以傾向一定要給出答案；明確允許它說不知道，能大幅減少硬編的情況。

**對一般使用者的建議**：
- 把 AI 當作「很博學但記性不太可靠的助理」，而不是百科全書。
- 用它來**整理思路、改寫文字、腦力激盪、解釋概念**，這些它很擅長。
- 涉及**數字、引用、法律、醫療、財務**等需要精確的資訊時，一定要自己查證原始來源。
- 有搜尋功能的 AI（會附上網址的那種）比較可靠，但仍要點進來源看一下。

@section 動動腦：你會怎麼設定？
**情境一：從 1,000 份合約中擷取「簽約日期」，輸出成表格。**
答案只有一個、需要穩定、需要可重現。→ **溫度 0**（或接近 0）。而且要搭配程式檢查日期格式是否正確。

**情境二：幫公司的新產品想 20 個名字。**
需要多樣性和創意。→ **溫度 0.8 到 1.0**，或 Top-p 0.9 到 0.95。名字重複或太平淡反而是失敗。

**情境三：客服聊天機器人回答「退貨政策」。**
需要準確、一致，但語氣可以自然一點。→ 溫度 **0.3 左右**，而且**最重要的是用 RAG**：把公司真實的退貨政策文件交給模型，要求它只根據文件回答。光靠調溫度，模型可能會編出不存在的退貨條件。

**情境四：同事說「我們把溫度設為 0 了，所以 AI 的財報分析一定正確」。**
你應該怎麼回應？→ 溫度 0 只讓答案固定，不讓答案正確。如果模型記錯了財報數字，溫度 0 會讓它每次都穩定地給出同一個錯誤數字。應該把真實財報資料提供給模型，並且人工核對關鍵數字。

@section 常見問題
**Q：為什麼同一個問題，ChatGPT 每次回答都不一樣？**
因為網頁版的聊天介面通常使用大於 0 的溫度，讓回答比較自然、有變化。每次生成時抽樣的結果不同，後面的字又依賴前面的字，差異就會一路放大，最後可能整段都不一樣。這不是壞掉，而是刻意的設計。

**Q：AI 說「我很確定」，是不是就比較可信？**
不一定。模型說「我很確定」，只代表在訓練資料中，這類回答常常搭配這種語氣；它不是在報告自己內部真實的把握程度。有研究嘗試讓模型輸出可靠的信心分數，但目前仍不完美。判斷可信度，看的是**有沒有可查證的來源**，而不是語氣。

**Q：模型越大，幻覺就越少嗎？**
整體來說，較大、較新的模型在常見知識上幻覺較少，也比較會說「我不確定」。但只要問到冷門細節，任何模型都可能出錯。而且大模型的錯誤往往寫得更流暢、更有說服力，反而更難察覺。

**Q：幻覺有沒有好處？**
在創作情境中，「編造」正是我們要的：寫小說、想廣告標語、腦力激盪，都需要模型產生訓練資料裡沒有的新組合。問題不在於模型會編造，而在於我們要分清楚**什麼時候要它創作、什麼時候要它陳述事實**，並為後者準備查證機制。

@section 本課重點整理
- **生成式 AI 不是在查資料庫**，而是根據前文，一個 Token 一個 Token 地算機率、挑選、接上。
- **解碼策略**決定怎麼從機率表中挑一個 Token。
- **貪婪解碼**每次選第一名：穩定但呆板，容易陷入重複迴圈。**純隨機抽樣**：多樣但可能抽到離譜的字。
- **溫度**：分數除以 T 再做 Softmax。低溫集中、保守；高溫平坦、有創意。寫程式用 0 到 0.2，創作用 0.8 到 1.0。
- **Top-k** 固定保留前 k 名；**Top-p** 動態保留累積機率達 p 的候選，更有彈性。溫度和 Top-p 擇一調整。
- **幻覺**來自訓練目標：模型只學「像不像人話」，不學「是不是真的」。知識是有損壓縮，精確細節容易模糊。
- **溫度 0 無法消除幻覺**，只會讓錯誤變得穩定（確定性幻覺）。
- **降低幻覺**：用 RAG 提供真實資料、要求附來源並查證、允許模型說不知道。

@term 生成式 AI
能產生新內容（文字、圖片、聲音、程式碼）的 AI，而不只是分類或預測（Generative AI）。
@term 解碼策略
從模型算出的下一個 Token 機率分布中，挑選一個 Token 的方法（Decoding Strategy）。
@term 貪婪解碼
每一步都選機率最高的 Token（Greedy Decoding），結果固定但容易呆板或重複。
@term Top-k
每一步只保留機率最高的前 k 個候選 Token 來抽樣。
@term 核抽樣
即 Top-p：保留累積機率達到門檻 p 的最小候選集合來抽樣（Nucleus Sampling）。
@term 幻覺
模型以自信流暢的語氣編造不存在的事實、引用或數據（Hallucination）。
@term 有損壓縮
壓縮後保留整體但遺失部分細節的壓縮方式，例如 JPG。用來比喻模型如何儲存知識。
@term 確定性幻覺
溫度設為 0 時，模型每次都穩定地輸出同一個錯誤答案的現象。
@term RAG
檢索增強生成（Retrieval-Augmented Generation）：先找出相關資料，再讓模型根據資料回答。
@term 接地
讓模型的回答建立在提供的真實資料上（Grounding），而不是憑記憶。
