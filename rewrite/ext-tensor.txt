@section 開場：AI 眼中的世界，全部都是「一格一格的數字」
你有沒有想過：一張照片、一段語音、一句話，對電腦來說到底是什麼？

答案是：**全部都是數字**。一張照片是幾百萬個代表顏色深淺的數字；一段語音是每秒幾萬個代表聲波高低的數字；一句話會先被切成小片段，每個片段再換成一串數字（第 13 課會講怎麼換）。不管原本是什麼，進入 AI 模型之前，都要先變成**整整齊齊排好的一堆數字**。

這個「整整齊齊排好的一堆數字」，在深度學習裡有個專門名稱，叫做**張量**（Tensor）。名字聽起來很嚇人，其實你每天都在用它的親戚：Excel 表格就是一種張量。

這一課來自李沐等人寫的《動手學深度學習》（簡稱 D2L，一本免費的線上互動教科書）。書裡在第一章就強調：讀懂任何 AI 論文或程式碼的第一個基本功，就是**隨時知道每一堆數字的「形狀」**——它有幾層、每層有幾格。這聽起來很枯燥，但 AI 工程師遇到的 bug，有一大半都跟「形狀對不上」有關。學完這課，你會理解為什麼一個小小的形狀錯誤，能讓模型白白訓練好幾天卻學出一堆廢物。

我們會依序學：張量是什麼、電腦怎麼把它存起來、三種基本運算，以及最容易出事的「廣播」機制。

@section 從一個數字到一疊照片：張量的「維度」
理解張量最好的方法，是從最簡單的開始，一層一層往上疊。

**0 維：一個數字。**例如今天的氣溫 25。數學上叫做「**純量**」（Scalar）。它的形狀寫成 `()`——空括號，表示「沒有任何方向可以延伸」。在 AI 訓練中，最常見的 0 維張量是「**損失值**」（loss）：一個代表「模型這次錯得有多離譜」的分數，後面的課會常常看到它。

**1 維：一排數字。**例如一週七天的氣溫 `[25, 27, 26, 24, 28, 30, 29]`。數學上叫做「**向量**」（Vector）。形狀寫成 `(7,)`，表示「一排、7 個」。（括號裡的逗號是 Python 的寫法習慣，表示這是只有一個數字的形狀描述。）

**2 維：一張表格。**例如 3 位學生、每人 4 科成績，就是 3 列 4 欄的表格。數學上叫做「**矩陣**」（Matrix），形狀寫成 `(3, 4)`。在 AI 裡最常見的 2 維張量形狀是 `(B, D)`：
- `B` 是 **Batch Size**（批次大小）：一次餵給模型幾筆資料。模型通常不是一筆一筆學，而是一次拿一小疊（例如 32 筆）一起學，比較有效率，就像老師一次改一疊考卷。
- `D` 是**特徵數**：每筆資料用幾個數字描述。例如描述一間房子用「坪數、屋齡、樓層、離捷運距離」，D 就是 4。

**3 維：一疊表格。**常用在文字和時間序列，形狀是 `(B, T, D)`。多出來的 `T` 是**序列長度**（Sequence Length）：一句話有幾個字、或一段時間有幾個時間點。想像 B 個人各寫一句 T 個字的話，每個字用 D 個數字描述——就是一個三層的資料堆。

**4 維：一疊照片。**彩色照片的標準形狀（PyTorch 這套最流行的深度學習工具的慣例）是 `(B, C, H, W)`：
- `B`：幾張照片
- `C`：**色彩通道**（Channels）。彩色照片由紅、綠、藍三種顏色疊成，所以 C = 3（這就是常聽到的 RGB）
- `H`、`W`：照片的高和寬（幾個像素）

例如 32 張 224×224 的彩色照片，形狀就是 `(32, 3, 224, 224)`，總共有 $32 \times 3 \times 224 \times 224 \approx 480$ 萬個數字。

「維度」的數量，也叫做「**階數**」（Rank），在程式裡常寫成 `ndim`（number of dimensions）。每一個維度，也常被叫做一個「**軸**」（axis）。第一個軸叫第 0 軸、第二個叫第 1 軸——程式世界習慣從 0 開始數，這點要記住。

除了形狀，每個張量還有兩個重要屬性：**資料型別**（dtype，例如是整數還是小數、用多少位元存）和**裝置位置**（device，資料放在一般記憶體還是顯示卡 GPU 上）。這兩個在本課先知道就好。

@section 電腦怎麼存一張表格？「一長排書架」與步幅
我們腦中想像的 `(2, 3)` 張量，是一個 2 列 3 欄的整齊表格：

```
[[10, 20, 30],
 [40, 50, 60]]
```

但電腦的記憶體不是一張方格紙，而是**一長排編了號碼的格子**，像一條很長很長的書架。所以電腦會把表格「攤平」成一條存起來。PyTorch 預設的攤平方式是「**一列接一列**」放（叫做 Row-major，列優先）：

```
書架：[10, 20, 30, 40, 50, 60]
位置：  0   1   2   3   4   5
```

那問題來了：我要找「第 1 列、第 2 欄」的數字（程式寫作 `A[1, 2]`，記得從 0 開始數，所以是第二列第三欄的 60），電腦怎麼知道它在書架上第幾格？

答案是靠一組叫做「**步幅**」（Stride）的數字。這個表格的步幅是 `(3, 1)`，意思是：
- 往下走一列，書架上要**跳過 3 格**（因為一列有 3 個數字）；
- 往右走一欄，書架上只要**跳 1 格**。

所以 `A[1, 2]` 的位置 = $1 \times 3 + 2 \times 1 = 5$，書架上第 5 格正是 60。

**為什麼要知道這個？因為它解釋了兩個常用操作的差別。**

**操作一：改形狀（reshape）。**把 `(2, 3)` 改成 `(3, 2)`：

```
[[10, 20],
 [30, 40],
 [50, 60]]
```

書架上的資料**完全不用搬動**，還是 `[10, 20, 30, 40, 50, 60]`，只要把「怎麼解讀」改一下：形狀改成 `(3, 2)`、步幅改成 `(2, 1)`（往下一列跳 2 格）。這種不搬資料、只換解讀方式的結果，叫做「**視圖**」（View）——就像同一排書，你換一種方式分組來看。因為不用搬，所以幾乎不花時間。

**操作二：轉置（transpose，寫作 `A.T`）。**把列和欄對調：

```
[[10, 40],
 [20, 50],
 [30, 60]]
```

形狀一樣是 `(3, 2)`，但內容完全不同！PyTorch 的做法一樣是不搬資料，只把步幅改成 `(1, 3)`。但這樣一來，「一列」的三個數字在書架上就不是挨在一起的了（10 在第 0 格、40 在第 3 格）。這種狀態叫做「**不連續**」（Non-contiguous）。

這就解釋了一個常見的錯誤訊息：對轉置過的張量直接呼叫 `.view()` 改形狀，程式會報錯——因為 `.view()` 要求資料在書架上是連續排好的。解法是先呼叫 `.contiguous()` 把資料真的重新排一次，或改用 `.reshape()`（它會在需要時自動幫你重排）。

**一句話記住：reshape 是換個方式分組讀同一排書；transpose 是換了閱讀方向，兩個形狀相同的結果，內容可能完全不同。**

@section 三種基本運算之一、二：逐格計算與「壓扁」
張量的運算可以分成三大類。先看前兩類。

**第一類：逐元素運算（Element-wise）——對號入座，一格算一格。**

加法 `A + B`、乘法 `A * B`，都是把**同一個位置**的數字配對起來計算。就像兩張同樣大小的成績單，把同一位學生、同一科的分數相加。不會跨列、跨欄混在一起，所以結果的形狀跟輸入一樣。

（逐元素相乘有個正式名稱叫 Hadamard 積，知道就好。深度學習裡常用的「激活函式」，例如 `relu`——把所有負數變成 0、正數保持不變——也是逐元素運算。）

**第二類：降維歸約（Reduction）——把某個方向「壓扁」。**

求和 `sum`、平均 `mean`、最大值 `max` 都屬於這類。它們會把很多數字合併成較少的數字。

這裡有一個**初學者最常搞混的觀念**：程式裡寫 `dim=k`，意思是「**沿著第 k 軸把它壓扁、讓這個軸消失**」，而不是「保留第 k 軸」。

用成績單來理解。`X` 的形狀是 `(2, 3)`：2 位學生（第 0 軸）、3 個科目（第 1 軸）。

```
         國文 英文 數學
小明  [[ 80,  70,  90],
小華   [ 60,  85,  75]]
```

- `X.sum(dim=0)`：把第 0 軸（學生那個方向）壓扁，也就是**直的加起來**，得到每一科的全班總分 `[140, 155, 165]`，形狀 `(3,)`。學生這個維度消失了。
- `X.sum(dim=1)`：把第 1 軸（科目那個方向）壓扁，也就是**橫的加起來**，得到每位學生的總分 `[240, 220]`，形狀 `(2,)`。科目這個維度消失了。

**keepdim=True：壓扁但留個位置。**

假設你想算「每科分數占該學生總分的比例」，直覺寫法是 `X / X.sum(dim=1)`，也就是 `(2, 3)` 除以 `(2,)`。結果程式會**報錯**！原因要等下面學了「廣播規則」才完全明白，簡單說是：電腦會把 `(2,)` 跟 `(2, 3)` 的**最後一軸**對齊，2 對 3，對不起來。

解法是加上 `keepdim=True`：`X.sum(dim=1, keepdim=True)` 會得到形狀 `(2, 1)` 的結果：

```
[[240],
 [220]]
```

被壓扁的那個軸還在，只是長度變成 1。這樣 `(2, 3)` 除以 `(2, 1)` 就能正確地「每一列除以自己那一列的總分」。小明國文占比 = 80 ÷ 240 ≈ 0.33。

@section 三種基本運算之三：矩陣乘法
**第三類：矩陣乘法（Matrix Multiplication）——加權總分。**

在 Python 和 PyTorch 裡，矩陣乘法用 `@` 符號（或 `torch.matmul`）表示。**請千萬分清楚 `*` 和 `@`**：
- `*` 是逐元素相乘（對號入座）。
- `@` 是矩陣乘法：拿左邊的每一列，跟右邊做「**乘完再加總**」。

用生活例子最好懂。學校算學期成績：國文、英文、數學的權重分別是 0.3、0.3、0.4。

```
成績 A（2 位學生 × 3 科），形狀 (2, 3)：
[[80, 70, 90],
 [60, 85, 75]]

權重 b，形狀 (3,)：[0.3, 0.3, 0.4]
```

`A @ b` 就是算每位學生的加權總分：
- 小明：$80 \times 0.3 + 70 \times 0.3 + 90 \times 0.4 = 24 + 21 + 36 = 81$
- 小華：$60 \times 0.3 + 85 \times 0.3 + 75 \times 0.4 = 18 + 25.5 + 30 = 73.5$

結果是 `[81, 73.5]`，形狀 `(2,)`。注意：**長度 3 的那個軸（科目）在「乘完再加總」的過程中消失了**。這種「一對一相乘再全部加起來」的運算，叫做「**點積**」或「**內積**」（Dot Product），用數學寫成 $y_i = \sum_{j=1}^3 A_{ij} b_j$——$\sum$（念作 sigma）是「全部加起來」的符號，意思是把 j 從 1 到 3 的每一項乘積加總。

**同樣的 A 和 b，換成 `A + b` 或 `A * b` 會怎樣？**這時電腦會啟動「廣播」，把同一組 `[0.3, 0.3, 0.4]` 分別套到每一列上逐格計算，結果形狀仍然是 `(2, 3)`。所以：

- `A + b` → 形狀 `(2, 3)`
- `A @ b` → 形狀 `(2,)`

這正是自我測驗區第 1 題考的觀念。

**更高維度的矩陣乘法。**在 ChatGPT 這類模型（Transformer 架構）裡，常常是兩個 3 維張量相乘，例如 `(B, T, D) @ (B, D, K)`。規則是：前面的批次維度 `B` 對齊保留，只對最後兩個維度做矩陣乘法：`(T, D) @ (D, K)` 得到 `(T, K)`。所以結果是 `(B, T, K)`。記憶口訣：**中間相同的 D 會被「吃掉」，兩邊的留下來。**

為什麼矩陣乘法這麼重要？因為神經網路最核心的計算，本質上就是「輸入 @ 權重」——把每個特徵乘上一個重要程度，再加總起來。第 5 課的線性回歸、第 8 課的神經網路，都建立在這個運算上。

@section 廣播：電腦自動幫你「複製貼上」的規則
當兩個**形狀不同**的張量做逐元素運算時，PyTorch 和 NumPy（Python 最常用的數值計算工具）會嘗試自動把小的那個「延伸」成大的形狀，這叫做「**廣播**」（Broadcasting）。就像廣播系統把同一段話播到每一間教室——同一組數字被套用到每一列上。而且它很聰明，不會真的在記憶體裡複製很多份，只是「假裝」複製。

廣播的規則只有兩步，但要一字不差地記住：

**第一步：靠右對齊，左邊不夠就補 1。**
把兩個形狀**從最右邊開始對齊**。如果其中一個的維度比較少，就在它的**最左邊**補上 1，直到兩個一樣長。

例：`A` 是 `(2, 3)`、`b` 是 `(3,)`。靠右對齊後，b 左邊補 1，變成 `(1, 3)`。

**第二步：每一軸檢查是否相容。**
從右到左，每一對長度只要符合以下其中一個條件就 OK：
1. 兩個長度**相等**；或
2. 其中一個長度是 **1**（長度 1 的那邊會被延伸成另一邊的長度）。

例：`(2, 3)` 和 `(1, 3)`：最右軸 3 = 3 相等 ✓；左軸 2 和 1，有一個是 1 ✓。所以可以廣播，b 被延伸成 `(2, 3)`，結果形狀 `(2, 3)`。

**失敗的例子：**`(2, 3)` 和 `(2,)`。靠右對齊，`(2,)` 補成 `(1, 2)`。最右軸是 3 對 2：不相等、也沒有 1 ✗。程式會立刻報錯：

`RuntimeError: The size of tensor a (3) must match the size of tensor b (2)`

這就是前面 `X / X.sum(dim=1)` 報錯的原因！加了 `keepdim=True` 之後變成 `(2, 3)` 對 `(2, 1)`：最右軸 3 對 1 ✓、左軸 2 對 2 ✓，就成功了。

**練習一題：**`(4, 1)` 和 `(3,)` 可以廣播嗎？結果是什麼形狀？
→ `(3,)` 補成 `(1, 3)`。最右軸 1 對 3 ✓（1 延伸成 3）；左軸 4 對 1 ✓（1 延伸成 4）。可以，結果是 `(4, 3)`。

注意到了嗎？**兩邊都被延伸了。**這個「雙向延伸」就是下一節那個可怕 bug 的源頭。

@section 最可怕的 bug：程式不報錯，模型卻學成廢物
AI 工程師最怕的不是程式當掉。當掉很好，因為你馬上知道哪裡錯了。最可怕的是「**靜默錯誤**」（Silent Bug）：程式順順地跑、沒有任何錯誤訊息、模型的分數看起來也有在進步——但它學出來的東西根本是錯的。就像一台秤每次都多算 2 公斤，你量了一整年體重才發現。

而廣播，正是靜默錯誤的頭號製造者。我們來看最經典的案例。

**情境**：你在訓練一個預測房價的模型，一次餵 32 筆資料（B = 32）。
- 模型輸出的預測值 `y_hat`，形狀是 `(32, 1)`——32 列、每列 1 個數字。（這是因為模型的輸出層習慣保留一個「輸出數量」的軸。）
- 從資料集讀出的真實房價 `y`，形狀是 `(32,)`——一排 32 個數字。

你想算誤差，很自然地寫下 `error = y_hat - y`。照理說應該得到 32 個誤差：第 1 筆預測減第 1 筆答案、第 2 筆減第 2 筆……

**但實際發生了什麼？**套用廣播規則：
- `(32,)` 補成 `(1, 32)`。
- 最右軸：1 對 32 → 1 延伸成 32 ✓
- 左軸：32 對 1 → 1 延伸成 32 ✓
- 結果：`(32, 32)`！

電腦算出了一個 32×32 的表格，裡面是「**每一筆預測，減掉每一筆答案**」的所有組合：第 1 筆預測減第 1 筆答案、第 1 筆預測減第 2 筆答案……一共 1,024 個數字。其中只有對角線上那 32 個是你要的，其他 992 個都是毫無意義的「拿 A 房子的預測去減 B 房子的價格」。

接著你習慣性地算平均 `.mean()` 當作損失值。程式不會報錯，損失值也會隨訓練下降——但模型學到的是「**怎麼讓我的預測接近所有房子的平均價格**」，而不是「預測這間房子的價格」。最後的結果是：模型不管看到什麼房子，都猜差不多的價格。

**怎麼防範？**唯一可靠的方法是養成習慣：
1. 在關鍵計算前**檢查形狀**，例如寫一行 `assert y_hat.shape == y.shape`（assert 的意思是「我斷定這件事成立，不成立就立刻停下來報錯」）——把靜默錯誤變成會報錯的錯誤。
2. **統一形狀**再計算，例如把 `y` 改成 `(32, 1)`：`y.reshape(-1, 1)`（-1 表示「這一軸的長度你自己算」）。

這個 bug 有多常見？常見到 PyTorch 的部分損失函數會在偵測到這種形狀不一致時主動跳出警告。但不是每個地方都有警告，所以最終還是要靠自己的習慣。

@section 跟著練一次：用形狀推理讀懂一行程式
我們把本課所有觀念串起來，練習「只看形狀，就推理出程式在做什麼」。這是 AI 工程師每天在做的事。

**題目**：`scores` 形狀是 `(4, 5)`，代表 4 位學生、5 個科目的分數。我們想算「每位學生每科占自己總分的比例」。

**第一步：要壓扁哪個軸？**「每位學生的總分」要把 5 科加起來，科目是第 1 軸，所以 `dim=1`。

**第二步：壓扁後形狀？**不加 keepdim → `(4,)`；加 keepdim → `(4, 1)`。

**第三步：能不能和 `(4, 5)` 廣播？**
- `(4, 5)` 對 `(4,)`：補成 `(1, 4)`，最右軸 5 對 4 ✗ → 報錯。
- `(4, 5)` 對 `(4, 1)`：最右軸 5 對 1 ✓、左軸 4 對 4 ✓ → 成功，結果 `(4, 5)`。

**答案**：`scores / scores.sum(dim=1, keepdim=True)`。

**再練一題反向的**：如果寫成 `scores / scores.sum(dim=0)` 會怎樣？`dim=0` 是把 4 位學生壓扁，得到每科全班總分，形狀 `(5,)`，補成 `(1, 5)` 後和 `(4, 5)` 完全相容——**不會報錯**！但算出來的是「每位學生的分數占該科全班總分的比例」，跟題目要的完全不同。又是一個靜默錯誤的例子：**程式能跑，不代表算的是你要的東西。**

養成「每一行都在心裡標註形狀」的習慣，你看 AI 程式碼的速度和準確度都會大幅提升。這也是為什麼本課放在所有模型課程的最前面。

@section 本課重點整理
- **張量就是整齊排好的一堆數字**：0 維是一個數、1 維是一排、2 維是表格、3 維是一疊表格（文字常用 `(B, T, D)`）、4 維是一疊照片（`(B, C, H, W)`）。
- **電腦把表格攤成一長排存放**，靠「步幅」找到每個位置。reshape 只是換個方式分組讀；transpose 是換了讀的方向，形狀相同、內容不同。
- **三類運算**：逐元素（對號入座，`*`、`+`）、歸約（`dim=k` 表示把第 k 軸壓扁消失，`keepdim=True` 保留長度 1 的位置）、矩陣乘法（`@`，乘完再加總，中間相同的軸被吃掉）。
- **廣播兩步驟**：靠右對齊、左邊補 1；每軸要嘛相等、要嘛有一個是 1。
- **最危險的是靜默錯誤**：`(B, 1)` 減 `(B,)` 不會報錯，卻會變成 `(B, B)`，讓模型學錯。用 `assert` 檢查形狀、計算前統一形狀。

下一課，我們要用這些張量來回答 AI 最核心的問題：模型猜錯了，要怎麼知道「該往哪個方向修正」？答案就是梯度與自動微分。

@term 張量
整整齊齊排好的一堆數字（Tensor）。0 維是一個數、1 維是一排、2 維是表格、更高維是一疊疊的表格。AI 處理的所有資料都會變成張量。
@term 形狀
張量每個方向各有幾格（Shape），例如 (32, 3, 224, 224)。看懂形狀是讀懂 AI 程式的第一步。
@term 批次
一次餵給模型的一小疊資料（Batch），像老師一次改一疊考卷。批次大小常用 B 表示。
@term 純量
單獨一個數字（Scalar），形狀是 ()。訓練時的損失值通常就是一個純量。
@term 向量
一排數字（Vector），形狀像 (D,)。例如用 4 個數字描述一間房子。
@term 矩陣
一張數字表格（Matrix），有列和欄，形狀像 (B, D)。
@term 步幅
在一長排記憶體中，往某個方向走一格要跳過幾個位置（Stride）。電腦靠它找到表格中每個數字。
@term 視圖
不搬動資料、只換一種解讀方式得到的新張量（View）。像同一排書換個方式分組看。
@term 廣播
形狀不同的張量做計算時，電腦自動把長度為 1 的軸延伸對齊的機制（Broadcasting）。方便，但也是靜默錯誤的元兇。
@term 點積
兩排數字一對一相乘再全部加總（Dot Product），像用權重算加權總分。矩陣乘法就是很多次點積。
@term 矩陣乘法
用 @ 表示的運算：左邊每一列和右邊做點積。(T, D) @ (D, K) 得到 (T, K)，中間的 D 被「吃掉」。
@term 靜默錯誤
程式不報錯、照常執行，結果卻是錯的 bug（Silent Bug）。比會當機的錯誤更可怕。
@term 損失值
代表模型「錯得有多離譜」的一個數字（loss）。訓練的目標就是讓它越來越小。
@term PyTorch
目前最流行的深度學習工具（程式庫）之一，提供張量運算、自動微分與神經網路元件。
