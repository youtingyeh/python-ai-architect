@section 開場：程式一關，資料就不見了
前兩課我們寫出了乾淨的函式和類別。但有兩個大問題還沒解決：

**問題一：資料留不住。**
程式執行時，所有資料都放在電腦的**記憶體**（RAM）裡。記憶體速度很快，但一關掉程式（或電腦當機、斷電），裡面的東西就**全部消失**。辛苦輸入的 100 筆記帳資料，下次打開程式就沒了。

**問題二：每次修改都要手動測一遍。**
每改一次程式，就要自己在終端機打五組數字，看看有沒有改壞。很快就會因為偷懶跳過，把錯誤帶上線。

這一課要學三樣工具：
1. **JSON**：把資料存成檔案，下次再讀回來（也是第 22、26 課呼叫 AI 服務時使用的格式）；
2. **型別標註**：讓人和工具一眼看懂函式要什麼、給什麼；
3. **pytest**：把測試寫成程式，一秒鐘自動跑幾百次。

我們用一個「**記帳程式**」當例子貫穿整課。

@section JSON：資料的通用語言
**JSON**（JavaScript Object Notation）是一種用**純文字**表示資料的格式。它長得很像 Python 的字典和清單：
```
[
  {"kind": "income", "amount": 1000},
  {"kind": "expense", "amount": 350}
]
```

它幾乎是現代軟體世界的**通用語言**：網站前後端溝通、呼叫 AI 的 API、設定檔……到處都是 JSON。Python、JavaScript、Java 各種語言都讀得懂。

**JSON 只認得六種東西：**
- 物件 `{}`（對應 Python 的字典；**鍵一定是文字**）；
- 陣列 `[]`（對應清單）；
- 字串、數字、布林值（`true`/`false`）、空值 `null`（對應 `None`）。

Python 有些東西 JSON **不認得**：類別的方法、`set`（集合）、日期時間、`tuple`（存進去會變成清單）。要存這些，得先轉換成上面六種之一（例如日期轉成 `"2026-11-27"` 這種文字）。

**Python 怎麼讀寫 JSON：**
```
import json
text = json.dumps(data, ensure_ascii=False)   # 資料 → 文字
data = json.loads(text)                       # 文字 → 資料
```
- `dumps` = dump string（倒成字串）；`loads` = load string（從字串載入）；
- `ensure_ascii=False`：讓中文字保持原樣，而不是變成 `中` 這種難讀的編碼。

**一定要指定編碼：UTF-8。**
寫檔案時，一定要寫 `encoding="utf-8"`：
```
with open("records.json", "w", encoding="utf-8") as f:
    f.write(text)
```
**編碼**是「文字怎麼轉成電腦的 0 和 1」的規則（第 13 課提過 UTF-8）。如果不指定，在繁體中文版的 Windows 上，Python 可能會用舊的 cp950（Big5）編碼存檔，換到 Mac 或 Linux 上讀，就會出現亂碼或 `UnicodeDecodeError` 錯誤。

@section JSON 的一個小陷阱：數字鍵變成文字
```
data = {1: "Alice"}
text = json.dumps(data)      # '{"1": "Alice"}'
back = json.loads(text)      # {'1': 'Alice'}
back[1]                      # KeyError！
```
因為 JSON 物件的鍵**只能是文字**，存進去時整數 1 被轉成了文字 `"1"`。讀回來後，用整數 `1` 去查，當然找不到。

**更好的做法：**不要用編號當字典的鍵來存檔，而是把每筆資料寫成有明確欄位的物件：
```
[{"id": 1, "name": "Alice"}]
```
這樣 `id` 的值保持是數字，也更清楚。

@section 檔案壞掉時，千萬別雪上加霜
存檔和讀檔時，有三種意外狀況要想清楚：

**狀況一：檔案不存在。**
第一次執行程式時，`records.json` 還沒建立。這時把資料初始化成空清單 `[]` 很合理。

**狀況二：檔案存在，但內容壞掉了。**
例如上次存檔到一半斷電，或有人手動編輯時少打了一個括號。`json.loads` 會拋出 `JSONDecodeError`。

**最危險的錯誤處理：**
```
try:
    records = json.loads(text)
except json.JSONDecodeError:
    records = []    # 當作沒資料
```
看起來很穩健，程式不會當掉。但下一次存檔時，程式會把**空清單**寫回去，**覆蓋**掉原本那個只是少了一個括號、其實還救得回來的檔案。一年的記帳資料，就這樣永遠消失了。

**正確做法：**
- 明確地告訴使用者「檔案損壞了」，**停止**後續的覆寫；
- 或先把損壞的檔案**備份**一份（例如改名成 `records.json.corrupt`），再處理。

這就是第 45 課「不要吞掉錯誤」的具體例子：吞掉錯誤不只讓問題難以發現，還會**擴大災害**。

**狀況三：寫到一半被中斷。**
直接寫入 `records.json` 時，如果寫到一半當機，檔案就只剩前半段，壞掉了。

**解法：原子寫入（Atomic Write）。**
1. 先把完整內容寫到一個**暫存檔**，例如 `records.json.tmp`；
2. 確認寫完了，再用 `Path.replace()` 把暫存檔**一次換成**正式檔名。

「換名字」這個動作在作業系統中是**原子的**（第 35 課提過：一次完成、不可分割）：要嘛換成功、拿到完整的新檔；要嘛沒換、保留完整的舊檔。不會出現「一半新一半舊」的狀態。

**比喻：**像換招牌。不要在原本的招牌上一筆一筆塗改（萬一塗到一半下雨就毀了），而是在旁邊做好一塊完整的新招牌，再一次掛上去。

@section 錢的問題：不要用小數
在 Python 裡試試：
```
0.1 + 0.2    # 0.30000000000000004
```
這不是 Python 的錯，而是電腦用二進位表示小數時，很多十進位小數**無法精確表示**（就像 1/3 無法用有限位數的十進位小數精確寫出）。這種格式叫做 IEEE 754 浮點數。

算科學數據時，這點誤差沒關係；但**記帳**時，誤差累積幾萬筆後，就會出現「帳對不起來」的問題。

**正確做法：**
- 用**最小貨幣單位的整數**儲存。例如新台幣用「元」的整數；美金用「分」（cents）的整數，$12.34 存成 `1234`；
- 或用 Python 的 `Decimal` 型別，專門做精確的十進位計算。

@section 型別標註：寫給人和工具看的說明
**型別標註**（Type Hints）是在函式上標明參數和回傳值的型別：
```
def total_expenses(records: list[dict]) -> int:
    ...
```
意思是：「`records` 應該是一個裝著字典的清單，這個函式會回傳一個整數。」

**好處：**
- **人**看一眼就知道該傳什麼進去；
- **編輯器**（例如 VS Code）可以自動提示、提早標出錯誤；
- **靜態檢查工具**（例如 mypy、pyright）可以在程式**還沒執行前**，就找出「把文字傳進需要數字的地方」這類錯誤。第 39 課 Agent Harness 中的「型別檢查」指的就是這個。

**重要的觀念：型別標註不會在執行時幫你擋東西！**
如果有人呼叫 `total_expenses([{"kind": "expense", "amount": "30"}])`（金額是文字），Python **照樣會執行**，直到某一行要把文字和數字相加時才當掉。標註只是「說明」，不是「警衛」。

所以要兩者並用：
- **型別標註**：在開發階段幫人和工具抓錯；
- **執行時的檢查**（第 44 課學的驗證）：在程式真正執行時，擋住外部傳來的錯誤資料。

另外提醒：要嚴格確認是整數、又排除布林值，可以寫 `type(amount) is int`，因為 `type(True)` 是 `bool`，不是 `int`。

@section 走一遍：總支出函式
需求：每筆紀錄必須是一個字典，有兩個欄位：
- `kind`：只能是 `"income"`（收入）或 `"expense"`（支出）；
- `amount`：非負整數（不能是布林值、負數、小數或文字）。

函式 `total_expenses(records)` 回傳所有支出的總和。

**情境 A：正常資料。**
`[收入 1000, 支出 350, 支出 150]` → 每筆驗證通過，只加總支出 → 回傳 **500**。

**情境 B：空清單。**
`[]` → 迴圈不執行，回傳 **0**。（這裡「沒有支出」的總額就是 0，和第 44 課「平均」的情況不同：總和為 0 是有意義的。）

**情境 C：一個隱藏的陷阱。**
`[收入 -50, 支出 100]`。第一筆是**收入**，不會被算進支出總額。但它的金額是 -50，是**不合法**的資料！

如果程式這樣寫：
```
for r in records:
    if r.get("kind") == "expense":
        驗證 r
        加總 r
```
只有支出才會被驗證，這筆壞掉的收入就**蒙混過關**了。之後如果有另一個函式計算總收入，就會算出錯誤的結果。

**正確做法：先把每一筆都完整驗證，再依種類分流計算。**

**情境 D：偽裝的布林值。**
`[支出 True]` → `type(True) is not int`，被攔下，拋出 `ValueError`。

@section pytest：讓電腦幫你測試
**pytest** 是 Python 最常用的測試工具。寫法非常簡單：建立一個 `test_` 開頭的檔案，裡面寫 `test_` 開頭的函式，用 `assert`（斷言）寫出「應該要成立的事」：
```
from ledger import total_expenses
import pytest

def test_normal():
    records = [
        {"kind": "income", "amount": 1000},
        {"kind": "expense", "amount": 350},
        {"kind": "expense", "amount": 150},
    ]
    assert total_expenses(records) == 500

def test_empty():
    assert total_expenses([]) == 0

def test_invalid_income_is_rejected():
    with pytest.raises(ValueError):
        total_expenses([{"kind": "income", "amount": -50}])

def test_bool_amount_is_rejected():
    with pytest.raises(ValueError):
        total_expenses([{"kind": "expense", "amount": True}])
```

在終端機輸入 `pytest`，它會自動找出所有測試並執行，告訴你幾個通過、幾個失敗、失敗在哪裡。

`with pytest.raises(ValueError):` 的意思是：「**這段程式應該要拋出 ValueError**，如果沒有拋出，測試就算失敗。」用它來確認程式**真的會拒絕**不合法的資料。

**好的測試要涵蓋三類情況：**
1. **正常情況**：一般的、正確的輸入；
2. **邊界情況**：空清單、0、剛好在上限的值；
3. **錯誤情況**：每一種不合法的輸入，都要確認會被拒絕。

這三類測試，從多到少排列，就像一座金字塔的底座、中段和尖端，每一層都不能少。

**常見的錯誤：只測快樂路徑。**
只寫一個 `assert total_expenses([{"kind": "expense", "amount": 30}]) == 30`，就以為測試完成了。這種測試對空清單、負數、缺欄位、布林值完全沒有保護力。第 42 課說過：AI 寫的測試特別常犯這個錯誤。

**另一個常見錯誤：測試印出的文字。**
測試應該檢查**回傳值**和**例外**，而不是螢幕上印了什麼。這也是第 44 課要求計算函式不要 `print()` 的原因之一。

@section 動動腦：找出問題
**題一**：函式標註了 `-> int` 和 `records: list[dict]`，有人傳入金額為 `"30"`（文字）的資料，Python 會自動擋下嗎？
→ 不會。型別標註只供人和檢查工具參考，執行時不會強制。必須自己寫執行時的檢查。

**題二**：讀取 `records.json` 時發生 `JSONDecodeError`，最安全的處理方式是什麼？
→ 明確回報檔案損壞並停止覆寫，或先備份損壞的檔案，保護還有機會救回的資料。

**題三**：為什麼除了測試正常的支出，還要測試「收入 -5」和「支出 True」？
→ 才能發現「沒被選中的分支沒有驗證」和「布林值被當成 1」這兩種漏洞。

**題四**：`{2: "Bob"}` 存成 JSON 再讀回來，用 `data[2]` 查詢會怎樣？
→ `KeyError`，因為鍵被轉成了文字 `"2"`。

@section 本課重點整理
- **持久化**：記憶體的資料關掉程式就消失，要存成檔案。
- **JSON**：純文字的通用資料格式，只認得六種型別，物件的鍵一定是文字。讀寫時指定 `encoding="utf-8"` 和 `ensure_ascii=False`。
- **檔案損壞**：不要當成空資料再覆寫；要回報錯誤或先備份。
- **原子寫入**：先寫暫存檔，完成後再一次替換正式檔。
- **金額**：不要用浮點小數，用最小單位的整數或 `Decimal`。
- **型別標註**：給人和工具看的說明，執行時不會擋錯誤；仍需執行時檢查。
- **驗證順序**：先驗證每一筆，再分流計算，避免沒被選中的分支漏網。
- **pytest**：用 `assert` 和 `pytest.raises` 寫測試，涵蓋正常、邊界、錯誤三類情況。

@term 記憶體
程式執行時暫存資料的地方（RAM），速度快但關機或結束程式後就會清空。
@term 持久化
把資料存到檔案或資料庫，讓程式結束後資料仍然保留（Persistence）。
@term JSON
用純文字表示物件、陣列、字串、數字、布林與空值的通用資料格式。
@term 序列化
把記憶體中的資料轉換成可儲存或傳輸的文字或位元格式（Serialization）。
@term 編碼
把文字轉換成電腦位元的規則，例如 UTF-8（Encoding）。
@term JSONDecodeError
讀取 JSON 時內容格式錯誤所拋出的例外。
@term 原子寫入
先寫暫存檔再一次替換正式檔，避免檔案只寫一半的做法（Atomic Write）。
@term 浮點數
電腦表示小數的格式，部分十進位小數無法精確表示（Floating Point）。
@term Decimal
Python 中做精確十進位運算的數值型別，適合處理金額。
@term 型別標註
在程式中標明參數與回傳值型別的寫法，供人和檢查工具參考（Type Hints）。
@term 靜態檢查
不執行程式、只分析程式碼就找出錯誤的方法，例如 mypy。
@term pytest
Python 最常用的自動化測試工具。
@term 斷言
測試中用 assert 寫出「應該成立的條件」，不成立則測試失敗（Assertion）。
@term 邊界情況
空資料、0、上下限等容易出錯的特殊輸入（Edge Case）。
